整体认知

问题。长期记忆系统是 agent 在真实企业场景落地的关键部件，但现有记忆 / RAG 评测多为短时、单轮、合成查询（本仓库 #16 PRISM、#37 IFCMemoryBench、#42 Active RAG 均偏单模型 / 单任务）。这类评测无法回答一个核心问题：记忆系统能否在长时间跨度下，正确处理那些"当时不完整、后来被修正、且从未被显式声明"的信息？

先前局限。短时测试把记忆当成"检索准确率"问题，忽略了真实企业记忆的三个结构性特征：证据是碎片化进入的，决策会被事后修正，而许多偏好是未言明的（参与者从未说出来，却期望 agent 记住）。短时测试下这些特征要么不出现，要么被平均掉。

核心思想。把"时间"当作一个独立的压力维度。具体做法：构造一个模拟一整年企业运行的记忆系统评估基准，让参与者的记忆涉及碎片化证据、事后修正的决策、未言明的偏好等复杂情况，评估 agent 在长程跨度下能否正确处理这些信息。隐含论点是：记忆系统的可靠性不能靠短时测试来推断。

主要贡献。(1) 提出"整年企业运行"的时间压力测试范式；(2) 把碎片化证据 / 事后修正 / 未言明偏好三类长程记忆难题显式建模进基准；(3) 从方法论上主张"时间维度压力测试"应成为记忆系统评估的一等公民，呼应同 keynote 的 MPCEval（长程多方协作）与 keynote 总体立场（时间敏感的现实）。

主要证据（keynote 描述层面的论断，无公开分数）。keynote 未给出 EverMemBench 的具体准确率或排行榜，强调的是方法论立场：记忆可靠性必须经受时间维度的压力测试。需注意：这是基准设计主张，缺可复现的量化结果（见证据账本）。

关键设计选择（框架亮点）。

  • 时间作为独立维度：不把"长程"当成任务更难，而是当成需要专门压力测试的轴。
  • 三类长程难题显式建模：碎片化证据、事后修正、未言明偏好，覆盖了短时测试天然缺失的记忆失效模式。
  • 企业运行的生态效度：以"一整年企业运行"为场景骨架，提升与现实部署的贴近度。

批判评价

维度内容
优点
  • 填补长程记忆评测空白：本仓库记忆类论文（#16/#37/#42）均偏短时 / 单模型，EverMemBench 把"时间"拉成主轴的思路稀缺且有价值。
  • 失效模式建模精准：碎片化、事后修正、未言明偏好正是短时测试会掩盖的三类真实记忆难题。
  • 方法论可迁移："时间压力测试"可推广到任何带状态 / 长程的 agent 系统（如本仓库 #28 ACID-Bench 的事务状态、#46 经济系统生命周期）。
缺点
  • 缺量化证据：keynote 未给任何分数或排名，无法判断该基准区分模型的能力（构念效度存疑，可对照本仓库 #23）。
  • oracle 定义风险："未言明偏好""事后修正"的正确答案如何判定，若依赖人工 / LLM judge，会引入本仓库 #30 的 judge 噪声与 #33 的 rubric 措辞敏感。
  • 成本与可复现："整年企业运行"模拟成本极高，可能限制可参与的模型数量与重复次数（对照本仓库 #45 最小任务预算问题）。
隐含假设
  • "整年"长度足以暴露长程失效——但缺乏"多久才够"的论证，可能冗余也可能仍不足。
  • 企业运行轨迹可被无偏地模拟，且模拟分布近似真实部署分布。
  • 三类难题相互独立可归因——实际中碎片化与事后修正常耦合。
复现风险
  • 无本地原文，无法复现；依赖正式论文发布轨迹生成器与 oracle。
  • 若 oracle 含 LLM judge，需先做 judge 选择分析（#30）。
缺失对照
  • 未与本仓库短时记忆基准（#37 IFCMemoryBench）做同模型对照，无法量化"加时间轴"带来的增益。
  • 未讨论与 RAG 触发决策校准（#42）的关系——长程记忆与 Active RAG 触发是互补问题。

研究用途

可复用的设计。

  • 时间维度压力测试范式：对任何带状态 agent，把"时间跨度"作为独立评估轴，构造长程回放——可迁移到本仓库 #28/#46 的状态 / 生命周期评估。
  • 三类长程记忆失效建模：碎片化证据、事后修正、未言明偏好，可直接作为记忆系统评测的失败模式清单。
  • 与 MPCEval 组合：时间轴（EverMemBench）× 多方协作（MPCEval）可拼出"长程多方协作"评估骨架。

应规避的设计。

  • 不要用短时检索准确率代表记忆系统可靠性。
  • 不要在 oracle 定义不清时用主观评分判定"未言明偏好"类任务。

后续 / 相关论文。

  • 同 keynote 的 MPCEval（长程多方对话评估）。
  • 本仓库 #16 PRISM、#37 IFCMemoryBench、#42 When Should Active RAG Retrieve（记忆 / RAG 短时评测）。
  • 记忆 / 长期上下文相关：MemoryBank、Generative Agents、RAG 生命周期评估文献。

可能的研究方向。

  • 给出"时间跨度—失效暴露"曲线，确定最小充分时间预算（呼应 #45）。
  • 用确定性 oracle（状态快照比对）替代 LLM judge 判"事后修正"正确性。
  • 把 EverMemBench 与 #46 的 discipline stability 结合，监控长程记忆导致的分布漂移。
