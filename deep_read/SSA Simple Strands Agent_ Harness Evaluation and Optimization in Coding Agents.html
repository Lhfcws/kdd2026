标题：Simple Strands Agent (SSA): Harness Evaluation and Optimization in Coding Agents（Industry Talk 题名；轻量级开源单 agent harness）

作者 / 机构：Jun (Luke) Huan · AWS AI Labs

Venue / 年份：KDD 2026 Workshop「Evaluation and Trustworthiness of Agentic AI」Industry Talk；2026

领域 / 任务：编码 Agent / Coding-Agent 的 harness（脚手架）设计与优化；聚焦"意图-执行鸿沟"

一句话工作：提出轻量、完全开源的单 agent harness SSA，核心是通过缩小"模型推理意图"与"工具执行"之间的意图-执行鸿沟来提升性能，而非依赖任务特定调优；可视为工业界对"harness 本身是关键变量"的印证。

阅读决策：精读（重建） 理由：作为 keynote 从工业界角度印证本仓库 #36「Scaffold Effect」的"harness 是关键混淆变量"论点，价值在"把 harness 当作独立优化对象"，适合拆其意图-执行鸿沟框架与对 #36 的呼应。

整体认知

问题。编码 agent 里，模型的"推理意图"（想做什么）和它实际"通过工具执行出来的结果"之间存在一道意图-执行鸿沟（intent-execution gap）。同样的模型，套上不同的 harness（脚手架 / 编排方式），表现可能天差地别——这正是本仓库 #36「Scaffold Effect」量化出的 40× token 差异与失败指纹复现现象。问题在于：多数团队把 harness 当成附属品，而不是可以独立优化、需要显式评估的变量。

先前局限。编码 agent 的改进常聚焦"换更强的模型"或"做任务特定调优"，却忽略了 harness 这一中间层。当 harness 选择本身是混淆变量（#36），那么"模型 A 比模型 B 好"的结论可能只是"harness A 比 harness B 更适配"，而非模型能力差异。

核心思想。与其为每个任务做特定调优，不如缩小意图-执行鸿沟来系统性提升性能。具体载体是 SSA——一个轻量级、完全开源的单 agent harness，把 harness 本身当成优化对象：让模型的推理意图更可靠地落到工具执行上。

主要贡献。(1) 提出 SSA 这一轻量、开源的单 agent harness 作为可复用的基线 / 研究载体；(2) 把"意图-执行鸿沟"显式定义为编码 agent 的核心失效来源与设计目标；(3) 从工业界角度印证 #36 的论点——AWS 选择优化 harness 而非只换模型，说明 harness 已被当作编码 agent 技术栈中的独立变量。

主要证据（keynote 描述层面的论断，无独立实验数字）。keynote 未给出 SSA 的具体 benchmark 分数或与 #36 的对照实验，强调的是方法论立场：harness 应被作为独立优化对象。其与 #36 的呼应属方向性印证，非新增量化证据（见证据账本）。

关键设计选择（框架亮点）。

  • harness 成为一等公民：显式把 harness 当成可优化、需评估的变量，而非模型能力的附属——直接落地 #36 的方法论主张。
  • 轻量 + 开源：单 agent、轻量、开源，降低复现与研究门槛，便于社区在统一基线上做 harness 对比（呼应 #36 呼吁"评估报告标注 harness 配置"）。
  • 以鸿沟为靶点：不追求任务特定调优，而是通过缩小意图-执行鸿沟获得跨任务增益，可能比 per-task tuning 更通用。
keynote 核心论点（还原）：编码 agent 中模型推理与工具执行之间存在"意图-执行鸿沟"；应通过缩小该鸿沟（而非任务特定调优）来提升性能；AWS 把 harness 本身作为优化对象，说明 harness 已是编码 agent 技术栈中的独立变量。

批判评价

维度内容
优点
  • 把 #36 落到工业基线：开源轻量 harness 让"harness 是关键变量"从学术主张变为社区可复用的研究载体，直接服务 #36 呼吁的"评估报告标注 harness 配置"。
  • 以鸿沟为靶点有通用性潜力：若缩鸿沟真能跨任务增益，则比 per-task tuning 更经济（呼应本仓库 #36 token 成本议题）。
  • 开源降低复现门槛：便于他人在统一基线上做 harness 对比，对抗 #36 揭示的不可比问题。
缺点
  • 缺量化证据：keynote 未给 SSA 的 benchmark 分数，也无法判断是否真优于现有 harness（如本仓库 #8 MacCode Lab、#15 Protocol Cards 的生态）。
  • "优于 per-task tuning"未证：主张跨任务通用，但缺乏对照，可能只是不同权衡。
  • 与 #36 的呼应是解读：观察笔记将其读作对 #36 的印证，但 SSA 作者未必以 #36 为对照，量化关联待补。
隐含假设
  • 意图-执行鸿沟是编码 agent 的主要瓶颈，而非模型能力本身——对某些任务可能模型能力才是主因。
  • 轻量单 agent harness 足以覆盖复杂编码任务——可能不及多 agent / 重编排方案的上限。
  • harness 与模型可解耦优化——但 #36 显示失败指纹跨模型复现，说明二者耦合。
复现风险
  • 无本地原文 / 公开代码（观察笔记未给仓库），暂不可复现；依赖正式演讲 / 开源仓库发布。
  • 若开源，需以 #36 式"harness–model pair"为单位报告，否则结论不可比。
缺失对照
  • 未与本仓库 #8（MacCode Lab 可复现 harness）、#15（Protocol Cards 可复现协议）做基线对比。
  • 未做 harness × 模型的双因子消融，无法验证"剥离混淆"的声称。

研究用途

可复用的设计。

  • harness 作为独立变量：任何编码 agent 评估都应把 harness 配置当作一等维度报告（本仓库 #36 的硬要求），SSA 提供了现成开源基线。
  • 意图-执行鸿沟作为诊断靶点：把"模型想做"与"工具做出来"的对齐度作为 agent 失败的诊断入口，可迁移到本仓库 #26（确定性 gate 拦截策略违规）的"意图未被忠实执行"场景。
  • 轻量开源基线策略：用统一开源 harness 做社区对比，对抗评估不可比。

应规避的设计。

  • 不要把"模型 A 优于模型 B"的结论建立在未控制 harness 的前提下（#36 的陷阱）。
  • 不要默认 per-task tuning 是唯一增益路径——缩鸿沟可能更通用，需对照。

后续 / 相关论文。

  • 本仓库 #36 The Scaffold Effect（harness 为隐藏混淆变量）、#8 MacCode Lab（可复现 harness）、#15 Beyond Leaderboards（Protocol Cards）。
  • 编码 agent harness / 编排相关：Agentless、SWE-agent、OpenHands 等开源框架。

可能的研究方向。

  • 用 #36 的 harness–model pair 协议，对 SSA 做跨模型量化对照，验证"剥离混淆"声称。
  • 把"意图-执行鸿沟"指标化为可观测度量（如意图-执行一致性分数），并接 #26 的确定性 gate。
  • 在 SSA 基线上验证轻量 harness 是否在 token 成本（#36）与任务成功率间取得更优权衡。
