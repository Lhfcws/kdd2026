Venue / 年份：Workshop 基准论文（文中自述 “A workshop benchmark paper”）；文件夹标注 kdd2026，推断为 KDD 2026 关联 workshop（inferred，未在正文明确给出会议名）。2026。

领域 / 任务：Agent 评测基准 / 方法论 + 实证校准；面向会修改持久状态的工具型 agent 的事务可靠性（atomicity / consistency / isolation / durability 视角）

一句话论文：任务是否“成功”会高估有状态工具 agent 的可靠性；ACID-Bench 用「确定性故障注入 + 无 LLM judge 的基于状态评估 + 有效性记账协议」把故障暴露、事务完整性、安全交接、无效证据分开度量。

整体认知

问题。会改持久状态的工具型 agent（取消订单、改地址、订票）即便对话“看起来成功”，也可能留下重复写入、过期读、部分提交、验证不足等状态损坏。现有多数 agent 基准（Tau-Bench、WebArena、AgentBench 等）度量的是“用户目标是否达成”，对事务可靠性而言这只是必要非充分条件：工作流可以到达奖励态，却留下未对账的部分提交或基于过期证据的状态更新。

先前局限。作者指出许多 agent 基准只报聚合任务成功率，很少把“任务完成”与“状态完整性”、“故障暴露”与“干净恢复”、“有效证据”与“无效证据”分开。结果是一个对话层面的成功可能掩盖底层状态损坏，且非匹配/污染样本容易被悄悄并表成“分数”。

核心思想。把这类失败当作一个测量问题而非模型排名问题。给定工具层暴露一个确定性事务故障，看 agent 是否：（1）暴露了该故障、（2）完成任务、（3）保住状态完整性、（4）在需要时收集并验证了证据、（5）避免把污染静默折算成干净分数。借用 ACID 词汇作可靠性透镜，但明确不是数据库 ACID 合规测试，评估对象是“agent 在可变工具上的行为”。

主要贡献（4 条测量贡献）。(1) 52 个确定性故障注入场景（零售+航空，钉在 Tau-Bench 任务上）；(2) 一个记录状态 delta 与场景契约、不使用 LLM judge 的 trace schema + evaluator；(3) 一套有效性记账协议，把“晋升终态记录 / 低层尝试与重试 / 表有效性 / 交互结果 / 完整性标签 / 质量告警”分离；(4) 校准与报告控制：带赋值标签的合成契约摘要 fixture、配对的 20 场景 overlay/无overlay 消融、以及放在行为计数之后的可选二级诊断。

主要证据（务必小心的读数）。5 个模型条件档 × 3 次运行 = 780 条晋升终态记录（底层 800 次尝试）。核心计数：SCP（Strict Clean Pass）= 234/780；525 条带完整性违规标签；配对消融在固定单模型上得到澄清 overlay 27/60 vs 基础 prompt 2/60。作者反复强调：这些只构成“确定性评估与记账框架的交叉条件/内部一致性证据”，不构成构念效度，也不构成决定性的模型或厂商排名。

关键设计选择（方法论亮点）。

  • 确定性故障注入而非采样。故障是“配置”的；若配置故障未触发，该记录被标为“无效故障暴露 / 污染”，不折算成干净的模型成功。这是把污染显式化的核心。
  • 因果可达性准入规则。每个故障族设计为“从用户目标自然可达”；若任务无需经过该注入点即可完成，则场景太弱、应予收窄或排除。该规则把基准维持在“评审可审计的事务失败”而非“任意陷阱提示”。
  • 三量分离。ACID 局部成功、事务完整性、表有效性是常被混为一谈的三个量，被显式拆开；交互结果（安全交接等）也不定义 SCP。
  • Manifest 审查。把历史 ACID 提交号、Tau 溯源、场景库存、提示条件、评估版本写入 manifest，使非匹配行被当作“不同条件”而非静默并入同表——防御常见的可复现性失败。
  • 合成校准 fixture。带赋值标签的契约摘要（非由 agent 执行产生），仅检验聚合与报告分离是否保留，不声称构念效度或策略性能。
论文原话（核心 thesis）：“Task success can overestimate state-changing agent reliability unless fault exposure, transactional integrity, safe handoff, and invalid evidence are measured and reported separately.”

批判评价

维度内容
优点
  • 有效性记账纪律值得复用：把“故障暴露 / 安全交接 / 无效或非暴露”分开报告，而非静默并入分母，是负责任的评测方法论，可迁移到任何 agent 可靠性基准。
  • 负责任的保守声明：明确“非部署安全认证、非 DB ACID 合规测试、非决定性模型排名”，并设独立“Falsifiability”小节列出可证伪条件。
  • 确定性、无 LLM judge：打分可复现、可审计（原则上），规避 LLM 评审者噪声与偏差。
  • 因果准入规则：要求故障对用户目标“因果必要”，避免任意陷阱提示，提升评审可审计性。
缺点
  • 证据基础不公开：原始 trace、行级证据、本地研究材料均未发布；历史 ACID 提交号在隐私改写后已不可从当前 Git 溯源。外部核实不可能，且为单作者本地验证。
  • 消融仅单模型 + overlay 自指：27/60 vs 2/60 这最抢眼的结果建立在单模型（DeepSeek V4 Flash thinking-max）上，且 overlay 本身即指示“重试前复查/写后验证”——几乎等于把被评估行为写进提示，混淆了“提示工程杠杆”与“模型固有恢复能力”。
  • 构念效度存疑：ACID 是比喻性透镜而非字面 DB ACID；18 行跟踪审计中 7 个边缘标签显示“触发匹配比语义任务路径更严”，可能把语义合法路径误判为无效。
  • 计数脆弱：Wilson 区间重叠、每档仅 3 次复跑且不估计 run 间方差；234/780 为微平均，小差异不可靠。
  • 领域窄：仅零售与航空；无支付、医疗、工业控制或长程企业流程。
隐含假设
  • 确定性脚本用户策略 + 澄清 overlay 能代表“真实”运行条件（作者承认它们也塑造行为）。
  • Tau-Bench 零售/航空任务足以代表一般性事务可靠性。
  • 完整性违规标签在“安全交接 / 无效-非暴露”结果上出现仍有意义——可能放大“完整性问题”叙事。
  • 模型名（DeepSeek V4 Flash / DeepSeek Pro / MiniMax M2.7 / Kimi K2.6）为非标准/疑似匿名化名，叠加不公开 trace 使第三方验证几乎不可行。
复现风险
  • 实现与 52 个已校验场景契约“本地准备、拟 MIT 许可”，但无已验证公开仓库或 camera-ready 附录。
  • 复现精确总数需“在指定条件下重新运行”或未来归档证据发布；历史 ACID 提交号不可从当前 Git 恢复运行期源码快照。
  • 晋升要求隔离目录、运行与评估同模型配置、提示条件元数据、场景库存检查、manifest 审查——任一缺失都会破坏可复现性。
缺失对照
  • 无“无故障”基线对照以隔离故障注入本身的效应。
  • 消融仅 1 个模型，无跨模型配对对照。
  • 无 LLM-judge 交叉校验，无法判断状态评估器是否漏判语义合法但形式违约的恢复。
  • 无支付/医疗等关键域，结论外推受限。

研究用途

可复用的设计。

  • 有效性记账分类法：晋升终态记录 vs 低层尝试/重试 vs 表有效性 vs 交互结果 vs 完整性标签 vs 质量告警——任何 agent 可靠性基准都应照搬这一维度分离。
  • Manifest 审查护栏：用历史提交号/溯源/场景库存/提示条件/评估版本防止非匹配样本污染并表。
  • 因果准入规则：“故障必须对主张必要”的场景审查标准，可迁移。
  • 确定性、基于状态的评估（无 LLM judge）：在可形式化规格的场景中优先采用，提升可审计性。
  • 合成校准 fixture：用赋值标签的假数据专门检验聚合/报告是否保住分离，是低成本的 pipeline 自检。

应规避的设计。

  • 不要把 SCP / 聚合分当成“自主恢复”或“自动化就绪”度量来宣传。
  • 不要将“非暴露/无效”记录静默并入干净分母或当成模型失败。
  • 不要仅凭微平均小计数做模型/厂商排名。
  • 不要把 ACID 比喻当字面数据库语义使用。
