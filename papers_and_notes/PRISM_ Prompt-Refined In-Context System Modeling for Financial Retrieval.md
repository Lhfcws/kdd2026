# PRISM: Prompt-Refined In-Context System Modeling for Financial Retrieval

## 背景与 Idea
金融信息检索（financial information retrieval）是 LLM 落地最快的工业场景之一：从冗长的 SEC 公告、年报、研报中抽取与查询相关的文档或段落，直接支撑投研、合规与决策。传统强监督检索系统依赖大量标注与端到端微调，但在金融领域面临三重困难。其一，文档密集且高度领域专有，检索需覆盖从整份申报文件到单一段落的多粒度（multi-granularity），例如 FinAgentBench 同时要求对五种备案类型（10-K、10-Q、8-K、DEF 14A、Earnings Transcripts）做文档排序，以及对文档内文本块做 chunk 排序。其二，标签稀缺且不均衡：FiQA-2018 仅 2.96% 语料被标为相关、标注稀疏度高达 99.99%，多数查询少于三个相关文档，平均查询 11 词、文档 133 词，这更考验语义理解、不利于 BM25 之类关键词模型。其三，很多实际部署根本没有任务级训练信号，而现有无监督方法又受 LLM token 上限约束，难以处理长而密的金融文本。

近年来基于 LLM 的排序（LLMs as rankers）被归为 pointwise（逐点）、pairwise（成对）、listwise（列表）三类，listwise 方法如 RankGPT 因效果与效率平衡常被采用，但受输入长度与文档顺序敏感所限；TourRank 用多阶段分组与锦标赛策略缓解。但这类方法仍依赖模型本身能力与提示设计。论文作者（AI Lens，马来西亚团队，发表于 KDD 2026 Agentic AI Evaluation Workshop）因此探索一条 training-free（免训练）的低成本路径：不更新任何模型参数，而是用提示精炼（prompt engineering）、上下文学习（in-context learning，简称 ICL，指在提示中放入若干输入—输出示例，让模型在不做梯度更新的情况下适配新任务，学界认为它近似一种隐式贝叶斯推断，模型从中推断能解释示例的潜在概念）、以及轻量多 agent 协作，对金融检索做"系统级建模"。所谓系统级建模，是把领域先验、推理脚手架与多角色分工固化进提示与上下文设计，使方法即插即用、易部署、易复用，从而规避微调所需的基础设施与标注管线成本。其核心主张是：在金融这类高门槛、低标注场景，低成本提示与上下文策略可以逼近强模型表现，且可作为可复现的准确度—效率基线。

## 核心方法
PRISM（Prompt-Refined In-Context System Modeling）把上述思路拆成三个可独立开关的组件，并用系统性消融研究回答"每个组件何时真正有用"，而不是简单堆叠复杂度。论文的贡献也据此列为三点：提出 training-free 三件套框架、做系统性消融识别各组件生效条件、提供延迟/token/成本的可行性分析。

第一个组件是提示工程，它在 PRISM 中是一个统管排序任务的系统模块：把来自探索性数据分析（EDA）的领域先验——例如各备案类型的词频分布与关键词模式——编码进结构化指令，并在长上下文约束下引导模型推理。作者借鉴 ReAct（推理与行动交错循环，减少幻觉）、CoT（思维链，引导模型走中间自然语言推理步骤）、ToT（思维树，并行探索并评估多条推理路径）的脚手架，设计了四个递进的提示变体 P1–P4。文档排序上从"领域启发式"逐步演进到"组合推理框架"；chunk 排序上从纯 ReAct 演进到"集成多策略"。具体而言：P1 用领域关键词提示与统计线索（chunk 排序用 ReAct 式框架让模型逐步思考后输出排序索引）；P2 增强统计关键词关联并引入多专家模拟（三个分析师协作推理、剪枝错误路径）；P3 对两类任务统一采用 CoT+ReAct+ToT 多策略框架、强调显式逐步推理；P4 在前序基础上精简指令、统一术语，同时保留组合推理。消融结论很明确：结构性推理 refinements 始终优于"堆内容"的增强，P4 在文档与 chunk 两个排序任务上整体最佳，说明"推理清晰"胜过"信息密集"。

第二个组件是 ICL 样本检索，本质是一条简化的 RAG 流水线。由于 EDA 显示不同文档类型与 chunk 的词法分布、信息密度不均（相关 chunk 通常比无关 chunk 信息更密、IQR 更宽、呈长尾分布；10-K/8-K 分别更频繁出现在排序头部与尾部），作者先用训练集离线构建示例库（exemplar store）：把每个查询—文档/片段对用 OpenAI text-embedding-3 嵌入，存入 FAISS 向量库。推理时，新查询用同一编码器取 top-k 语义最相似的示例，作为 few-shot 示范前置到系统提示，使提示随查询自适应；示例库与待排候选库分离，确保示例仅作推理脚手架、不污染候选。关键经验有两点：其一，示例与查询语义越接近，提供的推理模式越有效，更接近的示例让模型更早识别相关文档、推理更一致、在长上下文中更少幻觉；其二，ICL 增益高度依赖模型能力——较小或能力较弱的模型缺乏固有推理能力，靠精选示例可显著提升（论文报告 gpt-oss-120b 在 ICL-5 下取得最强开源 NDCG@10 0.5833，逼近 GPT-5-mini），而 GPT-5 级别模型本身已能从指令泛化，ICL 增益边际很小。

第三个组件是多 agent 系统（MAS，multi-agent system，指多个分工明确的 agent 通过协调达成集体智能，常用来缓解单 agent 的认知负荷与幻觉），用以把排序任务分解为专门角色。作者为 chunk 排序设计了 A1–A4 四个由繁到简的架构：A1 是四个并行 agent（CEO、金融分析师、运营经理、风险分析师）独立打分后取平均达成共识；A2 是三阶段流水线（去噪 Noise Remover→候选筛选 Candidate Selector→打分集成，含相关性打分、上下文推理、证据抽取、多样性四个 agent），但更深结构易过度过滤、级联出错；A3 是两阶段（快速过滤 Quick Filter→三个打分 agent），平衡深度与稳定；A4 是最简双 agent（金融分析师+风险分析师），减少交互与误差传播。论文对 MAS 的核心贡献是经验刻画：多 agent 仅在较大模型与文档级任务上才显示潜力，在较小模型和细粒度 chunk 排序上协调开销反而成为瓶颈；更朴素的非 agentic 配置常常优于复杂多 agent 流水线，尤其对细粒度 chunk 排序——这与 agentic IR 的常见直觉相反，是论文给从业者的重要反向指导。

支撑评测的三个数据集特征鲜明：FinAgentBench 基于 2023–2024 年 EDGAR 的 SEC 文件，含 4,986 条文档级与 18,855 条 chunk 级训练样本、每任务 200 条验证；FiQA-2018 来自 BEIR 的金融观点问答，57,638 文档、648 查询、1,706 条相关性判断，极端稀疏使其更考验语义理解；FinanceBench 是需数值推理的文档问答（150 文档、四类、32 家公司），作者在 oracle 条件下（已给相关段落）隔离推理成分。实验覆盖 GPT-4o-mini、GPT-4.1、GPT-5-mini、GPT-5 与多个开源模型（DeepSeek-V4-Flash、gpt-oss-120b、grok-4-20-reasoning、Llama-4-Maverick-17B-128E-Instruct-FP8），ICL 嵌入用 text-embedding-3-small/large，training-free 特性使其可直换其他供应商与部署设置，论文另在附录给出跨 BEIR 基线与完整可行性分析。

选择 training-free 还有一层现实考量：金融场景常受监管与数据隐私约束，机构往往不能把自有标注数据外发做微调，也难以把内部语料嵌入闭源模型做端到端训练；同时金融检索需求随市场事件快速演化，微调的迭代周期（重新标注、重训、重评估）远慢于改提示。PRISM 因此把"可部署性"本身当成一等目标：换模型只需替换 API 端点与嵌入模型，提示模板与示例库可版本化管理，配合论文提供的延迟/token/成本基线即可做部署决策。这也是它能在 FinAgentBench 这个含商业使用限制的竞赛中开源代码与模板的前提——方法不依赖任何私有训练信号。

## Performance 概括
在 FinAgentBench 私有榜上 PRISM 排名第三，最佳 NDCG@5 为 0.71818（Run 19）。它是唯一进入 top-3 的 training-free 方法；前两名均依赖微调（memex、Yuzhen Hu）。开源模型中 gpt-oss-120b 在 ICL-5 下取得最强 NDCG@10 0.5833，逼近 GPT-5-mini；各开源模型整体落在 NDCG@10 0.552–0.583 区间，稳定超过 BM25+CE 基线，且跨 MoE、稠密、推理专用等多样架构表现均匀，说明提示驱动方法对底层模型鲁棒。论文另给出延迟、token 用量与成本的可行性分析，并开源提示模板与代码。数字表明 PRISM 以显著更低的成本达到可比效果。

## 论文价值与不足
价值在于用受控消融证明 training-free 三件套中"提示工程收益最稳、ICL 选择性增强复杂查询、多 agent 仅在大模型上才划算"，并反向指出"简单非 agentic 配置常优于复杂 MAS（尤其 chunk 级）"，为资源受限的金融检索团队提供了清晰的成本—效果路线图，且方法可跨模型（含开源）部署、对底层架构鲁棒。不足主要有四：其一，仅在 FinAgentBench 单一金融榜单与 SEC 文件分布上验证，跨领域、跨检索分布（如一般网页、多语言）的泛化性未充分检验，结论外推需谨慎；其二，MAS 的负向结论来自特定架构与任务，不等于"多 agent 永远无用"，论文自身也指出强模型+仔细架构设计下 MAS 仍有潜力，不能一概否定；其三，论文对商业使用有显式许可限制（需书面授权），工业复用需注意版权；其四，ICL 对强模型增益边际、对弱模型增益大这一发现，意味着落地时要按模型档位决定是否启用示例检索，而非默认开启。此外，PRISM 的 ICL 示例库依赖自有训练集，分布漂移时需要重建。

## 工业界落地可行性评估
落地性强：金融检索、研报检索、合规文档抽取等场景可直接采用 PRISM，无需训练基础设施与标注管线，性价比高。对希望快速上线、控制成本的团队尤其合适——优先启用 P4 提示工程，仅在较弱模型或复杂查询上叠加 ICL 示例检索，并用 A4 级轻量 MAS 而非深流水线。建议在灰度期用论文提供的延迟/成本基线做预算评估，并保留"chunk 级排序上简单配置常优于复杂 MAS"的教训，避免过度工程化。需要注意的落地障碍有三：一是示例库需基于自有训练集构建并随数据分布更新，存在维护成本；二是商业部署须先确认许可授权范围；三是金融长文档的上下文打包（token 预算、截断策略）需按真实查询分布调优，否则可能影响强模型下本就边际的 ICL 增益。总体而言，它是一套低门槛、高杠杆的检索增强方案。值得注意的是，本文是 KDD 2026 Agentic AI Evaluation Workshop 的 workshop 论文（42 页），深度有限：它对 MAS 的负面结论来自特定 A1–A4 架构与 chunk 排序任务，而论文在文档级任务、较大模型上仍观察到 MAS 的潜力，因此"是否用多 agent"应按任务粒度与模型档位决策，而非一刀切。此外，PRISM 在 FiQA-2018 与 FinanceBench 上的结果进一步支撑了 training-free 路线的竞争力，但这两个数据集分别侧重段落重排与数值推理，与 FinAgentBench 的检索排序分布不同，跨数据集的一致性仍需读者自行验证。对工程团队而言，最稳妥的落地路径是先以 P4 单 agent 跑通基线，再按 query 难度与模型能力选择性叠加 ICL 与轻量 MAS，并用论文的消融结论作为是否加码复杂度的依据。具体到金融场景，由于 10-K/8-K 等不同备案类型有各自词法签名、单一检索策略会系统性偏科，PRISM 的 type-specific 提示（按文档类型注入关键词与统计线索）值得直接复用；而 chunk 级排序因相关块稀疏、信息密度长尾分布明显，更应优先采用 P4 的推理脚手架而非堆多 agent。配合论文开源的提示模板，团队可在数天内完成首版接入并据成本基线决定是否扩大 ICL 示例库规模。
