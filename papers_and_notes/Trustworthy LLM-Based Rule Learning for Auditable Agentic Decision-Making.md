# Trustworthy LLM-Based Rule Learning for Auditable Agentic Decision-Making

## 背景与 Idea
在高风险运营场景部署 LLM 驱动的 agentic 系统，需要同时满足可信、可解释、一致与可适应。现有的专家人工审计、监督分类器、硬编码规则系统都难以在同一框架内兼顾这些目标：人工审计可靠但不可扩展，分类器需大量标注且遇分布漂移要重训，硬编码规则可解释却僵化、无法泛化到未见样本。本文提出一个 LLM 规则学习框架，把业务规则从有限标注数据与文档中学成可被人类审计、可追溯的形式，而非黑箱决策，并以工业"记录对账"（库存缺口与盈余匹配）为用例验证多维可信度。

## 核心方法
框架含三大模块。① 错误驱动的规则归纳（Algorithm 1）：以少量人工标注数据为输入，每轮用 Chain-of-Thought（CoT）对当前错误集 𝐸 做假设并生成一批候选规则，经演绎模块预测后仅保留误分类样本进入下一轮（类似 boosting），直到错误集清空或达上限 𝐾；随后用贪心集合覆盖式剪枝（Algorithm 2）按"覆盖率"（纠正的误标样本占比）挑选最小高效用规则集，去除冗余。② 规则演绎：检索适用规则、给出预测及"触发了哪些规则、为何触发"的自然语言推理轨迹，供下游执行与干系人审计。③ 规则泛化：当现有规则库无法解决某案例时，LLM 基于现有库与高层领域知识推测新规则，经人工校验后再并入库。数据上采用 5K 库存差异案例（每缺口平均约 70 个候选盈余），分归纳集/验证集/4K 测试集，并以"少样本 LLM 与确定性基线分歧才送专家标注"的 disagreement-based 策略降低标注成本。

## Performance 概括
在 4K 测试集（4,101 例）上，agentic 系统对账准确率达 92%，高于领域专家耗时数月硬编码的确定性基线 85%，召回 98% 与基线 100% 相当。消融显示去掉规则归纳仅用零/少样本直推，准确率降至 84%，证明规则库作为"一致性锚点"消除 LLM 生成随机性（92%→84%）。归纳阶段 CoT 比标准提示高 8pp（92% vs 84%）且产出更完整规则库。数据表示显著影响表现：textual enumeration 84% > JSON 74% ≫ markdown 32%；规则泛化模块在 100 个含新特征的异分布案例上约 50% 成功识别有效新规则，专家审计确认所有 CoT 归纳规则均为有效领域知识。

## 论文价值与不足
价值在于把"可信 agent 评估"落到可操作框架：用归纳规则库实现可解释、用规则约束生成实现一致性、用自主规则泛化实现分布漂移鲁棒性、用人在回路迭代实现治理，并在真实对账任务上一举超过硬编码基线，同时贡献了若干对 agentic AI 评估普适的洞见（缺乏真值、随机行为、输入表示敏感性、规则数量≠质量、分布演化、可解释性提升人工监督效率、CoT 兼作评估工具）。不足：仅在库存对账单一工业域验证，跨域（欺诈检测、合规监控）迁移性未测；92% 是否为充分水平取决于该域难度；disagreement-based 标注可能低估两套系统"一致错判"的系统盲点，需周期性随机审计；泛化识别 50% 仍不足以完全自主，依赖人在回路。

## 工业界落地可行性评估
落地可行性高，尤其契合金融对账、合规审查等强监管、需可审计决策依据的场景。框架在低标注 regime 下工作（适合专家时间稀缺的域），输出"预测 + 所用规则 + 推理轨迹"三段结构，使审计员不仅能发现错、还能定位为何错，并支持人工校验后增量更新规则库，满足审计与追溯要求。落地需注意：补充更复杂真实业务规则库与更大规模验证；建立持续监控（规则覆盖漂移、置信度校准）与可扩展人工监督协议；对输入表示格式做鲁棒性测试以避免性能大幅波动。
