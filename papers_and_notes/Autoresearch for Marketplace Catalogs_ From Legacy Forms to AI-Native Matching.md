# Autoresearch for Marketplace Catalogs: From Legacy Forms to AI-Native Matching

## 背景与 Idea
双边服务市场（如 Thumbtack 这类连接消费者与本地服务专业人士的市场，论文称服务专业人士为 pro）依靠一套"目录"（catalog）作为消费者需求、服务提供者（pro）偏好与工作任务属性之间共享的表达语言：匹配、搜索与定价都依赖这套公共语言。历史上这类市场用结构化的问卷式请求表单（request-form Q&A）收集信息，目录因此是隐式的，分散在数百个按职业类别定制的 Q&A schema 中，而非统一结构。当市场转向 AI 原生的概率匹配（AI-native probabilistic matching，即由大语言模型从自然语言指令中推断用户意图、情境偏好与潜在约束，再做概率式匹配）时，问题出现了：这类匹配需要结构化的 provider 偏好信号来支撑匹配、搜索与定价；隐式目录在 AI 原生体系下变成负担，因为匹配模型需要结构化信号、定价模型需要能跨类目迁移的任务属性，而参与者也需要一个连贯的界面来表达偏好，而不必遍历数百个独立 schema。作者把问题定义为"目录重建"（catalog reconstruction）而非"新建"：因为隐式目录已经由 legacy 系统通过 Q&A 对隐式定义，任务是推断这些 Q&A 背后编码的潜在属性并重组为显式表示，而不是从零造一个全局层级。由于隐式 legacy 目录围绕不同的服务领域组织，每个领域有自己的词汇、偏好结构与匹配语义，作者把重建分解为多个更小的自研究（autoresearch）子问题——autoresearch 指一种"提出—评估—保留"（propose-evaluate-keep）的迭代式 LLM 优化范式，本文让每个职业（occupation）独立运行一个循环，而不是造一个单一全局分类法。这种 autoresearch 不宜与传统自动机器学习（AutoML）混为一谈：AutoML 调的是模型超参与结构，而 autoresearch 让语言模型自己提出假设、生成候选、用评测信号筛选并保留最优、循环往复，更接近"机器自驱动的研究助理"——本文正是用它来替代人手设计分类法这一研究性劳动，把专家从逐职业搭建 schema 中解放出来。这里的优化单元是"每个职业内部的偏好标签目录"（per-occupation preference-tag catalog），而非职业之间的层级；这种按职业并行、彼此独立的设计避免了把表面相似但操作语义不同的属性强行塞进单一全局层级、并限制了职业间的语义干扰。该系统已在 2026 年 4 月于某美国大型消费服务市场生产部署，覆盖 132 个职业（约一百三十个，含管道、家政、摄影、园艺等），pro 通过设定定向偏好决定自己有资格接收并购买哪些消费者线索。需要澄清的是，这里的"目录"（catalog）不是商品货架，而是服务市场中描述"什么样的 pro 适合什么样的消费者需求"的属性清单与偏好标签集合；legacy 表单即 request-form Q&A，是消费者下单时被要求逐项填写的结构化问卷，每个职业（如水管工、摄影师）各有独立 schema，这些 schema 拼起来才隐含地定义了一个庞大而碎片化的目录。AI-native matching 之所以让这套隐式目录难以为继，是因为 LLM 从自然语言推断意图后，匹配、搜索与定价都改为依赖结构化 provider 偏好信号，而隐式目录无法被模型直接消费或跨职业迁移。作者强调"重建"（reconstruction）而非"新建"（construction）的语义区别：legacy 系统已通过成百上千份 Q&A 暗中编码了真实存在的属性，任务是把这套散落的表达推断、重组为显式一致的标签集合，而不是凭空设计一套可能与线上行为脱节的理想分类法。这种定位也决定了优化目标必须是保真度（能否忠实映射 legacy 偏好），而非覆盖面（能否穷尽所有想象得到的属性）。

## 核心方法
每个职业独立运行 propose-evaluate-keep 循环。生成器（generator，GPT-5-4）基于该职业的 legacy 数据（各品类的 RF Q&A schema 与近期活跃 pro 是否把某 Q&A 对登记为偏好）生成候选标签集。六维度 LLM-as-judge（GPT-5-4-mini，温度为零）对每个标签打分，六维度求和得到 /15 的复合分数：Screening vs Intake 区分"该不该把某属性作为筛选条件"与"仅属客户录入细节"；Tag Legibility 衡量在岗 pro 能否仅从标签文本理解其含义；Preference Variance 检查 pro 群体是否在该标签上真实分裂（而非人人一致，那便是退化标签）；Cross-Category Consistency 要求同一作业属性在职业内跨品类用一致命名；Canonical Coverage 检查每个品类是否都有 canonical tag 覆盖；Information Loss 检查标签来源能否追溯到具体 legacy Q&A 答案。judge 分数还被一组集合级惩罚（set-level penalty）修正，惩罚标签膨胀（tag proliferation，父标签下过多兄弟标签）与覆盖缺口（legacy 偏好无对应标签）。七个 persona 的 critic 面板并行给出加权惩罚（没有硬否决）：PM、Pro、Taxonomy、Adversarial、Reasoning-Quality、Occupation-Coherence、Parity，其中只有 Reasoning-Quality 可给少量奖励，其余多为惩罚，Pro critic 惩罚封顶 2.5 以防单一怀疑型 persona 卡死循环。编辑 agent（editor）每次只对当前最佳 prompt 做一处针对性修改，针对六 rubric（加上注入的 parity-coverage 维度）中得分最低、且前两轮未被处理过的维度，查看该维度最弱标签样本、分数趋势与已接受/拒绝的编辑日志；当某个维度尽管反复编辑仍持续恶化时，editor 会切换到"根本性不同"的改法，且永不重复先前已试过的编辑。关键设计是跨家族模型栈：生成器与 judge 用 OpenAI 家族，critic、editor、parity mapper 用 Claude Sonnet 4.6，这样"提方案"与"打分"的模型不共享偏见，避免各自优化中互相强化偏见（论文称之为对 self-reinforcement 的缓解）；judge 本身还根据产品经理（PM）评审做过 recalibration（例如裸名词标签 "Appliances" 原来被打满分，校准后≤1，因为在岗 pro 看来它既显然为真又无信息量）。parity mapping 阶段运用 Step-Back abstraction（先推断每个 legacy 问题本想测量的潜在 provider 属性，而非做字面问题到标签的直译），把新标签映射回 legacy Q&A（多对多关系，并含 MEMORY_ONLY 类型原语），既产生覆盖率信号，也提供人工 QA 接口，并强制人工 sign-off 才上线。标签分两类：canonical tag 决定资格（pro 必须拥有对应品类 canonical tag，严格匹配过滤器才认为其有资格接该品类线索），specialty preference tag 让 pro 在已合格品类内细化想要接收的线索。当前搜索后端仍是朴素 LLM 提案，PM 评论通过实时表格回流到循环（human-in-the-loop）。需要注意的是，六维度 judge 的复合分以 /15 为上限（每维度满分 2.5），它衡量的是"标签集质量"而非"单个标签对错"，因此低分指向的是整组标签的策略性问题（如覆盖不全、命名不一致），而非某个具体标签必须删除。parity mapping 之所以必要，是因为即便生成器产出高质量标签，线上匹配器仍消费 legacy schema，二者必须存在可追溯的映射，否则新目录无法落地到现有线索路由逻辑；MEMORY_ONLY 原语专门标记那些"仅用于判定 pro 是否记得/愿意做某事、不应成为公开筛选标签"的 legacy 信号，避免把内部备注误当成对外资格条件。cross-family 模型栈除了缓解 self-reinforcement，还有一个实操收益：当 OpenAI 家族的生成器与 Claude 家族的 critic 对"某标签是否该存在"给出相反判断时，这种跨家族分歧本身就是一个廉价的异常信号，提示该标签处在语义模糊区，值得人工介入而非任由单一模型拍板。

## Performance 概括
重建保真度：73.3% 的 legacy 答案直接映射到新标签，20.8% 为 intake-only（尺寸/范围/"灵活"等合理非标签），仅 6.0% 为遗憾遗漏；按应映射项算 pooled coverage 92.5%，职业中位数 100%（均值 97.8%）。生产数据：14 天队列（1,840 个 MVP pro，9.3M 次 filter evaluation）。关键发现——40.66% 的 filter 失败源于"缺失 canonical category tag"，这是部署侧播种缺口而非目录质量问题；Handyman 单独占约 70% filter 事件。循环在迭代 3 前即达最优（best kept tag set 中位数迭代 2），E 分数中位数 13.84/15，循环相对单发生成提升中位数 +2.24 分、改进 119/132 职业。

## 论文价值与不足
价值在于首个生产级目录重建自研究系统，提出 per-occupation 独立循环、marketplace-grounded 加权 critic（无硬否决，避免单 persona 卡死循环）、legacy Q&A parity mapping（含 Step-Back abstraction 与 MEMORY_ONLY 原语）等可复用设计，并诚实区分"目录质量"与"部署结果"两类指标（如 40.66% filter 失败是部署侧问题）；生产规模还暴露了一个全局层级构建会掩盖的运营发现——三个废弃标签驱动了 48.6 万次 filter 事件。不足与信任缺口在于：六 rubric judge 与人类质量的一致性仍需独立外部 evaluator 验证（计划未做）；跨职业标签名漂移（如 Client preference/type 同义异名、大小写不一致）需下一波修复；与 legacy form 的结果级因果对比是未来工作；跨家族安排虽缓解了生成器与 critic 间的自强化，但 Claude Sonnet 4.6 内部的 editor 与七个 critic 仍共享同一模型家族，若 editor 的偏见方向恰被 critic 认可便无法被循环发现（可由第三个模型家族如 Gemini/Llama 担任一个 critic 席位来缓解），且 critic 分歧当前是"静默"的——editor 只看到聚合后的调整分而非各 critic 分解，高方差裁决会被平均进同一标量。搜索后端升级为 GEPA 式带执行轨迹的反思优化、以及把"41% 缺失 canonical tag"这类 matchmaker 侧失败回灌到下一轮自研究，是作者列出的两条明确扩展路径。还有一个值得点出的设计张力：本文把"优化单元"严格限定为 per-occupation 标签目录、刻意不做全局层级，这固然避免了跨职业语义干扰，但也意味着职业之间无法共享通用属性（如"服务半径""是否需要上门"），当消费者跨职业表达需求时，目录层不会提供统一抽象——这是 per-occupation 独立性必须付出的代价，作者并未声称已解决。

## 工业界落地可行性评估
已在 Thumbtack 真实生产部署（132 职业、按需数小时 onboarding 新职业、强制人工 sign-off），是本文最明确的工业落地案例之一，落地可行性高且已被真实流量验证。其"组合式"架构（per-occupation 独立 + 七 persona critic 面板 + parity mapping）可复用到任何携带大量 legacy 结构化数据的市场，把获得正确 pro 侧 schema 的下游收益放大。研究还指出单轮决策一致性并非验收门禁，而人工反馈会回流到自动循环，使其更接近真实生产运维形态；下一步若把 matchmaker 侧生产失败（如 41% 缺失 canonical tag 的 filter 率）路由回下一轮自研究迭代，将闭合"目录生成 ↔ 匹配结果"之间的回路。对工业界的实操建议是：在保留强制人工 sign-off 与跨家族模型栈的前提下，逐步引入第三个模型家族 critic 席位以暴露 editor/critic 同族偏见，并把 per-critic 分解与分歧摘要作为显式 editor 输入以提升循环可信度。需要强调的是，该系统的落地前提是市场已存在结构化程度较高的 legacy Q&A 数据——autoresearch 循环依赖"近期活跃 pro 是否把某 Q&A 对登记为偏好"这类历史信号作为生成器的输入；对没有这种历史埋点的新兴市场，per-occupation 循环将缺少冷启动的素材，落地可行性会显著下降，论文并未讨论零历史场景的处理。此外，pro 通过设定定向偏好来"购买线索"这一商业模式意味着标签质量直接影响 pro 的收入分配与消费者匹配公平，因此强制人工 sign-off 不只是质量闸口，也是合规与信任层面的必要控制，不能为了自动化而省略。
