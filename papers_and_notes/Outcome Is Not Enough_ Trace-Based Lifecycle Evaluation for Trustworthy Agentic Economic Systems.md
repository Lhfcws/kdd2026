# Outcome Is Not Enough: Trace-Based Lifecycle Evaluation for Trustworthy Agentic Economic Systems

## 背景与 Idea
agentic 经济系统（agentic economic system，指能自主定价、分配预算、调用工具并在多步交互中适应的生产级 agent）常以标量业务结果评估：收入、转化价值、支出效率、延迟等。这些信号客观、可扩展，但当 agent 处于隐藏状态（hidden state）并改变了它所评估的系统本身时，这些信号可能不可信。本文作者（Blossom AI）把这一类失败归入"代理失效 / 奖励误设（reward misspecification / reward gaming）"的家族：同一标量结果可由多个潜在状态、多条有效行为轨迹产生，于是 agent 可能优化了一个局部 KPI，却破坏了让基准系统可靠的行为纪律。

作者用一个双酒店定价 benchmark 研究此失败：一个学习定价 agent 可以达到合理的 RevPAR（每可用客房收入），却未能保持规则基准（rule-based revenue-management benchmark）的收益管理纪律。由此提出 discipline stability（纪律稳定性）——一个策略相对基准是"纪律稳定"的，当且仅当它在部署可观测的信息体制下，既保持标量结果、又保持基准的行为轨迹结构（trace structure）。这个 framing 把"上线后监控"变成了一个具体的轨迹问题：在训练、迁移、模型更新、或移除特权基准信号之后，哪些行为统计量应当保持稳定？

论文把问题边界讲得很清楚：它贡献的是一套针对带隐藏状态、带演化反馈环的 agentic 经济系统的评估与监控框架，而不是一个新的优化器、也不是对多 agent 强化学习（MARL）的普适断言。其四大贡献为：定义一套基于轨迹的生命周期评估协议；展示一个可复现的失败（reward-only PPO 变体即便标量目标自然，也会错过基准轨迹）；诊断触发机制（隐藏的竞争对手库存让一个可见状态兼容多个有效基准价格，于是确定性复制坍缩了不确定性）；测试持续性（corrected-history student 能继承教师大量纪律；移除固定基准后冻结的learned-agent 对局不会立刻坍缩）。

把本文放进更大的图景有助于理解它的针对性。近期 agent benchmark 多研究工具使用、网页/桌面控制、软件任务、交互决策等（如 MLAgentBench、SWE-bench、AgentBench、AgentBoard、OSWorld、WebArena、τ-bench），而本文研究一个互补的生产评估问题：当经济 agent 在反馈系统里行动时，评估者能否检测该 agent 是否保持了基准的行为结构、而不只是达成了 headline 分数？这呼应了"accuracy-only 基准会隐藏成本、短路、弱 holdout、可复现性失败"的近期批评（如 AI Agents That Matter），也与奖励博弈（reward gaming）和奖励误设（reward misspecification）的文献一脉相承——同一标量结果可由多个潜在状态、多条有效行为轨迹产生，于是优化局部 KPI 却破坏可部署纪律成为一种"代理失效（proxy failure）"。本文的测试床虽是酒店定价，但核心问题更一般：当 agent 在部分可观测下行动，同样标量结果可由多个 latent state 与多条有效 trace 产生。

## 核心方法
主基准是一个两酒店定价模拟器。Hotel A 是学习 agent（learner），Hotel B 是固定的收益管理（RM）对手，用基于时间、市场条件、自身隐藏剩余库存的确定性规则定价，learner 看不到 B 的库存或定价规则。每轮 Hotel A 选价 p_A,t、B 选价 p_B,t=FixedRM(t, q_B,t, m_t)；客人选 A、选 B 或选外部选项。从 A 视角看这是一个单 agent 部分可观测控制问题（POMDP），但 A 的定价会改变哪个酒店获得需求。标量奖励是每步收入归一化到起始容量（r_A,t = p_A,t·y_A,t / Q_A），求和即得 RevPAR；该奖励自然鼓励卖房，却不区分"有纪律的收益管理"与"低价占满 occupancy"——这正是标量指标不够的关键。

信息体制分三档：NC（无对手价上下文）、CA-lag（观测滞后市场价）、Oracle（额外知道 B 的当前库存 q_B,t）。两个可部署体制（NC、CA-lag）都看不到当前 q_B,t 与 RM 规则。POMDP 触发点正是隐藏的 q_B,t：同一个 A 可见观测可对应多个竞争对手库存、从而多个有效基准价格，因此正确目标应是后验预测分布而非单一动作标签——这就是"隐藏状态混叠（hidden-state aliasing）"。

discipline-stability 协议有五步，构成一套生命周期评估工具：① 定义超出 KPI 的基准纪律（benchmark discipline）；② 限定可部署观测体制与隐藏变量；③ 从观察到的失败中诱导轨迹诊断（用 D1 距离 ∑|P(x)−Q(x)| 与 Jensen-Shannon 散度度量价格/bid 分布相对基准参考的偏离）；④ 用消融分离弱优化、隐藏状态、确定性坍缩、分布修复四种机制；⑤ 测试在直接基准访问减少/移除后纪律是否持续。预部署测试可揭示"标量 KPI 达标但是为错原因"，上线后监控可跟踪模型更新/上下文变化后的轨迹分布漂移，治理审查则能用同一批轨迹问"agent 做了什么"而非"得了多少分"。

实验对象分两类对照。负对照是 reward-only PPO 变体（含循环 R-PPO、CTDE PPO，critic 训练时能看到隐藏对手信息但部署时 actor 仍去中心化），它们只优化 r_A,t；trace-access 基线则有 BC-only 随机复制、BC 热身+PPO、带 BC 辅助损失的 PPO。核心方法是 Trace-Prior teacher：从观测到的市场轨迹训练一个监督先验 π̂_M，再优化目标 J(θ)=E[r_A,t^out − β·D_KL(π_θ(·|o_t) ∥ π̂_M(·|o_t))]，系数 β 在约束结果优化与轨迹纪律间插值（选定教师用 β=30）。该先验估计的是隐藏状态下的基准轨迹，而非 agent 自身离线行为，与 offline-to-online RL 思路相关。第二域验证用 hidden-budget bidding：出价策略为顺序广告机会选出价档位，全状态专家能看到剩余预算并 pacing 花费，部分策略看不到隐藏预算，纪律轨迹是出价分布加 pacing 行为。该域用四变体（默认、紧预算、高竞争、易变质量）各 10 个 seed 测试，标量结果是每步转化价值，纪律轨迹是出价分布加 pacing 行为；它比酒店域更紧凑，目的是检验"范式是否只适用于酒店"——结果证明同一机制在 bidding 上也成立：标量接近但纪律失败、argmax 可提升结果却坍缩隐藏状态不确定性、随机 trace-prior 采样保留专家轨迹。

持续性测试（persistence）是生命周期视角的重点，需单独说明。论文先训练 corrected-history student：用 DAgger 式的纠正思路，学生输入可见状态与自身最近纠正过的历史价格（o_S,t 含归一化时间、A 剩余库存、市场条件、自身历史动作滞后 3 步），教师标定的状态由学生自身 rollout 诱导，部署时移除教师。再"冻结"学到的策略并移除固定 RM 基准（注意这是部署诊断而非在线共学习），NC-vs-NC 与 CA-vs-CA 对局保持对称；在席位平衡的混合部署中 CA 有小的方向优势（RevPAR 107.891 vs 107.471），支持的论断是谦逊但重要的：学到的策略在基准移除后不会立刻坍缩回低价捷径。这说明 trace 纪律具有可迁移性，也意味着监控栈必须包含"持续性测试"这一层，否则只能看到上线瞬间的合规、看不到模型更新后的漂移。

## Performance 概括
reward-only PPO 变体失败于基准 trace：PPO 的 RevPAR A=93.55、Trace-Prior teacher=108.06（后者 D1=0.0165、D_JS≈0.0000）；CTDE PPO RevPAR A=94.48、D1=0.6582 仍远偏离。容量不对称（Q_A=120, Q_B=100）下 Trace-Prior RL 提升 RevPAR +0.764（95% CI [0.125, 1.403]），靠在相似价位填满更多房而非提价。隐藏状态机制：argmax 预测逐步准确率 78.14% 但聚合对齐更差；采样把步准确率降至 69.50% 却改善 D1（0.0323→0.0183）——动作准确率与轨迹对齐可反向移动。学生继承：corrected-history student 的主要业务指标落在教师 95% CI 内（RevPAR 107.96 vs 108.06）。冻结部署（移除 Fixed RM）后 learned 策略不立即坍缩回低价捷径（CA 略有方向优势）。第二域 hidden-budget bidding：outcome-only 激进出价 value/step=0.374、纪律差（D1=0.986、pacing gap 0.212）；partial argmax 模仿几乎恢复标量值（0.475）却仍轨迹错（D1=0.3549）；trace-prior 采样保留专家 trace 最佳（pacing gap 0.059，D1=0.0130，D_JS≈0）。

## 论文价值与不足
价值在于把"代理失败 / 奖励误设"框架化为一套可度量的生命周期评估协议，并揭示了"标量结果相同但行为纪律失败"这一被 accuracy-only benchmark 掩盖的现象。它给出一套可部署的监控栈：标量 KPI（收入、转化价值、延迟）→ 业务分解（occupancy 与 ADR，或 spend 与 pacing）→ 轨迹分布（价格/bid 分桶、D1、D_JS）→ 状态切片（早/晚 horizon、高/低库存、紧/松预算）→ 持续性测试（student 迁移、冻结部署、混合信息体制对局）。这套栈把"分数提升了但行为纪律是否保持"变成可操作的工程问题，对定价、出价等经济 agent 的生产监控直接有用。它指出冲突模式/轨迹分布可作无真值漂移检测信号，呼应了"accuracy-only 基准会隐藏成本、短路、弱 holdout、可复现性失败"的近期批评。一个对生命周期评估尤为关键的方法论教训是：动作准确率与轨迹对齐可以反向移动——argmax 预测步准确率更高（78.14%）却扭曲了聚合轨迹，随机采样步准确率更低（69.50%）却改善了 D1；这意味着若只看"每步动作对不对"会误判纪律，必须把分布层面的轨迹距离纳入监控。

不足也明确。其一，模拟器是合成的、未用真实酒店数据校准，结论外推到真实业务需谨慎；其二，Hotel B 是固定基准而非学习对手，无法反映线上共学习的动态；其三，bidding 任务紧凑（仅四变体），不是完整生产广告系统；其四，trace prior 质量受限于基准轨迹本身——若基准轨迹有噪声、有偏、串谋或商业上不可取，方法会保留"错误的纪律"；其五，论文未覆盖 MAPPO、MADDPG 式在线共学习、真实数据校准、模型更新漂移测试等自然下一步。作者也明确划界：不声称真实酒店有效性、不声称所有现代 MARL 方法都失败、不声称在线共学习安全。这种诚实的边界声明本身是该范式可被信任的前提——它把贡献定位为评估/监控工具，而非"证明某类 MARL 不行"的普适论断。

## 工业界落地可行性评估
中等可行，定位是"定价 / bidding 等经济 agent 的生产监控与治理"而非新训练算法。论文给出可部署的监控栈与持续性测试建议，能直接回答"KPI 涨了，但 agent 的行为轨迹是否还兼容基准纪律"这一治理问题——对广告出价、收益管理这类"标量好但行为可能走偏"的场景尤其对症。落地方式是保留原始事件日志（观测状态切片、动作分桶、实际结果、可用时的基准/参考动作、按 seed/周期聚合元数据），以便模型或策略更新后重算每个轨迹统计量，支撑漂移检测与 shortcut 优化识别。

落地障碍主要有四：其一，需真实数据校准模拟器/基准轨迹，否则纪律定义建立在合成分布上；其二，trace prior 依赖"基准轨迹本身值得保留"，若企业历史策略有偏或串谋，需先审计基准；其三，监控栈要持续采集与存储细粒度轨迹日志，对数据基建有要求；其四，论文的 frozen-deployment、student-transfer 等持续性测试需在真实上线前做受控诊断，而非直接假设。落地时具体要做的事是：先把"什么是合规的基准纪律"显式写成可度量的轨迹统计量（价格/bid 分桶分布、pacing gap、occupancy 与 ADR 分解），再把生产系统的原始事件日志（观测状态切片、动作分桶、实际结果、可用时的基准动作、按周期聚合元数据）持久化，以便每次模型或策略更新后重算 D1/D_JS 等轨迹距离并触发告警。这套监控栈可叠加在现有定价/出价系统之上，无需替换底层算法。

总体看，作为评估与监控范式（而非即插即用的服务），它在已有定价/bidding 系统的团队中可被渐进采用，但前提是愿意投入轨迹日志基建与基准纪律的显式定义；它最适合作为"上线前纪律审计 + 上线后漂移监控"的治理层，而不是作为提升 KPI 的优化器。
