# Beyond the Final Answer: Evaluating the Reasoning Trajectories of Tool-Augmented Agents

## 背景与 Idea
工具增强智能体（tool-augmented agent）指让大语言模型在回答用户请求时调用外部工具（如计算器、图像描述、数据库查询、网页检索）的智能体系统，典型实现是 ReAct 式循环：每轮由 Thought（思考）、Action（选定工具与参数）、Observation（工具返回结果）三段组成，反复迭代直到给出最终答案。工具增强的意义在于补足模型自身的知识与时序计算短板，但随之而来的问题是"如何判断一个智能体做得好不好"。现有基准（GTA、m&m's、GAIA、MetaTool 等）几乎都把评测简化为 Answer Match——只校验最终输出是否与人工标注的 ground-truth 一致。作者指出这一定式有明显盲区：两个 agent 即便最终准确率相同，其推理过程可能天差地别，一个用最少步骤直达答案，另一个充满冗余调用、幻觉（在证据之外凭空断言）或对工具失败缺乏适应能力。更隐蔽的是，同一个用户请求往往存在多条都正确的有效轨迹（例如先查图 A 还是先查图 B），逐条标注所有 ground-truth 轨迹代价极高，因此评测框架必须做到 reference-free（无需参考答案轨迹）。基于此，论文提出 TRACE，从效率（efficiency）、幻觉（hallucination）、适应性（adaptivity）三个常规基准忽视的维度评估推理轨迹质量。这三点之所以重要，是因为它们直接对应工具型 agent 在真实部署中的成本与可靠性：冗余步骤浪费 token、幻觉制造错误事实、缺乏适应性则让一次工具故障拖垮整轮对话。论文发表于 KDD Workshop on Evaluation and Trustworthiness of Agentic AI（2026，济州），定位正是“评估与可信赖性”这一新兴议题。进一步看，“推理轨迹”（reasoning trajectory）指 agent 从接收请求到给出答案之间产生的全部 Thought/Action/Observation 序列，它才是 agent 真实行为的中介，而非首尾两端。现有基准忽略轨迹，等于把“过程正确”与“结果正确”等同，而工程上二者经常脱钩：一个答对的 agent 可能靠运气或冗长试错，一个答错的 agent 也可能过程基本正确只是最后一步出错。把轨迹作为评测对象，才能区分这两种情况。此外，“工具增强”之所以成为独立研究议题，是因为当模型学会调用工具后，失败模式从“算错”变成了“调错工具、读错观察、在错误状态上继续推理”，这些都需要从轨迹层面而非答案层面诊断。从产业视角看，这三维度直接映射到部署成本与可靠性：效率对应 token 与延迟开销，幻觉对应输出事实正确性，适应性对应面对工具故障时的鲁棒性。也正因如此，仅靠 Answer Match 的榜单会让一个“答得对但贵得离谱、且一遇工具故障就崩”的 agent 与一个“精简稳健”的 agent 被同等对待，掩盖了真实运维风险。

## 核心方法
TRACE 全称为 Trajectory-based Reasoning Assessment and Comprehensive Evaluation，面向 ReAct 式 agent。其核心组件是 evidence bank（证据库）：把每一步的 (action, input, observation) 累积为结构化证据，而不是把整段非结构化的对话原文直接喂给 LLM 评判，从而让效率与幻觉的衡量更稳定、可复现。选择结构化证据而非原始对话的原因在于，长对话原文夹杂无关叙述，直接交给判断模型会引入噪声，而证据库只保留与工具调用相关的三元组。三个维度的度量方式如下。效率评估是 post-hoc（事后）分析，且仅在 agent 已给出正确答案的轨迹上才计算：用 LLM 从证据库中挑出推导答案所需的最小证据集 Emin，效率分数 Eff(T) = |Emin| / |Etotal|，比值越接近 1 越冗余、越低表示越精简。幻觉检测用 IsGrounded(th_t, E_{t-1}) 判断每一步 thought 是否能由此前全部证据支撑，若依赖证据库之外的内部知识就记一次幻觉，最终分数取各步平均。适应性（adaptivity）则针对工具失败场景：研究者在 GTA 标准工具集里注入一批名称与原工具高度相似但无效的"伪工具"（fake tools），当 agent 选中伪工具时环境返回 "unavailable tool" 错误，再看其后续步能否合理切换到替代工具，评分是二值的（能否恢复）。为减少噪声，环境还带一个 feedback mechanism：当 agent 调用了不在列表中的工具或参数格式错误时，环境给出"tool not in the list / tool execution error"的具体反馈而非直接终止，且这些初始错误仍被计入指令错误指标。评估者模型（evaluator）方面，作者依据 meta-evaluation 表现挑选了 Claude-Sonnet、GPT-4.1、Llama-70B、o3-mini 四种担任裁判。TRACE 还可扩展到多智能体系统（MAS）：为每个 agent 维护独立证据库，并在 orchestrator 与子 agent 的每一步用全部证据库校验幻觉，例如论文在 GAIA 上对 Magentic-One 做了展示。作为对照基线，作者与 PIPA 的 state consistency（状态一致性）指标比较：PIPA 按累积状态的一致性惩罚多余工具调用，但当查询并行附带多个输入文件时其一致性分数会下降；TRACE 因为是在整条轨迹中识别“对最终答案非必需的证据”，轨迹顺序的多样性不影响其判分，因此在多有效轨迹并存时方差更小、更稳健。在 meta-evaluation 数据集构造上，作者在 GTA 与 m&m's 的真实轨迹上人为注入三类缺陷——低效率（多余工具调用）、幻觉（无证据支撑的断言）、适应性缺失（工具失败后不切换替代工具），再由人工标注多维性能分数，从而能反向检验评估器自身是否识别得出这些缺陷，这正是 PIPA 等只给单一一致性分数的方法做不到的。另一个工程要点是“adaptivity”的触发方式：他们不直接改环境逻辑，而是放入名称与正版工具高度相似的伪工具（fake tools），让 agent 自然踩坑，再用“unavailable tool”错误测试其后续是否恢复，这种受控失败注入比随机断网更接近真实工具故障。TRACE 对多智能体的扩展也值得注意：它给每个子 agent 建独立证据库，并在 orchestrator 与子 agent 的每一步用全部证据库做幻觉校验，论文以 GAIA 上的 Magentic-One 为例做了演示。

## Performance 概括
论文构造了 Meta-GTA 与 Meta-m&m's 两个 meta-evaluation 数据集（在 GTA、m&m's 上注入低效率/幻觉/适应性步骤并人工标注）来验证评估器本身。在 Meta-GTA 上，TRACE 相对朴素 LLM-as-a-Judge 在效率、幻觉、适应性三维度均有明显提升（如 Llama-3.1-8B 效率由 86.47 升至 90.03、适应性由 70.46 升至 85.28），且小开源模型受益最大。与 PIPA 的状态一致性指标相比，TRACE 在多种有效轨迹并存时方差更小、更稳健（Llama-8B 在 PIPA 上仅 24.94，而 TRACE 为 79.10）。在真实 GTA 任务上评测 9 个 agent（Claude、GPT-4.1、o3-mini、Llama、Mixtral、Mistral、Qwen 等）：o3-mini 幻觉率极低但适应性弱，GPT-4.1 与 Qwen-72B 总准确率相近（约 0.53 vs 0.52）却在效率/幻觉上各有短板；Figure 4 还显示输出 token 数、对话轮次与总准确率呈负相关，即越长轨迹越易失败。GTA 本身是一个含多模态、多输入查询的较新挑战性基准，按查询类型用 MCQ 二值准确率、长文本响应用 All-MPNet-Base-V2 嵌入余弦相似度、图像用参数嵌入余弦相似度分别计分，并以微平均得出 Overall Accuracy。

## 论文价值与不足
价值在于把 agent 评测从"只看结果"推进到"看过程"，提出的三维度（效率/幻觉/适应性）切中工具型 agent 真实痛点，且 reference-free 设计与 evidence bank 机制让小模型也能胜任评判，降低了评测成本。论文还给出了若干有反直觉的过程洞察：效率与整体准确率大体同趋势（更大模型通常更精简），但越长的低效轨迹越容易答错，作者假设原因是更长上下文削弱了模型的准确推理能力；推理模型 o3-mini 幻觉率极低，可能来自其深度推理（LRM）只盯累积证据的特性；而 Mistral-7B 之所以幻觉分数偏高，并非因为它更可靠，而是它在无法推进时就直接终止——这是用"分数高"掩盖"没做成"的度量假象，提醒读者不能孤立读单维指标；GPT-4.1 与 Qwen-72B 整体准确率高但适应性低，说明提升对工具失败的适应能力是进一步提分的杠杆。不足方面：效率分数只衡量"所选工具中的冗余"，并不保证找到全局最优路径；幻觉定义偏宽松（只要用了证据库之外的内部知识就计为幻觉）；实验主要基于 GTA 单一基准，小模型（Mistral-7B）几乎无法产出正确答案导致很多指标缺失，泛化性结论需谨慎；幻觉与效率两维又都与整体准确率高度相关，独立性有限。从评测方法论看，TRACE 把“轨迹质量”拆成三个可在工程上分别优化的子目标，比单一准确率更适合做回归看板：例如 o3-mini 整体分不低却因适应性弱而在工具故障后难以恢复，提示对该类推理模型应补“失败重试/工具切换”机制；GPT-4.1、Qwen-72B 这类高分模型若幻觉偏高，则需要约束其引用证据的范围。论文还给出一个对落地很关键的反直觉结论：效率与幻觉两维都与整体准确率高度相关，也就是说“过程差”通常会直接拖累“结果对”，所以监控三维度并非额外负担，而是指向最终准确率的先行指标。当然，这正是其局限的另一面——三维度独立性有限，单独看某一维可能被高分假象掩盖（如 Mistral-7B 幻觉分高只是因为它直接放弃）。

## 工业界落地可行性评估
该框架对需要真实部署 tool-augmented agent 的企业（如客服、数据分析、RPA）有较高实用价值：其 reference-free 特性意味着无需维护参考答案即可对线上 agent 轨迹做持续质量监控，证据库机制也便于定位冗余调用与幻觉步骤以优化成本。论文已开源代码（github.com/wonjoong-kim/TRACE），并指出 Llama-3.3-70B 评测耗时仅为大模型约 1/3，利于大规模低成本部署；可结合反馈机制与"accuracy × efficiency 加权"缓解只统计成功样本带来的幸存者偏差，适合作为 agent 上线前的回归评测组件。对工程团队的更直接用法是：把效率分与幻觉分纳入 agent 迭代的回归看板，一旦某次模型或提示词更新导致轨迹变长、幻觉上升，即便最终准确率没掉也能及时告警。需要提醒的是，由于幻觉定义偏宽松、且评测锚定在 GTA 这类多输入基准，落地到业务自有工具链时仍需先在小样本上校准证据库与评判提示，避免把合理的内部知识误判为幻觉。一个常被忽视的落地细节是 evidence bank 同时承担“可解释性”职责：线上 agent 出错时，运维可直接打开证据库判断是冗余、幻觉还是无适应性导致，而不必通读整段对话。配合用 Llama 等小模型做裁判、把评测耗时压到大模型约三分之一，这套框架很适合嵌入持续集成，作为 agent 的回归测试：每次提示词或工具集变更后自动跑一遍并对比三维度分数，一旦轨迹变长或幻觉上升即使准确率未掉也能告警。具体接法上，可把 TRACE 的三维度分数作为 agent 服务的回归指标接入监控：每次模型灰度发布或提示词变更后，取一批评测任务跑出 Eff/Halluc/Adapt 分数，与基线对比触发告警阈值；再用 accuracy×efficiency 的加权综合分缓解“只统计成功样本”带来的幸存者偏差——因为答对的样本可能恰好是成本低的一批，掩盖了整体轨迹的退化。论文提到 Llama-3.3-70B 评测耗时仅大模型约三分之一，意味着即便高频回归也不会让评测本身成为成本瓶颈。
