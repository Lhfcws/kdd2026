# Construct Validity Failures in Agentic AI Benchmarks: An Empirical Audit

## 背景与 Idea

agentic AI benchmark（智能体评测基准）如今被大量用于给语言模型排名、指导采购决策、设定研究方向，乃至支撑营销宣称。但一个根本问题长期未被检验：这些榜单到底有没有在测量它们声称测量的那个"构念"（construct）？本文借用心理测量学（psychometrics）里的 construct validity（构念效度）概念，对主流 benchmark 做了一次实证审计。所谓构念，是指某个理论构想出的、不可直接观测的属性，比如"推理能力""工具使用能力"。构念效度衡量的是一个测试是否真的测到了它自称要测的那个属性；一个有效的测试应当满足：与测量同一构念的其它测试正相关（收敛效度，convergent validity），与测量不相关构念的测试不相关（区分效度，discriminant validity），且其内部题目彼此一致（内部一致性）。这套框架源自心理测量学对智力测验与人格测验的研究传统：一个测验必须能被验证"真在测它声称测的属性"，否则排名再高也只是测量了别的构念。把该纪律迁移到 agent 评测，正是本文区别于一般 benchmark 吐槽的核心——它不质疑某个分数的对错，而是质疑"分数能否被当作统一能力的证据"，因此结论指向的是榜单方法论缺陷而非具体模型能力。

把这套框架搬到 agent 评测上：一个有构念效度的 agent benchmark，应当精确定义自己测的是哪项能力，与测同一能力的其他 benchmark 给出一致的模型排名，而与测不同能力的 benchmark 给出不同的排名。如果不同 benchmark 之间的模型排名高度相关，说明它们测的是同一个东西；如果彼此无关甚至负相关，说明它们测的是不同东西；如果一个综合榜单把若干个本应测不同能力的分数平均成一个数字，那这个分数就可能在误导——它可能既不代表工具使用能力，也不代表推理能力。

论文的关切有具体的现实动因。设想一个产品团队要选一个客服 agent 来处理退款、改签航班、回答政策类问题，于是去查一个把 SWE-bench、GPQA、τ-bench 分数平均起来的综合榜单，榜单推荐了 o4-mini，因为它推理分高、综合靠前。但本文会展示：o4-mini 在 GPQA Diamond（推理）排第 2，在和它真实使用场景最像的 τ-bench Airline 却排第 9，这中间有 7 个名次的落差被综合分数掩盖了。团队据此部署了 o4-mini，结果 agent 在其最贴近的场景下表现不佳。这不是假设，而是构念无效评测可预见的后果。

论文把"agent benchmarks 是否测到了声称的能力"当作核心科学问题，覆盖五大 benchmark——τ-bench Retail、τ-bench Airline、SWE-bench Verified、GPQA Diamond、MMLU-Pro——并在 15 个模型上做跨基准分析。其中 GPQA 与 MMLU-Pro 被特意选作"非 agent"的区分效度对照：如果 agent benchmark 真的测的是有别于"通用推理"的构念，那它们彼此间的相关应高于它们与 GPQA/MMLU-Pro 的相关。这一选择本身就体现了心理测量学的严谨——用对照构念来检验区分效度。

## 核心方法

论文的方法可以概括为"把心理测量学的效度检验流程，原样搬到 agent 评测生态上"。先说 benchmark 选择：五个基准覆盖了 agent 评测的主要地形——τ-Retail 与 τ-Airline 测"工具使用 + 政策遵循"的多轮 agent 交互；SWE-bench Verified 测代码生成 agent 在真实 GitHub issue 上的表现；GPQA Diamond 测研究生级科学推理；MMLU-Pro 测横跨 14 个学科的广博知识。后两者虽常被塞进 agent 综合榜单，但本质是"非 agent"推理基准，被当作区分效度控制组。

模型选择上，作者收集了 15 个模型的公开分数，横跨三个能力档位与多家供应商：Anthropic 的 Claude 系列（3.5/3.7/4/4.1/4.5 等）、OpenAI 的 GPT 与 o 系列（含推理专用的 o1、o3-mini、o4-mini）、以及开放权重生态（文中指出来自 Llama、Qwen、Mistral 的覆盖不足）。分数采集于 2026 年 5–6 月、7 月再核对一次，且只用各基准标准配置下的官方/榜单数字（例如 τ-bench 用标准 pass^1 与标准用户模拟器；SWE-bench 用各家的单轮 agentic scaffold 而非并行测试时计算），因为 τ-bench 分数对模拟器模型与 scaffold 敏感，第三方改了模拟器的复现会得到不同绝对值。作者诚实指出，各家自报协议并非逐字一致，这种残留协议方差本身就是一个构念效度问题，因此它驱动了后文的 D1、D4 两条 desiderata，且本文的相关应被读作"从业者实际查阅的公开分数生态"的性质，而非受控实验。

分析由四步构成。第一，跨基准排名相关：对每对基准，在被共同评测的模型上算 Spearman 秩相关 ρ；若测同一构念，ρ 应很高（作者以 >0.85 为"统一 agent 能力"的阈值），若测不同构念则应低。第二，收敛 vs 区分效度：比较"agent 基准之间"的平均相关与"agent 基准 vs 非 agent 基准"的平均相关，收敛效度要求前者高于后者。第三，排名反转（ranking inversion）：对每对基准，统计有多少对模型在 X 上高于 Y、在 Z 上却低于 Y；高反转率意味着排名是基准特定的、不可泛化。第四，排名画像（rank profile）分析：对评分覆盖 4 个以上基准的模型，算其名次跨度（最高名次减最低名次），跨度 >5 者即"构念模糊"模型，说明其能力无法被单一排名概括。统计上用 Spearman 而非 Pearson，因为关心的是排名的序数关系而非不同量纲的分值线性关系；这也意味着本文结论约束的是"排名能否跨基准泛化"，而非"模型在某基准上的绝对能力高低"——这一相对定位让结论对评分尺度与量纲差异不敏感，但相应地，它不能直接说明某个模型"真实能力"有多强，只能说明"把多个基准的分数平均成一个数字"缺乏心理测量学依据。显著性检验 α=0.05，并对 10 组两两比较做 Bonferroni 校正（α_adj=0.005）；样本量 6–15，作者明确把少于 8 个样本的相关系数标记为统计功效有限、仅作完整性报告、不支撑任何头条结论。

基于上述分析，论文提出五条 desiderata（理想基准应满足的要求）作为评测设计的自检清单。D1 显式构念定义：每个 benchmark 应精确说明自己测什么、不测什么。D2 收敛效度证据：声称测"工具使用"的基准，应展示与 established 工具使用基准的相关（ρ>0.80）。D3 区分效度证据：工具使用基准应产出与推理基准不同的排名。D4 按构念报告分数：含异构子任务的基准应报子任务分而非单一聚合分。D5 披露排名稳定性：应报告相对相关基准的预期排名反转率。这五条直接对标心理测量学测试手册里的做法（如重测信度、因子结构），意图把"构念验证"变成 benchmark 论文的默认内容。

## Performance 概括

跨基准的 Spearman 相关均值 ρ=0.67（范围 0.10–0.92），整体只是"中等"相关，远低于支撑"统一 agent 能力"所需的 0.85。具体看：agent 簇内部 τ-Retail×SWE-bench=0.81、τ-Retail×τ-Airline=0.75、τ-Airline×SWE-bench=0.66；推理簇 GPQA×MMLU-Pro=0.92。跨域相关则低得多：τ-Airline×GPQA=0.49（不显著，n=9）、τ-Airline×MMLU-Pro=0.10（近乎为零，p=0.85，n=6）。一个值得注意的反常是，τ-Retail 与推理基准的相关（与 GPQA 0.76、与 MMLU-Pro 0.80）几乎和它与其它 agent 基准的相关一样高，说明 τ-Retail 部分像"通用能力"度量，收敛效度只得到部分支持（域内平均 ρ=0.74 vs 跨域 ρ=0.59），分离主要靠 τ-Airline。

排名反转方面，平均 22% 的模型对存在反转；涉及 τ-Airline 的反转率最高（31%–40%），说明航空域工具使用能力与推理能力几乎不相关。最突出的构念效度失败来自 OpenAI 的推理专用模型：o4-mini 在 GPQA Diamond 排第 2（81.4%）、MMLU-Pro 排第 2（81.4%），却在 τ-Retail 跌到第 6（71.8%）、τ-Airline 第 9（49.2%）；o1 在 MMLU-Pro 排第 1、GPQA 第 4，却在 τ-Retail/τ-Airline 第 7、SWE-bench 第 9；o3-mini 在 MMLU-Pro 第 3、GPQA 第 5，却在 τ-Retail 第 12。反向不对称也存在：推理专精并不迁移到工具使用，但强工具使用与强推理并不互斥——Claude Sonnet 4.5 在三个 agent 基准和 GPQA 上都排第 1。排名画像上，推理模型跨度最大（o3-mini 跨度 9、o1 跨度 8、o4-mini 跨度 7），而 Claude 模型跨度仅 0–5，更"可预测"。最终结论：没有任何一个被审 benchmark 满足全部五条 desiderata；τ-bench 最接近（显式定义、报分域分、区分效度强），但同样未全满足。

## 论文价值与不足

价值在于用一套成熟、严谨的心理测量学框架，第一次系统地对 agent benchmark 做了构念效度审计，把"榜单是否真在测它声称的能力"这个被社区长期忽略的问题摆上台面。它用可复现的相关、反转率、排名画像数据证明：现有分数诱导不出稳定的跨基准模型排名，更符合"多个不同构念"而非"统一 agent 能力"，因此聚合榜单与单数字排名对从业者具有误导性。它进一步给出可直接套用的 D1–D5 清单，把"构念验证"从哲学讨论变成 benchmark 设计的可执行规范。对工程界来说，最关键的一句话是：模型选型应锚定与部署场景最相关的那个基准（客服看 τ-bench、写代码看 SWE-bench），而不是被综合榜的平均分带偏。

不足主要来自样本与生态层面。其一，15 个模型虽跨档位与供应商，但开放权重模型（Llama/Qwen/Mistral）覆盖不足，且并非每个模型都在每个基准上有分，需做 pairwise-complete 分析，最小配对仅 6 个样本、统计功效有限，τ-Airline 的相关尤其应谨慎解读。其二，分析用的是公开聚合分数而非逐题分数，聚合分无法把"题目难度、领域知识、scaffold、评估者差异、prompt 效应"从潜在能力中分离出来，因此相关只能约束、不能确认底层因子结构，确认需题目级因子分析。其三，各家评估协议异质（推理强度、扩展思考、用户模拟器、scaffold 不同），残留协议方差无法完全消除。其四，benchmark 选择未覆盖 GAIA、WebArena、OSWorld、BFCL（因当时 15 个模型里在它们上有可比分的太少），两簇结构在这些基准加入后是否存续仍是开放问题。总之，结论是"关于所选基准、模型、公开分数"的断言，而非关于 agent 能力的一般性断言，且是某一时点快照，会随新模型新榜单变化，需持续审计。

## 工业界落地可行性评估

落地性很强，且几乎零成本即可采用。企业在做模型选型或内部评测时，最该吸取的教训是：不要盲信综合榜单与单一聚合分，而要问"这个基准测的是不是我用到的那项能力"。论文的 D1–D5 可以直接作为评测设计的自检清单——要求内部 benchmark 显式写清构念定义、报告跨基准相关与排名反转率、按子任务而非总分汇报。对采购而言，一个具体可操作的动作是：为每个部署场景（客服、代码助手、数据分析）单独锁定最相关的基准，并把"排名画像跨度大"的模型视为高风险（因为它的能力不可泛化，今天在 A 场景好不等于在 B 场景好）。

更深一层的落地价值是"能力地图"（construct map）的构想：社区应逐步建立一张 agent 能力的分类学，明确不同部署场景各需要哪些不同能力，从而指导基准设计与选型。对评测平台方，论文呼吁把"单一复合排名"改成"按构念分列的多维画像"（类似智力测验同时报言语、数量、空间子分）。需要提醒的是，本文是审计而非提出新基准，它不改变任何模型能力本身；其结论的可重复性依赖于分数生态的持续发展，企业应把"构念效度审计"作为周期性动作，而非一次性的采购前检查。总体而言，这是一篇方法论贡献清晰、对产业选型有直接指导意义的短文，值得每个做 agent 评测与选型的团队当作必读。
