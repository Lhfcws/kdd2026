# Adaptive Decentralized Multi-LLM Orchestration with Accelerated Consensus-Based SPSA

## 背景与 Idea
LLM 驱动的智能体越来越多地不再以孤立模型形式部署，而是作为更大"agentic AI"系统的组件：系统中可能包含多个专门化的 LLM agent（负责不同类型任务）、路由/编排层（决定把任务派给谁）、外部工具、质量评估器，以及在线反馈环。这类系统的评估远比单模型在静态 benchmark 上的评估困难，因为观察到的最终行为不仅取决于单个模型输出的质量，还取决于"选了哪个 agent""如何处理延迟与成本""反馈如何被延迟""系统如何随时间自适应"。本文聚焦其中一类具体却长期被低估的难题：多 LLM 系统中的自适应在线路由（adaptive routing）难以被可靠、可复现地评估。所谓自适应路由，就是在任务在线到达时，仅凭历史与当前系统状态，决定把任务分派给哪个 LLM agent；不同路由策略会把同一任务发给不同模型，于是策略观察到的差异混杂了"路由决策本身的质量"与"模型生成、API 延迟/成本、LLM-as-judge 打分"这些随机性的随机扰动。若直接在线比较策略，就把策略优劣与这些随机噪声混在了一起。

LLM-as-judge（用另一个 LLM 当裁判近似质量信号）虽提供了可扩展的评分手段，但也引入了自身的偏置与不确定性，包括 judge 模型对不同模型的偏好、以及对提示词协议的敏感性。因此，评估一个自适应路由策略，不能只看任务级分数，还必须有一个能控制"每个策略可获得哪些潜在结果"的协议。本文把"如何可复现地评估自适应在线路由策略"作为一个 agentic AI 评估问题提出来，并给出其解法：replay-based 评估协议——固定任务流（the task stream，即依次到达的在线任务序列）与每个"任务–agent"对的潜在结果（potential outcomes，即把某任务发给某端点时可能得到的响应、延迟、成本、judge 分），使得所有被比较的策略都在完全相同的条件下运行，从而把策略/适应行为与随机 LLM 调用彻底分离。在该协议框架内，作者采用已有的分布式加速共识型 SPSA（A-SPSA）作为控制器在线参数的零阶优化器，而非提出新的优化算法。之所以选零阶分布式方法，是因为路由目标本身是黑盒、带噪声、且只能通过反馈观测的——这恰恰是零阶优化的天然用武之地。

本文把上述评估问题实例化在一个现成的"去中心化自适应多智能体路由架构"（文献 [25]）作为受控系统基座上，而非从零设计新系统；与 [25] 不同，本文的关注点是"在随机输出、部分可观测（partial observability，即每时刻只能看到历史与当前系统状态，未来到达、API 延迟、LLM 输出、质量值均未知）、延迟反馈（delayed feedback，任务完成后的质量信号往往滞后）与异构延迟—质量权衡下，如何可复现地评估自适应在线路由策略"。可复现性（reproducibility）是整篇的中心难点：在去中心化部署里，多个控制器各自基于局部历史做路由，若没有共享的潜在结果表，任何两策略的在线比较都会把"策略差异"与"各自碰巧抽到的随机 LLM/API 表现"搅在一起，结论无法归因。这也是为何论文把评估协议（而非新优化器）作为主干贡献——它先把"比较的条件"固定下来，再让各种自适应策略在该条件下公平竞争。

## 核心方法
系统由多个 LLM agent（记为集合 E）与多个控制器（记为 C）组成，是一个去中心化的多控制器路由架构：控制器负责估计每个任务的处理时间与可等待时间、定义内部截止时间（deadline），并按打分函数 score = wᵀf − κ₁·截止缺口 − κ₂·预算超支 来为每个到达任务选择最合适的 agent。这里 wᵀf 是效用项，κ₁/κ₂ 是惩罚系数，整体表达"在尽量命中截止时间与不超预算的前提下最大化路由效用"的权衡。

评估协议是整套方法的骨架。它先构造一张结果表 Y：在仿真模式下，Y 由带固定随机种子的 agent profile（每个端点的人工设计性能画像，含延迟分布、质量、成本）生成；在真实模式下，则预先收集并缓存每个任务发往各端点的实际响应、延迟、成本与 judge 分。回放时，被试策略按自身历史选择 agent，并直接查表取缓存结果作为反馈——由于所有策略共享同一张表，观察到的差异只能来自策略本身，而非随机生成或 API 行为。协议同时报告两类指标：操作类路由指标（如路由效用 Routing Objective、截止命中率 Deadline Hit Rate、成功率）与中间自适应指标（如预测损失、跨种子稳定性），从而把"策略最终表现"与"中间估计质量"分开度量。

A-SPSA 用于在线优化控制器的预测参数：θ⁽ᵖ⁾（处理时间预测）与 θ⁽ʷ⁾（等待预算预测）。SPSA（Simultaneous Perturbation Stochastic Approximation，同时扰动随机近似）是一种零阶梯度估计算法，它不要求路由目标有解析梯度，而是每轮用同一个随机扰动向量 Δ 同时扰动全部参数，再通过"扰动前/后"两点的反馈之差估计梯度方向，因而在黑盒、高维、噪声反馈下比逐维有限差分高效得多。A-SPSA 在 SPSA 之上叠加了两类机制：一是加速代理更新（accelerated surrogate updates），维护一个代理中心 z 与随轮次递减的步长序列 α_τ/γ_τ，使收敛具备动量式的加速；二是共识校正项（consensus correction），利用邻居控制器之间的参数差异做校正，让分布式各节点估计的参数逐渐拉向一致，避免单个节点被局部噪声带偏（所谓 consensus，即多个去中心节点通过邻居通信就某个量达成一致）。参数在滚动窗口上定期更新，形成"路由→反馈→窗口更新→A-SPSA 适应→下次路由"的闭环，闭环中参数的变化会直接影响路由打分与截止时间，从而体现自适应编排。作者把共识型 SPSA 及其加速变体，连同若干分布式零阶/原对偶基线（consensus-SPSA、KW/Kiefer-Wolfowitz、ZO-PGD、ZO-GT/零阶梯度跟踪、PD-2pt/两点原对偶、SP-GT）作为可比的"自适应路由策略"放在同一协议下比较，它们在这里只是被比较的行为对象，而非本文新提出的算法。这些基线分属不同家族：KW（Kiefer-Wolfowitz）是经典的逐维有限差分零阶方法，每轮需分别扰动每个参数，高维下样本代价高；ZO-PGD 是零阶投影梯度下降；ZO-GT 与 SP-GT 都引入梯度跟踪（gradient tracking），让各节点估计的梯度收敛到全局平均而非局部量，区别在 SP-GT 用 SPSA 式同时扰动而非逐维差分；PD-2pt 是两点原对偶（primal-dual）方法，兼顾约束与目标；consensus-SPSA 则是带共识项但未加速的 SPSA。把它们与 A-SPSA 同台，意义在于显示"加速 + 共识"两项叠加带来的相对收益，而非单比某一种优化器。

A-SPSA 的"加速"具体来自代理中心 z 与步长序列：每轮先用当前参数与代理中心之差做加速更新，再按随轮次递减的 α_τ（主步长）与 γ_τ（代理步长）把代理中心拉向新估计，这种"重球/动量"式结构使其在带噪声反馈下比朴素 SPSA 收敛更快、抖动更小；"共识"则体现为邻居控制器间定期交换参数、用参数差做校正项，使去中心各节点不被自身局部窗口的噪声带离群体解。参数在滚动窗口（rolling window，仿真中窗口 25、每 5 个任务更新一次）上累积观测后定期重估，形成"路由→反馈→窗口更新→A-SPSA 适应→下次路由"的闭环，闭环中参数变化会直接改变路由打分 wᵀf 与截止时间，从而体现自适应编排。协议同时报告两类指标：操作类（路由效用 Routing Objective、截止命中率 DHR、成功率）衡量最终表现，中间自适应类（处理时间/等待的预测损失、跨种子稳定性）衡量估计质量，二者分开报告正是为了能检验"中间损失低 ≠ 下游路由好"这一论点。

## Performance 概括
数值仿真（3 控制器、5 异构 agent、N=800、7 个 seed、每 5 个任务更新一次、滚动窗口 25）中，A-SPSA 在 Routing Objective、Deadline Hit Rate（DHR）中位数最高、Wait MSE 最低，其中 DHR 分离最明显；对比基线含 consensus-SPSA、KW、ZO-PGD、ZO-GT、PD-2pt、SP-GT。组件消融显示：无 surrogate 变体的中间 Wait MSE 更低却未转化为更优下游路由，固定加速系数同时损害操作指标与预测误差，印证"更低中间预测损失≠更好下游路由"。真实 LLM 端点（200 任务、两流 seed {11,42}、5 个 Groq 端点，API 延迟用受控样本替代）下，A-SPSA 的 Routing Objective 0.839、DHR 0.722、Wait MSE 0.162，均优于 ZO-GT/KW/PD-2pt 等，仅 SP-GT 明显落后；A-SPSA 初期有适应暂态，积累反馈后维持最高持续 DHR。

## 论文价值与不足
价值在于给出可复现的多 LLM 路由评估协议（共享执行缓存、固定潜在结果），把策略比较从随机噪声中剥离，并以 A-SPSA 在路由效用、截止命中、等待预测三者上取得最佳平衡，且贡献了"中间预测损失下降不等于下游路由更好"的反直觉评估洞见——这对所有用在线自适应控制器管理 LLM 编队的团队都有方法论意义（监控中间估计质量会误判最终路由质量）。不足：数值仿真依赖人工设计的 agent profile；真实实验仅 5 个 Groq 端点、2 条任务流、API 延迟用合成样本替代，未覆盖服务端拥塞/限流/失败；质量估计受 LLM judge 偏好影响；实验仅 3 控制器/5 agent，更大网络、更密通信图与异构模型池的可扩展性未研究；A-SPSA 共识项（式 4）假设同步通信，未含通信延迟项，物理分离部署时需延迟感知扩展；此外其结论建立在特定去中心化架构之上，对中心化路由器的直接适用性未讨论。一个值得点出的隐含前提是该协议需要"预收集或仿真每个任务—端点潜在结果"的缓存，这在端点数量巨大、或输出高度非平稳（如快速迭代的在线模型）时，缓存维护成本会上升，需在落地时权衡缓存刷新频率与评估结果的新鲜度。

## 工业界落地可行性评估
中等可行。replay 协议可直接用于路由策略的离线对比与回归测试——任何想在生产环境切换/调优 LLM 路由逻辑的团队，都可先把历史或合成的执行结果缓存成 Y 表，再在同一张表上比较新旧策略，避免被随机性误导；A-SPSA 适合作为在线路由控制器的参数优化器，且在真实生成内容上复现了数值优势；代码已开源（github.com/newpotatato/decentralized-llm-spsa）。但真实验证规模小、延迟为合成、且仅限同址低通信开销场景，工业落地前需在目标生产环境做更大规模、含真实延迟与跨供应商网络的验证，并为分布式部署补充延迟感知的共识项；此外 judge 偏差与任务域覆盖有限也需在落地时加以校准与扩展。对大多数公司的实际意义在于：先采纳 replay 评估思想（缓存潜在结果、同条件比较），再视网络拓扑决定是否使用共识型加速优化。即便最终不采用 A-SPSA，本文的评估协议本身也是可直接复用的资产——它把"路由策略比较"从玄学变成可复现实验，对任何用 LLM 编队、又苦于无法公平对比不同路由逻辑的团队都适用。
