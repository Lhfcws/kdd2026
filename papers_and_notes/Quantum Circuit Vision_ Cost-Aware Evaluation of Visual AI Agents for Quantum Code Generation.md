# Quantum Circuit Vision: Cost-Aware Evaluation of Visual AI Agents for Quantum Code Generation

## 背景与 Idea

量子算法在论文、教材与课程中普遍以电路图（quantum circuit diagram）形式传播：电路图由若干条水平导线（每条代表一个量子比特，qubit）以及从左到右排列的量子门（如 Hadamard 门、CNOT 受控非门、Toffoli 门等）组成，门的时间顺序固定为从左向右、没有反馈回路，且门符号遵循标准化约定（例如 H 表示 Hadamard、⊕ 表示 CNOT 目标位、• 表示控制位）。这种图形表达直观且符合领域惯例，但真正在量子计算机或模拟器上运行算法时，必须把它翻译成某个 SDK（软件开发工具包，即提供量子电路编程接口的 Python 库，例如 Amazon Braket、Qiskit、Cirq）的可执行代码。三大主流 SDK 的 API 风格互不相同，同一个电路在不同 SDK 中要写不同的代码；而长期以来每个发表在论文里的电路都得由研究者手工翻译——这一步既繁琐又易错，且需要同时具备"读懂图"和"熟悉特定 SDK 编程"两类能力，被视为量子软件工具链的核心瓶颈。论文把"从量子电路图视觉理解并生成经过验证的可执行代码"定义为 AI-for-Science 的基础性挑战，并类比 AlphaFold 用自动化取代了蛋白质结构预测中的人工劳动，设想可靠读取电路图并产出可验证代码的系统能加速量子算法研发与抗量子密码研究。

论文提出的 Quantum Circuit Vision (QCV) 是首个多模态、成本感知（cost-aware）的量子电路视觉评测框架。多模态（multimodal）指模型同时接收图像输入（电路图 PNG）与文本指令、输出代码，这类视觉 AI agent 通常基于多模态大语言模型（MLLM，即能处理图文两类输入的 LLM，例如 Claude 家族的视觉模型）。与只报告准确率的评测不同，cost-aware evaluation 同时记录每次调用的延迟、单次调用成本（论文用平台积分 "credits" 作为计费单位）以及路由策略的代价，回答"视觉 agent 能否读懂量子电路图并生成可验证代码、且成本几何"的问题。其关键创新是用单位矩阵保真度（unitary fidelity）作为不依赖 LLM 评判的客观 oracle（判定器）：把生成电路与真实电路各跑一遍，比较两者的完整幺正矩阵 U_gen 与 U_gt，保真度 F=|Tr(U_gt† U_gen)|/2n，F≥0.99 即判通过。该指标对全局相位不敏感（仅相差整体相位 e^{iθ} 的两电路仍得 F=1.0），且因验证了全部 2^n 个计算基态下的行为，比只在单一输入态上比较态矢量更严格，从而避免了用另一个 LLM 当裁判所带来的偏向与不稳定。

论文在引言中进一步论证了三个"为什么"。第一，为什么是量子电路而非经典电路：经典集成电路有逾五十年成熟的电子设计自动化（EDA，Electronic Design Automation）工具链，量子电路则完全没有，每一个电路都需手工设计、编码、验证；量子计算市场到 2040 年被估算达 4500–8500 亿美元规模，瓶颈不在硬件而在规模化设计算法的软件工具链。第二，为什么是"自主设计"而非仅"翻译"：从图到代码只是第一步，终极价值在于能发明新电路（更高效的分解、新纠错码、更优变分线路）。第三，为什么需要成本感知评测：据作者所知，此前没有任何工作在科学图理解任务上联合评估准确率、延迟与成本；而 agent 规模部署要求使用者在预算与质量之间做出匹配选择，框架必须能给出"选哪一档模型"的依据。论文还把 2025 年称为"量子拐点"——诺贝尔物理学奖授予超导量子比特实验、图灵奖表彰量子信息论基础、联合国宣布 2025 年为国际量子科学技术年——以此说明评测基础设施的紧迫性。QCV 因此被定位为通往"自主量子电路设计"三级路线（Level 1 理解+代码生成、Level 2 优化、Level 3 发明）的第一级基础设施。

## 核心方法

QCV-Dataset 含 132 个电路、覆盖 13 个类别、量子比特数 1–10。每个电路配五种核心模态（modality，即不同形式的数据）：电路 PNG 图、Amazon Braket SDK 可执行代码、Qiskit 可执行代码、仿真结果（LocalSimulator 跑出的态矢量，存为 JSON）、双语（英/中）结构化标注；另含两类补充模态：自然语言目标描述（用于电路合成任务）与优化等价对（optimization equivalence pairs，记录电路间的等价关系）。13 个类别包括基础门（5，如 Hadamard、Bell、Toffoli）、中级算法（10，如 QFT、Grover、量子隐形传态、Deutsch）、高级算法（6，如 QAOA、VQE、Bernstein-Vazirani）、区块链协议（11，如 BB84、VRF、共识）、门类型覆盖（15）、量子比特扩展 4–10q（12）、经典算法（15，如 Shor、Simon）、变分电路（10）、纠错码（8，如 Shor-9、Steane-7、表面码）、量子机器学习（10）、区块链扩展（8）、视觉变体（10，测布局鲁棒性）、BTC/区块链量子安全（12）。电路图全部由 Qiskit 的 matplotlib 绘图器程序化生成，以保证可复现且无歧义；真实标注同时提供 Braket 与 Qiskit 两份实现。用于统计显著性检验的核心子集由前三类（基础/中级/高级）共 21 个电路构成，做 n=5 重复试验；其余 111 个电路为 n=1 的指示性结果。

评估采用两种视觉提示模式，均改编自 VGV（Verilog Generation via Vision，一项用 MLLM 从经典电路图生成 Verilog 硬件描述语言代码的工作，并首次提出 Thinking Vision 提示）：Basic Vision (BV) 直接给出"请基于该量子电路图生成 Amazon Braket SDK Python 代码"的指令；Thinking Vision (TV) 先让模型做链式思考（chain-of-thought，逐步分析量子比特数、门序列、控制关系），再生成代码。在 VGV 中 TV 曾把开源模型性能提升最多 50 个百分点，但 QCV 固定每种模式只用单一提示，以隔离"链式推理"与"提示信息量"两个变量。论文还指出量子电路之所以比经典电路更适合视觉代码生成，是因为它有标准化门符号、严格从左到右的时间结构、有限门词汇表——这些性质是经典微架构图所缺乏的，因此 QCV 基线准确率（78–91%）高于 VGV 的 40–60%。

验证走三级流水线：① 语法检查，用 Python 的 compile() 检测语法错误；② 执行检查，在带标准导入（math、numpy）的沙箱命名空间中运行代码，确认产出一个合法的 Braket Circuit 对象且无运行时异常（例如调用不存在的 .crz()、.toffoli() 这类错误 SDK 方言会在此暴露）；③ 单位矩阵保真度检查，通过 Amazon Braket 的 LocalSimulator（免费本地态矢量模拟器，shots=0）把 2^n 个计算基态逐一跑过生成电路与真实电路，得到各自的 d×d（d=2^n）幺正矩阵后算 F=|Tr(U_gt† U_gen)|/2n，F≥0.99 判通过。该 oracle 对全局相位不敏感，且因同时验证全部输入态，比单输入态矢量比较更严格；阈值敏感性分析显示 F≥0.95 与 F≥0.99 通过率完全相同，保真度分布呈双峰（要么几乎完美 F>0.999，要么明显错误 F<0.95），说明 0.99 阈值稳健。

实验固定 Claude 家族三档能力—成本层级，经 kiro-cli 统一以非交互模式调用，以保证执行条件一致：Haiku 4.5（最轻量，0.40 cr/次）、Sonnet 4.6（中档，1.30 cr/次）、Opus 4.6（最强，2.20 cr/次）。总调用量 132 电路 × 3 模型 × 2 模式 = 792 次；核心 21 电路子集在 BV/TV 下做 n=5 重复，并用配对 t 检验比较各模型/模式差异，外加 TOST（two-one-sided-tests，双单侧检验）等价检验确认 TV 与 BV 是否在 ±10pp 内等价；全 132 电路为 n=1。每次调用的平台积分、延迟（3.7s/6.0s/24.4s 分别对应三档）、保真度均被记录用于成本分析。论文还提出 Haiku→Sonnet→Opus 的级联路由（cascade routing，受 FrugalGPT 启发：把查询按难度依次路由到由廉价到昂贵的模型）策略，并贡献了 268 个带标注的失败案例（覆盖语法错误、执行错误、低保真输出三类），用于错误分析与生产监控。数据集按 FAIR（可发现、可访问、可互操作、可复用）与 CARE（集体利益、控制权、责任、伦理）两套治理原则发布：提供 Hugging Face Dataset Card（YAML）、Croissant JSON-LD（机器可读知识图谱元数据，被 Google Dataset Search、Kaggle、OpenML 采用）、Croissant-RAI（扩展 MLCommons RAI 词表记录 provenance、局限与偏差，如 23.5% 电路与区块链相关可能偏向密码应用）三层治理元数据，并遵循 Datasheets for Datasets 标准撰写文档；数据集以 Apache Parquet 格式上传，含电路图以 Image() 特征内嵌以便浏览器交互预览，共 132 电路、1,931 文件，分为 circuits/experiments/failures/equivalences 四种配置。

## Performance 概括

核心子集（n=5，BV）上 Sonnet 4.6 最准且最稳（91.4%±5.2%），Opus 4.6 次之（85.7%±5.8%），Haiku 仅 48.6%±4.0%；Sonnet–Opus 的 +5.7pp 差异不显著（配对 t p=0.083），而 Sonnet 单次成本仅为 Opus 的 18%（1.30 vs 2.20 cr/call）。全 132 电路（n=1）总体通过率 Opus 78%、Sonnet 77%、Haiku 43%，基础电路多数模型 80–100%，复杂算法/密码协议降到 41–87%，18 个电路所有模型均失败（Shor、表面码、BTC 安全协议等结构不规则者）。链式思考 (TV) 对任意模型均无统计显著效果（all p>0.18，n=5）；逻辑回归确认电路深度（p<0.001）而非量子比特数（p=0.20）是理解难度主预测因子。成本上 Haiku→Sonnet 边际成本 0.002 cr/pp（极划算），Sonnet→Opus 达 0.508 cr/pp（254× 边际）；级联路由以 30.9 积分（Opus 单独成本的 38%）取得 84% 通过率。与人工翻译（估 $50–200/电路）相比，最贵模型约 $0.78/电路，降本 >100×。

## 论文价值与不足

价值方面，论文首次把"多模态视觉→可验证量子代码"做成带客观 oracle、成本感知、且统计严谨（n=5 重复 + 配对 t 检验 + TOST 等价检验）的完整评测基础设施。在数据集层面，它填补了量子电路领域长期缺乏标准化大规模、可共享基准的空白——此前 NTangled、QDataSet、MNISQ、VQE-Generated 等量子数据集或侧重量子态本身、或侧重小系统的物理动力学，而视觉到代码基准（VGV、MMCode、Plot2Code、ChartCoder、CODE-VISION）根本不含量子电路数据；QCV-Dataset 是首个同时提供机器可读引用（CITATION.cff）、Datasheets 文档与版本化可复现三者结合，并配 FAIR/CARE 治理元数据、Croissant-RAI 的开放数据集（Hugging Face 上 132 电路、1,931 文件）。其"结构复杂度而非量子比特数决定成败""CoT 无效""模型路由胜过提示工程"等发现对科学图理解的 agent 评测具普适启发，可推广到化学结构、生物通路、工程 schematic 等任何带可验证真值的科学图领域。

不足方面：(1) 仅测 Claude 家族三档（固定厂商以隔离能力—成本档效应），未覆盖 GPT-4o/Gemini/Qwen-VL 等跨厂商；论文说明其流水线模型无关，任何具图像输入与代码输出的模型都可接入，但跨厂商实证为未来工作。(2) 电路图均由 Qiskit matplotlib 渲染，未测 TikZ、Quirk、手绘等真实异质渲染；虽 Visual Variants 类别（H）测了布局鲁棒性（强模型 90–100% 通过），但跨渲染器的全面异质性测试仍缺失。(3) 端到端验证仅经 Braket 包装，单位保真度 oracle 本身不限定于 Braket（只要 SDK 能暴露态矢量或幺正矩阵即可），但跨 SDK（Qiskit Aer/Cirq/PennyLane）实证验证为未来工作；数据集已带 Qiskit 真值。(4) 全 132 电路与成本/级联结论为 n=1，统计显著声明仅限于核心子集；论文显式指出 run-to-run 方差达 ±4–9pp，单轮评测会误导。(5) 仅处 Level 1（理解+代码生成），优化与发明层未实证；Level 2/3 所需等价对与目标描述虽已随数据集发布，但闭环设计—验证—精化系统仅为提案（Hybrid Agent 架构，附录 D）。(6) 失败分类 268 例虽丰富，但对失败模式的细粒度归因（如 Opus 偏低保真、Haiku 偏视觉误读）只作现象描述，未给出可操作的修复建议，且 gate 失败的因果（例如 Opus 的低保真是门参数错误还是门序错误）未进一步细分。

## 工业界落地可行性评估

该框架对量子计算研发辅助、量子密码/区块链安全、以及更广的科学图理解 agent 部署均有明确落地场景。其级联路由（廉价→昂贵模型）与边际收益分析可直接用于成本敏感的批量电路翻译任务：论文给出 Haiku 先跑全部 132 电路（43% 通过、4.1 积分）→ Sonnet 重跑失败 75 个（救回 60%、8.3 积分）→ Opus 重跑剩余 30 个（救回 33%、18.5 积分），总成本 30.9 积分取得 84% 通过率，仅为 Opus 单独跑完全部成本 81.6 积分的 38%；人工+AI 混合流程把单电路成本从约 $100 降到 $23，使大规模电路翻译首次具备经济可行性。单位保真度 oracle 提供的客观验收标准也适合嵌入 CI/CD 做自动验证，作为电路代码合并前的门禁。论文在量子安全区块链的专项案例研究中也发现，Sonnet+BV（9/11）在含并行门层的电路上优于 Opus BV（7/11），说明中档模型可避免"过度分析"错误。

但当前落地前需跨三道门槛：扩展跨厂商模型、真实电路图样式与跨 SDK 验证，并优先在"人工校验兜底"的人机协同工作流中试点，而非完全自动化可信发布。具体而言，(1) 模型覆盖：近地板模型（如 gpt-4.1-mini）在该任务上无信号可搜（论文同类实验 +0.00），落地需先确认评估器本身足够强；(2) 视觉多样性：产线中的电路图常来自不同绘图工具或扫描件，与 Qiskit matplotlib 风格差异大，需做分布适应性测试，且 Oracle 仅经 Braket 包装，若下游用 Qiskit Aer 而非 Braket 需补一层执行包装；(3) 成本口径：论文以"平台积分"计成本，企业自有网关的计费单位不同，迁移时需重测边际成本曲线。总体而言，作为"辅助人类 + 自动验收"的半自动管线最具近期可行性，全自动可信发布仍需等待 Level 2/3 与跨厂商、跨 SDK 实证。
