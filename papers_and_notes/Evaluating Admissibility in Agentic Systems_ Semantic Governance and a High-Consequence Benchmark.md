# Evaluating Admissibility in Agentic Systems: Semantic Governance and a High-Consequence Benchmark

## 背景与 Idea
可信 agent 的输出可能流畅、合理却不适合执行。在高风险工作流里，一个被提议的动作是否“可准入（admissible）”不应只看它是否似真、是否符合任务准确率，而要看它是否有受治理的理由依据、权威支持与可回放的决策基础。这里的 admissibility（准入性）是论文自创的核心术语：它指的不是“模型内部对齐得不好”，而是“在治理层面，这个动作凭什么被允许执行”。企业执行控制无法靠直接检查或认证模型的内部状态来保障，因此治理必须从“声称内部对齐”转向对外部可观测行动基础（证据、权威、策略兼容、可解释、可回放、可问责干预）的检查。论文指出现有可信/可靠 agent 研究通常停在“输出好不好/安不安全”，而没有回答“该动作在治理上是否被允许执行”，并将其正式定义为一个动作级控制问题。

论文把基准实例化为 REA（资源-事件-主体）事实到日记账分录（journal entry, JE）的记账任务。REA 是会计学里一种结构化本体：把经济现象建模为资源（resource）、事件（event）、主体（agent）三类对象及其双重记账关系，用来规范一笔业务应该如何进入账簿；journal entry 则是具体的借/贷过账。选会计域的动机是：它够紧凑、又能同时暴露三类治理难点——分类歧义（一笔业务应记入哪个科目）、策略冲突（在什么规则下该动作被禁止）、以及可审计要求（每一步都要能追溯）。会计因此成为“合理投影”与“可审查、可回放决策基础”之间差距的高后果压测域，而不是论文的主概念贡献本身。论文把自己定位为“先是一个 agent 评估与治理贡献，其次才是一个高后果会计压测”，因此 54 例（24 合成 + 30 公开来源）结果只是定钉条件下的框架级干预证据，而非部署可靠性的统计估计。

相关工作定位上，Constitutional AI 把无危害约束形式化在 LLM 输出上，instruction-hierarchy 研究冲突指令下的权威优先，但二者都不指定用于审计决策的回放基础（replay basis）或不可解情形下的升级路径。语义网/知识图谱/神经符号工作提供机器可解释约束，却把 grounding 当作表征或推理问题而非治理问题。论文第 6.1 节还归纳了四类反复出现的失效模式来论证治理必要性：缺乏证据血缘的“似真但未充分论证”过账、数值平衡但语义错误的过账、破坏回放一致性的不稳定上下文，以及暴露延迟不一致的长程漂移。其更广义的 agentic 工作流模式是：证据摄入 → 投影 → 动作提议 → 受治理的执行决策；会计只是实例化环境。论文归纳的四类失效模式值得展开：一是“似真但未充分论证”的过账——分录借贷平衡、读来合理，却缺少支撑它的证据血缘；二是数值平衡但语义错误的过账——账户与金额对得上，但经济含义错（如把费用记成资产）；三是破坏回放一致性的不稳定上下文——同一输入在不同时刻给出不同决策基础；四是长程漂移——随对话或任务推进，决策逐渐偏离初始策略。这四类都属“输出流畅却不可准入”，正是为何仅看任务准确率会漏掉负例，也说明治理必须从外部可观测的决策基础入手，而非信任模型内部状态。

## 核心方法
论文提出语义治理模型与执行规则骨架：Execute(a_t) 仅在 Justification 有效、Authority 批准、Replayable 三者同时满足时放行，即 Execute(a_t) ⟺ Valid(J_t) ∧ Approved(I_t) ∧ Replayable(I_t)。核心对象包括 Admitted Facts → Governed Projections → Execution Intents，由 Justification Artifacts（满足治理准入检查的理由包）与 Replay Bindings（内容寻址的证据哈希、治理规则 id、权威上下文 id 打包成的定钉决策包，可日后重建同一决策基础）把投影过渡到准入。控制边界分三层：Fact Admission 只接受已验证事实；Projection Trust 评估投影是否满足准入标准；Execution Admissibility 决定意图是否获准执行。

治理路径（Semantier）在直接 LLM 投影前插入四道门：Gate 1 结构化 REA 校验（守恒与资源完整性），拦截畸形投影并触发纠正（AWC）；Gate 2 分层证据门（缺失治理产物时升级 ESC）；Gate 3 策略与决议门（基于优先图与活动策略包，命中冲突时阻断 BLK/FPRR）；Gate 4 回放绑定校验（依赖产物版本定钉，识别决策基础漂移）。每起一次门所对应的目标 unsafe-allow 类与 Table 6 组件归因表一一对应。基准包含 6 类场景（positive/correctable-negative/evidence-gap/policy-conflict/projection-rejection/replay），5 个 gold 标签：ALW（允许）、AWC（纠正后允许）、ESC（证据不足需升级）、BLK（策略冲突须阻断）、FPRR（事实保留、投影被拒）。决策流先判证据是否充分，不足转 ESC；再判策略冲突，命中转 BLK；可纠正误投影转 AWC；下游被拒不留尾迹转 FPRR。

评测维度含结果控制（记账正确性、unsafe-allow 率、纠正精度、正当阻断率）与解释质量。后者具体覆盖证据可追溯、理由可追溯、决策轨迹清晰度、纠正透明度、升级有用性、回放一致性与决策前理由覆盖；其中回放一致性用稳定决策基础身份（标签+被引产物集+策略与规则 id）而非逐字输出，决策前理由覆盖只奖励属于决策基础、在结果之前已存在的产物，而非事后补写的理由。记账正确性按规范化的过账元组多重集 {account, side, amount, currency}（行序不变、别名归一）计算。为保持可复现，模型定钉为 openai:gpt-5.5（2026-05-13）、temperature 0、固定 prompt hash、每案例 5 次种子试验，模型与基线制品记录在 benchmark/v2/baselines/ 清单下；并邀请两位独立会计领域人类评审员用冻结 rubric 对 30 例公开来源包做双评裁定，另以冻结的 4 例子集（v2-heldout-2026-05-14）作 sanity check。需要强调：Table 2 中的各项阈值只是面向更大规模后续评估的“建议报告目标”，应配合敏感性分析解读，而非已验证的截断点。

## Performance 概括
在冻结条件下对比 permissive direct、cautious、governed 三条路径。24 例合成包的整体记账正确率为 8/24（0.33，direct）、12/24（0.50，cautious）、24/24（1.00，governed），整体 unsafe-allow 率分别为 0.67、0.50、0.00。30 例公开来源派生基准（来自 Zenodo、PCAOB、SEC EDGAR XBRL 制品）上，unsafe-allow 计数为 14/30（direct）、7/30（cautious）、0/30（governed），对应记账正确性为 8/30、15/30、30/30；谨慎基线在 evidence-gap 类有改善，但在 correctable 误分类与 policy-conflict 类仍不如治理路径的干预分离清晰。外部独立双人评分对 30 例结果标签达成 30/30 一致（Cohen's κ=1.00），次级字段一致性较低（纠正充分性与解释依据 76.7%，证据充分性 90.0%，策略冲突存在性 100.0%）。结果应读作“定钉条件下治理协议的受控证据”，而非跨会计或 agent 决策领域的泛化优势。

## 论文价值与不足
价值在于把“是否允许执行”从模糊的对齐目标变成可度量、可回放、可审计的评估对象，并用冻结制品、外部双人裁定、组件归因表把治理路径与直接基线在干预行为上做了清晰区分，方法学上对高风险 agent 执行控制有直接参考意义。论文明确区分“框架验证”（治理路径在定钉条件下产出比直接基线更受限的干预行为）与“基准验证”（还需独立裁定标签、更强基线多样性、保留评估与更广外部证据）——本文主要解决前者、仅部分解决后者，这一声明边界对其他高风险 agent 评测也值得借鉴。不足在于：24 例合成包为作者自造，存在把期望答案编码进基准的循环风险；30 例公开来源包的案例包、JE 金标与治理标签仍属作者标注，外部制品只提供字段与缺陷模式；direct/cautious 基线是有意收窄的比较族而非完整基线套件，故属受控干预研究强、前沿模型性能声明弱；每门控贡献的 hold-out 消融（依次禁用各门测 unsafe-allow 变化）虽在架构上可行，但被列为计划中下一步、当前只把结果差异归因于治理路径整体；生命周期回归监控虽为协议设计但本次未经验证。整体结论是“受控证据”而非统计泛化。另有两点边界：一是 24 例合成包为作者自造，存在把期望答案编码进基准的循环风险，尽管 30 例公开来源包由外部制品派生，但其金标与治理标签仍属作者标注；二是 direct/cautious 基线是有意收窄的比较族，目的是凸显治理路径的干预分离，而非提供完整前沿模型性能基准。因此本文更应读作“在定钉条件下，受治理路径相对于宽松基线的行为差异”的证据，而非“受治理路径优于所有方法的统计结论”。每门控贡献的 hold-out 消融虽在架构上可行，但被列为下一步，当前只把差异归因于治理路径整体，未能把 unsafe-allow 的下降逐门分配到具体门控。

## 工业界落地可行性评估
该框架对会计、审计、金融等高后果、强监管的动作级执行控制有明确落地场景：其四门控架构（结构 REA 校验、分层证据门、策略与决议门、回放绑定校验）可直接嵌入企业 agent 的“allow/correct/escalate/block”决策流，与 model cards / datasheets 的可追溯理念一致，适合作为上线前的治理闸门与人机协同升级点，并可与 OpenTelemetry、in-toto/SLSA 来源追踪对接。落地时还应借重论文已采用的外部双评裁定机制来提升基准可检视性：30 例公开来源包由两位独立会计领域人类评审员用冻结 rubric 裁定，结果标签 30/30 一致（κ=1.00），次级字段一致性较低反而成为更有诊断价值的信息，因为更细粒度的定性判断本就比粗标签更难。但落地需注意：治理质量仍依赖策略质量本身，回放问责不能替代人工策略设计；治理会引入审查与运营开销，在部分环境可能不可接受；当前仅在小规模冻结切片验证、基线族刻意收窄，故工业部署应扩展真实工作流轨迹、补齐逐门控消融与生命周期回归监控后，再将其作为生产治理层而非性能认证依据。论文自己强调，54 例结果是在定钉模型、基准、策略条件下的框架级干预证据，不是部署可靠性的统计估计。具体落地时，该框架最适合作为“上线前的治理闸门”与人机协同升级点，而非替代业务系统的自动执行层：当证据不足时转 ESC 升级给人类、当策略冲突时 BLK 阻断，这类干预分离让企业能把不可信动作拦在出错之前。但治理会引入审查与运营开销，在需要低延迟的实时场景可能不可接受，应按动作风险级别决定哪些走全自动、哪些必须人工确认。此外，治理质量上限由策略与证据质量本身决定——回放问责能追溯“决策依据是否一致”，却无法替企业设计正确的策略；因此部署时应配套人工策略设计与定期策略复审，并把论文未经验证的生命周期回归监控补上，再将其作为生产治理层而非性能认证依据。
