# DutyFormer: Neural-Symbolic Prediction of Silent Obligation Omissions in AI-Agent Process Traces

## 背景与 Idea

现代 AI agent 越来越多地被部署在流程化、高风险的关键业务里，例如贷款审批、临床分诊、监管合规审查、客服工单处理等。这类系统的工作方式是一连串多步骤的"流程轨迹"（process trace）：先观察状态，再调用工具，检查工具输出，决定是否需要向上级审批，最后产生动作。在这样一个长链条里，存在一类容易被忽视却危害很大的失败模式，作者称之为"沉默义务遗漏"（silent obligation omission）。所谓"义务"（obligation），是指流程中某个被规则要求必须执行的步骤，常见形式包括：执行一次核验（verification）、获得一次审批（approval）、给出引用出处（citation）、发起升级上报（escalation）、或在最终动作之前把证据记入日志（recording）。当 agent 在某个截止期限之前悄悄跳过了这些本应完成的义务步骤，且没有触发任何显式异常或报错，就发生了沉默义务遗漏。典型的例子有：在工具返回结果之后没有做核验就继续推进；在会产生副作用的调用之前省略了本应有的审批；在给出最终答复之前没有把证据落库。它与"显性错误"的关键区别在于：显性错误会抛出异常或被用户立即投诉，而沉默义务遗漏不报错、不被即时发现，往往要等到一次审计或下游事故爆发时才暴露出来，因而在合规与流程治理中极具隐蔽性。

论文把这个问题放到"义务逻辑"（deontic logic，研究应当、允许、禁止等规范概念的形式逻辑）的框架下理解。作者指出，现有两类方法都无法直接解决这个问题。其一是"预测性流程监控"（Predictive Process Monitoring，PPM）：它在无约束的活动序列上预测流程最终结果或下一个事件，但并不显式建模"哪些义务被触发了、还剩多少截止时间余量、若违约会有多严重"。其二是"一致性检验"（conformance checking）：它把观察到的轨迹和一个参考流程模型（如 Petri 网）做对齐，检测已经发生的违反，本质上是事后诊断，不能对未来轨迹后缀给出前瞻性的风险分数。社区真正缺的是一类"在线监视器"：它把前缀可观测的义务状态，转化为可校准的、能在 agent 执行循环内部使用的在线风险估计。具体而言，给定已观测到的流程前缀 τ(k)=⟨e1,…,ek⟩ 和一组领域义务，DutyFormer 要预测"一个已被触发的义务，是否会在整个轨迹结束之前、越过其截止期限后仍未被满足"，也就是判定该义务是否会最终变成 violated 状态。论文的黄金标签是通过把一个正式的义务引擎（以 DECLARE 风格的响应约束 compiled 到 Time Petri Nets 上）在整条完整轨迹上回放（replay）而确定性地计算出来的，再把终态的 Violated 反向传播到每一个前缀。这里一个关键设定是：运行时只暴露"前缀可观测"的一致性状态，模型必须在不完整观测下做预测，这正是该问题的难处。

本文的"Neural-Symbolic"（神经符号）指将神经网络与符号逻辑两类范式融合：神经网络负责从大量轨迹数据中学习时序模式，符号部分负责把由 DECLARE/Time Petri Nets 表达的形式化义务约束作为结构化先验注入模型。DutyFormer 的价值，正是在于它把"语义义务"（符号规则）与"神经序列建模"结合，而不是像纯过程挖掘那样只做统计分析，也不是像纯大模型那样只凭文本推断。

## 核心方法

DutyFormer 的核心是一个以 Transformer 编码器为骨架的在线监视器，输入是一条被分词的活动前缀，同时拼接连续的两两事件间隔、领域标识、每个 token 所属的义务族（obligation-family）标注，以及一个四维的符号一致性向量 s_k。这个 s_k 是整篇方法的关键符号信号，它来自把前缀 τ(k) 在一组义务 Time Petri Nets 上回放后提取出的"前缀可观测状态"，四个维度分别是：是否存在任何待办义务（pending>0）、是否已有违反（violated>0）、剩余最小截止时间余量 δ_min、以及归一化的累计一致性代价 c_k。需要强调的是，s_k 只反映"当前还挂着哪些义务"，而大多数待办义务最终会在截止前被满足，因此模型真正要学的是"在当前前缀下，这条轨迹后缀会把义务引向满足还是违反"。

方法最大的创新点叫 SAB（Symbolic-Attention-Bias，符号注意力偏置）。它的核心思想不是把符号状态当作又一个输入特征拼接进去，而是直接去调制 Transformer 每一层的注意力计算本身。在标准注意力里，query i 与 key j 的缩放点积分数会被 softmax 归一；SAB 给每个注意力头、每一层额外加一个由 s_k 派生的加性符号偏置 β。具体地，每个头有一个可学习的投影 W_sab，把 s_k 映射成该头的标量符号信号 β∈[−1,+1]（用 tanh 把范围限制在正负一之间，保证加性项不会破坏注意力 logits 的数值范围）；再配合一个"键位置义务掩码" m_j：只有当 key 位置 j 带有活着（live）的义务族标签时 m_j=1，否则为 0。于是 SAB 的偏置张量只作用到"义务相关的 key 列"上，对其它列完全不动。

为什么必须用"键选择性"（key-gating）而不是直接加一个对所有 (i,j) 都相同的标量？论文给出了解释：如果给每个注意力分数都加一个位置不变（position-invariant）的常数，行向 softmax 会把它吸收掉，注意力权重分布完全不变，等于没加；而键门控打破了这种不变性——因为偏置 β·m_j 在同一行内随 key 位置 j 不同而变化，softmax 就会按 β 的正负，把质量重新分配到（或远离）承载义务的 key 上去。换句话说，符号状态 s_k 由此获得了"逐层、逐头、针对义务关键位置"的控制力，却不需要拉长序列、也不引入新 token。与之相比，把 s_k 只拼在池化表示上、或当作一个额外 token 注入，都只能在表示层给模型访问一致性状态的机会，却不能在每一层对义务承载位置做注意力上的条件化。

在得到编码器表示后，DutyFormer 接出多任务输出头（multi-task output）：遗漏概率头（sigmoid 输出，配合 focal loss 处理类别极不平衡）、必需动作族分类头（cross-entropy）、以及违反严重度回归头。这些辅助头不只是为了多任务本身，更充当表示正则化器——在触发刚刚发生、前缀还很短的时候，迫使编码器在内部维持一份义务状态估计。论文还用一个 split conformal prediction（分裂式保角预测）wrapper 把遗漏概率转换成一组"分布无关的预测集合"，提供有限样本下的覆盖保证（实测 90% 覆盖），这是所有对比基线都不具备的性质。此外模型还联合训练了一个离散时间生存头（用于估计"距离违约还有多久"），权重 λ_tte=0.3，但作者明确指出该头在当前 checkpoint 下塌缩成近似常数风险，因此不宣称任何 time-to-violation 结果。

与 DutyFormer 对比的基线覆盖了多类范式：纯序列的 N-gram、过程挖掘里的 DA-LSTM、强序列模型 RoBERTa-PM、以及直接吃一致性特征的表格模型 XGBoost / Logistic Regression。这一点很重要，因为本文处在"高信息 regime"——运行时有形式化一致性状态可用，所以像 XGBoost 这样只吃一致性特征的表格模型也能非常强，AUROC 会直接饱和到 ≥0.999；因此论文刻意不把判别力（AUROC）当主指标，而改用义务专属的遗漏率、校准、消融与可部署性来衡量。

## Performance 概括

在遗漏误报率 OMR（Obligation Miss Rate，真实有义务却没被标记的比例）上，DutyFormer 为 0.95×10⁻⁴，显著优于 RoBERTa-PM 的 9.70×10⁻⁴（约 10 倍优），也把纯序列 N-gram（182×10⁻⁴）远远甩开。消融实验清晰区分了两个组件的作用：移除 SAB 后 OMR 翻倍到 1.91（2×）；而移除符号一致性向量后 OMR 升到 54.4，约为完整模型的 57 倍，说明符号注意力与显式一致性状态是互补的两件事。conformal coverage 达到 90%（未校准 ECE 为 0.0193，用温度缩放 T=0.25 后降到 0.0017，Brier 分数 0.0016）。在跨域泛化 LODO（leave-one-domain-out，留一域外出）设定下，DutyFormer 的 TSuC（Task Success under Compliance，同时任务成功且不违约的比例）降到 0.7791，相比域内接近 1.0 有约 0.22 的明显下降，跨域脆弱性主要来自固定活动词表带来的词表漂移（out-of-vocabulary），而非 SAB 本身。外部验证方面，在 τ-bench（工具调用 agent 基准，airline 与 retail）的轨迹上，DutyFormer 的 OMR 为 0.07（原生单位 0.007），说明把"义务监视"这一形式化思路迁移到工具调用 agent 轨迹上同样成立。

## 论文价值与不足

价值在于：它首次把"沉默义务遗漏"这个被长期忽视的 agent 失败模式，形式化为一个建立在义务逻辑之上的结构化在线预测问题，并给出带前缀级标注协议的完整定义；更关键的是，它用 SAB 实现了"符号状态逐层注入注意力"的轻量机制，并配齐了在线监督层真正需要的工程属性——温度缩放校准、分裂式保角覆盖、动作族路由、严重度分级，且全部是第一等公民输出而非外挂 wrapper。在义务稠密（conformance-rich）的设定里，DutyFormer 与最强表格/序列基线在原始遗漏率上持平，却额外提供了可校准、带覆盖保证、对符号状态腐蚀鲁棒的监视能力，组合上无基线可比。

不足与局限也较明确。其一，跨域泛化有明显下降：DutyFormer 固定活动词表对未见活动映射成词表外嵌入，而词表无关的一致性特征迁移良好，这说明跨域缺口是词编码器问题而非 SAB 问题，作者把"换成词表无关编码器（字节/子词级或义务族派生嵌入）"列为最高优先级后续工作。其二，τ-bench 是公开基准派生的 agent 轨迹，并非生产级企业日志，外部验证证的是"形式化是否成立"，不等于在 LangGraph、浏览器 agent 或企业 RPA 真实日志上的部署证据。其三，时间到违约（time-to-violation）估计仍是探索性的，生存头塌缩成常数风险，论文明确不做此宣称。其四，义务目前只能表达为 DECLARE 响应约束，更丰富的时间模态（义务间的前序依赖、数据条件豁免、嵌套截止）尚未覆盖。其五，义务标注由每个域单一分析师按书面协议完成，缺少多标注者一致性研究和标签对齐，属于已知的范围限制。

## 工业界落地可行性评估

落地路径清晰且价值高。DutyFormer 最直接的落点是合规审查、流程审计与 RPA/agent 监控系统：它在 agent 执行循环内部就能对每个"该做却被跳过"的义务步骤给出前瞻风险分，对贷款审批漏审批、临床分诊漏核验、客服漏记录这类风险有实际预警意义。其保角覆盖保证便于在强监管场景做风险预算——运维可以给定一个覆盖率目标，由 split-conformal wrapper 自动挑出落在"零误报带"内的工作点，使监视器成为一个可调风险姿态、带有限样本覆盖保证的在线监督层。从工程角度看，它不要求替换现有 agent，而是作为一个旁路监视器读取前缀与义务状态即可，接入成本相对低。

需要正视的落地障碍有三点。第一，它依赖"用正式义务引擎对流程回放以生成标签"这一前提，意味着企业要先把本领域的义务规则写成 DECLARE/Time Petri Net 形式，并维护一个运行期一致性状态提取器，这是明显的领域知识与工程门槛。第二，跨域脆弱性提示：若直接把一个在 A 流程训好的 DutyFormer 零样本用到 B 流程（尤其活动词表不同），性能会显著掉，需针对目标域重新训练或换用词表无关编码器。第三，真实生产日志的覆盖域仍有限，论文只在四个真实流程日志域（Incident Response、Loan Approval、Road Traffic、Sepsis）与 τ-bench 上验证，工业界在引入前应做自有流程日志的小规模 pilot，并以 D1–D5 类似的建设性清单自检标注质量。总体而言，这是一篇"方法扎实、框架完整、可立刻试点"的 workshop 工作，适合作为高风险流程 agent 的可观测性与合规基础设施组件。
