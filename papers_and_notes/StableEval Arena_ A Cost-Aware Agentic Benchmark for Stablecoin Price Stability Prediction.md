# StableEval Arena: A Cost-Aware Agentic Benchmark for Stablecoin Price Stability Prediction

## 背景与 Idea
稳定币（stablecoin）是交易、借贷、支付、抵押、流动性与结算等数字金融基础设施，其效用建立在“脆弱的承诺”之上：一个锚定一美元的稳定币应当始终贴近一美元。一旦承诺弱化，应用层就会面临定价错误、流动性压力、支付失败与结算不确定性。稳定币风险监测关心的不是“近期价格是否贴近面值”，而是“其锚定是否由在压力下仍可靠的运行机制支撑”——稳定币稳定性取决于市场设计、套利通道、储备或抵押质量、赎回机制、流动性、用户信心与监管设计，因此一个 token 在普通条件下看似稳定，仍可能暴露于流动性冲击、赎回摩擦或信心驱动的挤兑。论文指出，稳定币风险评估不同于普通加密币预测：目标不是预测完整未来价格路径，而是判断其在固定窗口内是否稳定、进入预警（watch）或发生锚定压力（peg stress）。锚定压力指稳定币相对一美元锚定的显著、持续偏离；由于正常锚定噪声与罕见高后果压力事件必须分开，评估需要“有界证据”——关于偏离、波动率、成交量、市场语境与稳定币机制的有限信息。监测因此被框架为一种“证据有界的风险评估任务”：给定有限信息，系统应识别显著风险信号、判定锚定状况严重度、产出可复现评估。

随着 agentic AI 进入金融决策支持（包括自主预测市场交易），仅看最终答案准确率已不够。这类系统越来越承担推理、工具使用、工作流执行与决策支持，但可信评估还要求协议遵从、输出合法性、运行时成本与失败模式。相关工作里 AgentBench 把推理与指令遵循列为持续挑战，Agent2 RL-Bench 强调固定预算、运行时记录与失败诊断，Prediction Arena 把收益、胜率与 token 用量、周期时间一并衡量，TabArena 强调可复现透明的基准文档。成本感知的可信基准要求一个系统在“其预测将被使用的运行条件下”是否可靠，而非仅平均准确率高：一个模型在聚合指标上强，却可能漏掉罕见但高后果的压力事件、产出畸形输出、产生过高延迟或无法固定协议复现。论文指出，现有基准未直接测试 agentic 系统在成本与可靠性约束下能否充当稳定币风险监测 agent。其 idea 是把“可信赖性（trustworthiness）”定义为预测质量、运行可靠性与计算成本的联合属性，用防泄漏（leakage-safe）的历史回放框架，在统一协议下比较 agent 与简单基线，并显式报告稀有压力事件检测、校准、结构化输出合法性与推理成本。三个研究问题分别问：相对基线 agent 是否改善预测、稀有压力下如何权衡漏检与误报、富集块与自然分布块对比能揭示什么聚合榜掩盖的信息。补充机制背景有助于理解 peg 为何会断。主流稳定币靠套利维持锚定：价格低于一美元时套利者低价买入并向发行方按面值赎回获利，高于一美元时按面值铸造后卖出，这一闭环依赖赎回通道通畅与储备可信。一旦发行方暂停赎回、储备受质疑或预言机报价失真，套利失效，价格便可能持续偏离。USDT 与 USDC 属法币储备型（以现金与短期国债作储备），DAI 属加密超额抵押型（以 ETH 等超额锁仓生成），二者抗压力来源不同：前者取决于储备透明度与赎回信用，后者取决于抵押率与清算机制。基准将 BTC/ETH 仅作市场语境，正是为区分“稳定币自身机制失效”与“更广加密市场系统性压力”两类诱因。正因为罕见高后果压力事件占比极低，整体准确率之类聚合指标会掩盖漏检，这也正是论文强调分块设计与稀有事件诊断的动机。所谓成本感知（cost-aware）评估，是把每次预测消耗的 token、延迟与费用也列为评估维度——生产环境不会为一次风险判断无限投入算力，可靠性须在预算约束下衡量。

## 核心方法
StableEval Arena 是面向稳定币风险监测的历史回放基准。每个案例给定冻结的 30 天（720 小时）回看窗口，要求系统输出结构化的未来 7 天风险评估：stable/watch/stress 三分类、depeg（脱锚）概率、最大锚定偏离（基点 bps）、方向、置信度与理由，并以严格 JSON 模式约束。标签由冻结评估器按偏离阈值规则生成：偏离 = |小时收盘价 − 1| × 10000 基点；stable 为无实质不稳定，watch 为 ≥50 bps 的轻度不稳定，stress 为 ≥100 bps 持续偏离或严格持续脱锚（100 bps 连续 ≥3 小时）等严重情形。一个预声明校准规则把模型报告的概率与预测偏离映射为最终 stable/watch/stress 标签，原始与校准输出分别保留。隐藏的未来价格与标签仅用于案例选取与评分、绝不进入 prompt，从而保证 leakage-safe（防泄漏，即未来信息不泄漏进输入）。

资产覆盖 USDT/USDC/DAI（分别代表中心化发行方背书与去中心化抵押背书），BTC/ETH 仅作上下文以捕捉更广加密市场压力。框架用两套互补实验块：StableEval-120-Enriched（54 stable/45 watch/21 stress，富集压力以做稀有风险诊断）与 StableEval-507-Natural（441 stable/45 watch/21 stress，自然分布全池扩展）。二者共享同一协议：统一后端为 OpenRouter 上的 qwen-2.5-72b-instruct（temperature 0、禁用联网），相同 prompt 契约、严格 JSON schema、相同评估器。对比四个原生/框架级 agent（Nanobot、LangGraph、Hermes AI、EvoAgentX）与两个适配型 -Claw 扩展（OpenClaw、NanoClaw，因无本地 CMDOP 运行时仅作适配执行），并以 always-stable、historical persistence、threshold rule、simple ML 四类非 agent 基线防止“只有 agent”的比较。由于所有 LLM 后端相同，该比较测的是平台中介的执行、结构化输出、成本、延迟与可靠性，而非独立基础模型能力。可信诊断视角显式覆盖稀有 stress recall、missed-depeg 率、误报率、校准、成本、延迟、失败率与可复现性；每 agent-case 运行还记录原始/解析输出、输入包哈希与复现元数据，使预测错误与畸形输出、执行失败得以区分。为检验标识符敏感，论文做匿名化消融，最大标签变更率 0.333、平均概率变化 0.017–0.062，说明结果并非主要由记忆真实名称驱动；120-vs-507 对齐审计进一步确认扩展运行不 contradict 原始富集验证。

## Performance 概括
120 例富集块中，historical persistence 基线最强（Macro-F1 0.285、平衡准确率 0.300）；原生 agent 里 Nanobot 最佳（准确率 0.442、Macro-F1 0.351、平衡准确率 0.393），6 个 agent 中 5 个 Macro-F1 超过历史基线，但最高校准首过 stress recall 仅 0.095（历史基线 0.333）。507 例自然分布块中，always-stable 基线准确率 0.870 但 watch/stress recall 全为 0；最强基线 simple ML/logistic 为 Macro-F1 0.402、平衡准确率 0.493、stress recall 0.381；没有任何 agent 在 Macro-F1 上超过该基线（LangGraph 最高 0.304、NanoClaw 0.304、Hermes AI 0.301）。507 池 21 个真实 stress 案例中 6 个系统共漏掉 19 个，持续 depeg 漏检率无 agent 低于 1.0000；而所有 agent 在 120 与 507 上 valid-JSON 率均为 1.0、失败率 0.0。校准把最佳 agent Macro-F1 从 0.301（原始）提到 0.351（校准），验证器层把最佳 stress recall 提到 0.143 但成本几乎翻倍（Nanobot 从 $0.345 升至 $0.978）。核心结论是：执行可靠性高，但稀有压力与持续 depeg 检测仍很弱。

## 论文价值与不足
价值在于把“过程可靠性 vs 金融风险可靠性”的落差作为稳定币 agent 评测的核心发现，并以双块设计（富集 vs 自然分布）避免两类对称误读：富集块防止“因为多数案例稳定就认为可靠”，自然块防止“富集收益被误当部署级鲁棒性”。同时把成本、延迟、校准、稀有事件诊断纳入可信赖性视角，且开源数据集与代码、保留完整复现元数据，方法论对金融 agent 评测很有示范意义。论文还强调 missed-depeg（持续 ≥100 bps 脱锚 ≥3h）与 stress recall 是两个不同量、校准与验证器是成本敏感的权衡而非免费增益。不足在于：真实 stress 案例稀少（全池仅 21 个），stress recall 与漏检率应作风险信号而非统计结论；证据包有意有限（仅价格/成交量/市场结构），不含储备证明、赎回摩擦、预言机、跨链流动性、治理行为等更丰富信号；统一后端 qwen-2.5-72b 不测试后端泛化性；OpenClaw/NanoClaw 仅为适配执行而非原生 CMDOP；少量真实名称/日期带来残余参数记忆风险（匿名化消融最大标签变更率 0.333）。综上它是一项诊断型、可审计的评测基础设施，而非即时生产依据。还有两点边界需点明。其一，基准采用历史回放而非实时预测，测的是“给定同一份冻结证据包，系统能否稳定产出正确评估”，并不包含真实市场中的信息获取时延与工具故障；其二，统一后端固定为单一模型，论文无法区分“平台框架缺陷”与“后端模型能力上限”，agent 间的差距也不反映基础模型能力差距。这两点说明 StableEval Arena 的价值更偏向方法论与运行时诊断，而非提供可直接套用的生产风险阈值。

## 工业界落地可行性评估
该基准明确面向稳定币支付基础设施的 agentic 监测层，工业落地场景清晰：论文直接讨论了三类产业启示——（1）委托授权与可互操作的定期支付，用户需把支付权威委托给应用/智能合约/agent，agent 可决定执行/暂停/改路由支付；（2）SLA/清算/经济最终性，链上确认不等于经济最终性，需明确失败或延迟结算如何升级、损失谁担；（3）结算定价与税务问责，跨场价格与预言机喂价分歧会带来价差损失与税务归类风险。论文指出 agent 可帮助这些决策，但前提是 stress recall 显著高于当前水平。落地障碍在于稀有压力检测过弱，尚不能支撑自动化支付执行；且其仅覆盖价格稳定性，未来需扩展流动性、赎回、预言机、监管事件等多模态证据与错失压力惩罚的代价函数。未来工作应纳入钱包级流、授权指令、撤销日志、审计追踪与结算记录，并把评估从预测质量扩展到涉利益相关方、风险敏感的代价函数（错失压力惩罚、检测延迟成本、用户损失、平台合规负担、结算价误差、价差分摊、税务计算风险）。整体适合作为稳定币风险监测 agent 的回归基准与上线前压力测试，而非生产部署依据。成本维度对工业落地尤为关键：生产环境往往需对大量稳定币与长时段持续监测，而论文显示加入验证器层会让单次运行成本近乎翻倍，说明“更可靠”与“更便宜”在该场景下存在真实权衡，应按风险级别设定分层策略（高风险资产启用验证器、低风险资产用轻量路径）。此外 depeg 的判定阈值（持续 ≥100 bps 达 3 小时）本身是业务约定，落地须与具体稳定币的赎回机制、储备披露节奏对齐，而不能照搬论文的通用阈值。在接入方式上，StableEval 的冻结协议与可复现元数据（输入包哈希、复现元数据）使企业能把它作为 CI 中的回归测试：每次更新监测 agent 都重跑同一批案例，对比 stress recall 与误报率是否退化，从而把评估常态化而非一次性评测。
