# PCBWorld: A Benchmark Environment for Engine-Grounded PCB Design Automation

## 背景与 Idea
印刷电路板（PCB，Printed Circuit Board）是搭载并互连电子元器件的物理基板，几乎每一件电子产品都以它为骨架。把一张电路设计变成可制造（manufacturable）的板子，核心环节叫布线（routing）：在严格的设计规则（design rules）约束下，用铜走线（copper traces）把每个网络（net，即一组必须电气连通的焊盘 pad）的焊盘连起来，同时保证不同网络之间彼此电气隔离。现代电路板越来越密集，要在不冲突的前提下布通每一条网络变得愈发困难——两条不同网络的走线靠得太近会引发设计规则违例（DRV，design-rule violation，例如间距违例或交叉），从而阻断制造；只有零违例（DRV=0）的布线才是几何可行的（geometrically feasible）。

PCB 设计自动化若只停留在"大模型生成"层面，缺乏真实 EDA（电子设计自动化，Electronic Design Automation）引擎的校验，就极易产出不可制造的結果。工业界至今主流仍依赖基于规则的布线器（rule-based routers），它们源自几十年积累的启发式（heuristics），能可靠地完成板子上常规的部分，却很少能端到端完成多样、复杂的生产级板子。基于学习的方法（RL、LLM）虽被广泛研究，却不像语言、视觉、游戏领域那样已经能与规则型方法竞争——论文把这一落后归因于"布线问题被如何建模"：既有 RL 把布线建模为离散网格上的逐格移动，搜索空间随网格变细而爆炸式增长；要么把智能体限制在为自动布线器做辅助决策（如网络排序），质量被底层布线器封顶；近年的 LLM 方法则在一次开环（open-loop）中直接生成脚本或完整板文件，没有引擎反馈，难以满足严格设计规则。唯一能端到端可靠完成生产板的是人类工程师——他既不会把整块板交给自动布线器，也不逐条手画每根走线，而是反复读取当前板的几何状态、判断下一段连接该往哪走，并用引擎的原生操作（native operations）把新走线保持在设计规则之内。

论文主张"引擎接地"（engine-grounded）的评测与建模范式：让智能体在真实布线引擎中行动，并由引擎判定结果是否合法可行。换言之，把"能否制造"从一句模糊诉求变成可由引擎直接计算、可复现、可量化的指标。这一范式同时覆盖强化学习策略（RL policies）与工具调用型 LLM 智能体（tool-using LLM agents）两类方法，使它们能在同一环境里被公平比较。

## 核心方法
PCBWorld 把开源的 KiCad EDA 引擎包装成一个 Gym 风格的环境（Gym 是强化学习领域事实标准的智能体-环境交互接口，把任务形式化为状态-动作-奖励的马尔可夫决策过程 MDP），忠实复现真实世界的 PCB 布线工作流。整个系统分三层：最底层是 C++ 的 KiCad 引擎，负责实际计算（布线、设计规则检查）；中间层是 Gym 环境，它把引擎的原生操作定义成一个 MDP 的状态、动作与奖励；最顶层是两个定制包装器（wrappers），分别把同一个 MDP 重新编码给 RL 智能体和 LLM 智能体使用。

底层通过一组 Python 绑定（bindings）暴露 KiCad 引擎，PCBWorld 在其上提供 58 个 Python API：其中 14 个复现 PNS（推挤式布线器 Push and Shove Router）的核心布线 API，28 个直接包装 KiCad 的 DRC（Design Rule Check，设计规则检查）与板状态提取 API，16 个提供辅助工具。所有上层都只通过这些无图形界面（headless）的 Python API 与引擎交互，不依赖 GUI，因此每个环境持有自己的引擎实例，可并行化为向量化环境（vectorized environment），一次性推演多块板以满足 RL 训练所需的 rollout 吞吐。KiCad 本身是在 Linux 基金会下维护的开源 EDA 套件，能力可与 Cadence、Altium 等商业套件比肩；PCBWorld 基于 KiCad 9.0.8 与 kicad-python 0.6.0 构建。

动作空间被设计成贴近人类工程师的操作：一条动作由"动作类型 + 参数"组成，共六种类型（net_select 选择网络、net_end 释放网络、start_route 从某点起步、make_line 画一段到某点、make_via 画线并打过孔、finish 自动连到最近未连焊盘）。工程师式的 routing_mode 参数控制引擎如何实现这段走线（推挤阻挡走线 push_n_shove，或绕行 walkaround），以满足间距等设计规则。KiCad 引擎为终点 p_end 提供一组有限候选点（焊盘中心、已有走线/过孔端点），把动作空间从连续平面收敛到少数有意义的points，智能体只需选候选点与模式，而非在无限细的网格上逐格生成。

状态被表示为一个嵌套字典，忠实记录 KiCad 的精确数值与层级（板子有 pad→坐标等异构对象）；它刻意不用网格或渲染图像等抽象表示，因为 EDA 的严格设计规则要求智能体观察到板的精确状态。字典按可变性拆分：Board_static 保存不可变对象（焊盘几何、内部障碍、设计规则），Routing_geometry 保存布线中新增的对象（走线、过孔、逐焊盘连通性）。

奖励被定义为一个势能函数 Φ(s)：在约束优化目标（最小化线长 ℓ(s) 与过孔数 n_via(s)，且 n_drv(s)=0）的基础上，把"零 DRV"的硬约束松弛为一个惩罚项（对每条网络上的首个违例施加较大的边际成本），于是最大化 Φ 就驱动策略走向零违例、且逼近线长/过孔最优的布线。DRV 数量来自 KiCad 的 DRC API，它在 35 项库存错误级设计规则上评估违例（含未连焊盘、跨网络间距违例）。奖励可以是终端奖励（只比对最终与初始板），也可以是逐步奖励（每步势能差），后者在长程任务里提供稠密信用分配（credit assignment）信号；PPO 这类需要值函数估计每步优势的方法尤其受益于逐步形式。

配套发布的 PCBWorld-Bench 是一个面向"几何可行性推理"（geometric feasibility reasoning）的基准，提供统一的跨方法评测协议、三个板数据集与八项引擎可校验指标。三个数据集族：D1 是基于网格的合成板（把 Jumanji 的 Connector 环境移植到 PCBWorld，网格尺寸 G∈{10,50,100,200,500}，训练/验证/测试为 10000/128/128），用于和基于网格的 SOTA RL 方法（如 Sable）公平比较；D2 是无网格（gridless）合成板，释放 4–6 个网络、8–21 个焊盘、双层、允许过孔，同样 10000/128/128 切分，难度可通过网络/焊盘数直接调节；D3 是 679 块来自 PCBench 开源语料、经 KiCad 9 格式转换并保留原设计规则的真实开源板，按焊盘数从小到大分为 D3-A（小）、D3-B（中）、D3-C（大），所有方法共享 99 块 D3-A 与 10 块 D3-B 作为零样本评测集（大板评估成本高，故 D3-B 仅取 10 块）。由于评测只依赖完成的板文件，不论方法是否经过 PCBWorld，都用同一引擎验证打分，保证公平。八项指标里主指标是 Clean Pass（CP，干净通过率）：一块板只有在被选 rollout 完成布线、全连通且 DRV=0 时才算成功；其余指标包括 Potential Gain（势增益，板从裸板到完成态的势能变化）、Routability（已布通目标连接比例）、用时、DRV 总数、线长、过孔数，对 LLM 智能体另报 Parse-fail（响应无法解析为合法动作的比例）。论文默认对每块板抽 5 次 rollout 取势增益最大的一次计分（best-of-five，记为 @5）。

## Performance 概括
在分布内（in-distribution）的 D2-test 上，从零训练的紧凑 PPO Transformer 与最强规则基线 Freerouting 都达到完美 CP=1.00、Routability=1.00，但 PPO 在势增益（10.52 vs 9.76）与耗时（0.43s vs 2.69s）上更优；在分布外（out-of-distribution）的 D3-A 上，PPO 仍取得更高 CP（0.86 vs 0.80），显示强泛化；但在更大更复杂的 D3-B 上，Freerouting（0.78）反超 PPO（0.45），暴露了"仅在合成小板训练"在远超训练分布的网/焊盘规模板上的局限。

LLM 智能体方面，GPT-5.4 在 D2 的 CP 为 0.96，明显优于其小号变体 mini（0.58）与 nano（0.55）；但在 D3-B 上所有 LLM 的 CP 均为 0.00，说明当前 LLM 的几何推理尚无法扩展到大型板——这把"大板布线"确立为面向当今 LLM 的开放挑战。仅用合成板训练的 PPO 可以零样本迁移到真实板，接近基于规则的布线器，给出了一条训练布线策略的实用配方。

引擎参与度（engine engagement）的对比显示：交互式（interactive，每步观察板状态与 DRC 反馈）> 仅规划（plan-only）> 无引擎（engine-free）。在 D3-A 上，交互式与仅规划虽用同一动作空间且都能连上网络，但只有交互式保持了设计规则干净，DRV（1.29 vs 16.3）与 CP（0.65 vs 0.19）大幅分化；而无引擎方式因缺少 API 约束，需要极精确的几何推理才能不出错，GPT-5.4-nano 在 34–51% 的输出里甚至无法生成合法 KiCad 语法。奖励设计上，PPO（逐步）在最长程的 D3-B 上达到 CP 0.45，远优于 GRPO 的 0.10 与 PPO（终端）的 0.00，凸显长程布线中稠密反馈对信用分配的重要性。

## 论文价值与不足
价值在于提供了一套"引擎接地"、可复现、且同时公平覆盖 RL 与 LLM 两类智能体的 PCB 设计自动化基准，把"能否制造"这一模糊目标变成了可由引擎直接计算、可横向比较的量化指标（Clean Pass 等）。它用系统实验讲清了几个长期模糊的判断：基于网格逐格移动的 RL 在网格变细时因搜索空间爆炸而崩溃（Sable 在网格 200、A2C 在网格 100 即崩），而用段级 KiCad-API 动作的 PPO 决策视野绑定在"已布段"而非"网格格"，不随网格变细而恶化；交互式、带引擎反馈的布线一致优于一次生成式 LLM 与开环 LLM；仅合成板训练的紧凑策略能零样本逼近规则型布线器。PCBWorld-Bench 是首个在单一引擎验证评测器下的集成式 PCB 设计基准。

不足同样来自其引擎接地的取舍：其一，LLM 在复杂真实板（D3-B）几乎完全失败（CP=0.00），说明让大模型直接端到端生成可制造 PCB 仍有巨大差距，距离工业可用很远；其二，引擎所覆盖的 PCB 类型与约束有限——评估只基于几何可行性与连通性（DRV、线长、过孔），并未纳入工业实践中更关键的信号完整性（signal integrity）、电磁干扰（EMI）、热目标（thermal）等；其三，动作空间未纳入"删轨迹"类 API（如 delete_track_near），因此缺少 rip-up and reroute（撕除重布）这类高质量布线通常依赖的迭代修正能力；其四，D3 大板评测样本少（D3-B 仅 10 块），统计稳健性受限。

## 工业界落地可行性评估
可落地于 EDA 工具内部的自动化布线评估与算法对比，尤其对 RL/搜索类布线方法价值直接：企业可在 PCBWorld 的向量化、headless 环境里大规模训练与回归自己的布线策略，并用 Clean Pass 等八指标做可复现的横评。对于"辅助+引擎校验"的闭环（人类或 LLM 提建议、引擎做硬约束校验），本范式已经比较成熟，是现阶段最现实的应用形态。

但让 LLM 直接端到端生成可制造 PCB 目前远未成熟——D3-B 上全部 LLM 归零，意味着纯生成式方案短期内不能替代工程师或规则型布线器。工业落地更可能沿两条线推进：一是把 PCBWorld 当作"布线策略的训练场与评测台"，用于炼出可零样本迁移到真实板的小模型（论文已证 PPO 接近规则型）；二是把引擎接地作为"生成-校验"流水线的校验层，凡 LLM/搜索产出的布线都过一遍 KiCad DRC 才算数。要真正进入生产，还需补齐信号完整性、EMI、热等工业级目标（把这些信息纳入势能函数 Φ 即可同时塑造评测与训练），并补上 rip-up and reroute 等迭代修正动作——这些在论文讨论里被明确列为下一步方向。总体而言，它是高价值、中高可行性的研究基础设施，而非可直接上线的端到端布线产品。
