# Confidence-Aware Multi-Agent Orchestration for Evaluating Multimodal Rule Compliance

## 背景与 Idea
多模态规则合规评估（multimodal rule compliance，即判断图文/视频等内容是否违背平台或监管规则）需要综合视觉与文本两类证据，而单一模型在跨模态信息相互冲突时容易出错。这类任务在工业界真实存在：大量商品必须依据复杂的监管标准、用文本与图像等多模态证据来判定合规，且每个模态都带有噪声、缺失数据与部分观测。评估不仅要准，还要可解释、可审计、能报告不确定性——这是可信 agentic AI 的核心要求。

作者（Amazon 团队）指出，现有做法各有短板：有监督分类器需要大量标注数据、且标准一变就要重训；LLM-as-a-Judge 提供了可扩展的零样本替代，但常见的多模态大模型（MLLM）对整个输入套用统一的推理策略，既缺少不确定性量化机制，也缺少跨模态冲突解决机制；多 agent 协作虽能按模态分专家，但朴素集成（平均、投票）把所有 agent 输出当成同样可靠，掩盖了推理路径、削弱可审计性。更根本的空白是：当模态专家给出相互矛盾的判定时，这种"冲突本身"其实是丰富的诊断信号，它指示出系统应当投入额外推理的区域（认知不确定性区域），而现有工作很少直接处理 agent 间冲突。

针对这一痛点，作者提出置信度感知的多智能体编排框架：让多个专家 agent 协作完成评估，并显式引入各 agent 的置信度来协调分歧、融合判断。其出发点是在"感知—判定"两段式流程中，用置信度作为调度信号来抑制单模型在模态冲突下的误判。置信度感知（confidence-aware）指编排层不只看各 agent 的判定，还看它对自己的判定有多确定，再据此决定信任谁、何时需要进一步追问——这把"不确定性"从被掩盖的东西变成系统显式处理并记录的头等对象。

这一问题在合规场景尤其尖锐：工业界用有监督分类器需要昂贵标注、标准一变就要重训；LLM-as-a-Judge（把大模型当裁判做零样本评估）虽可扩展，但多模态 LLM 往往在跨模态证据冲突时过度自信且评分不一致；而多 agent 辩论（Multi-Agent Debate, MAD）这类开放辩论方法，近期研究反而显示其常劣于朴素集成、且会被"自信但错误"的推理带偏。因此本文刻意不选开放辩论，而是让编排层生成定向追问来收集补充证据——这同时吸收"选择性升级难例"的效率与"证据锚定的裁决"的可靠性，并产出完整推理审计轨迹。

## 核心方法
框架由三个组件构成，目标是同时最大化准确率与可信度。第一是 Rule Generation（规则生成）：把监管文档转成结构化、可审计的合规规则，每条含自然语言描述、严重级别、来源溯源、以及验证所需的产品属性。它分三步——抽取、精炼、路由：抽取出规则后，用少量标注样本（每条模糊规则 5 正 5 负）分析 base agent 的系统性错误模式并改写规则表述（加入关键属性、明确定义、正负面例、边界条件），注意这里改的是规则规范而非模型权重，因此标准演进时可快速适配而无需重训；路由则按规则所需属性与"模态主导性"先验，把规则确定性地派给文本 agent、视觉 agent 或两者都调用来做跨模态校验。

第二是 Base Agents（基础专家 agent）：每个模态配专用基础模型，而非用单一 MLLM 套用统一推理。文本 agent 基于结构化商品元数据做逻辑推理；视觉 agent 采用 perception-then-judgment（先感知、后判定）两段协议——感知步只描述输入模态中观察到的属性事实、不做任何合规判断，判定步再基于感知描述单独做合规推理。论文强调这一分离对可信度至关重要：当"观察"与"结论"被混在一起时，模型对规则结果的预期会偏置它看到什么；把感知与结论隔开，能保证证据扎根于实际观测而非被期望中的判定塑形。每个 base agent 返回标准化输出：verdict（PASS/FAIL/UNCERTAIN）、证据、置信度、推理轨迹，便于下游统一处理与逐 agent 可信度评估。

第三是 Orchestrator Agent（编排 agent）：通过两个机制做跨模态合成与冲突解决。其一是 verdict triage（判定分诊）：综合"模态主导性"先验与各 agent 输出的置信度来路由——单 agent 触发则直接返回；全部一致则聚合置信度；冲突但有一方在其主导模态上高置信则信任该高置信方；冲突且双方低/不确定置信则升级为迭代冲突解决。这避开多数投票"所有输出同等可靠"的陷阱，且分诊逻辑透明、记录了走了哪条分支及原因，可事后审计。其二是 follow-up question generation（追问生成）：当冲突仍未解决，编排层不是用相同提示重问或开无界辩论，而是审视冲突判定、置信度与证据，用 LLM 生成一个针对具体分歧点的澄清问题，判定哪个 base agent 最适合解决该歧义，并委派它透过新问题重新评估数据；该过程迭代直到达成共识、达到置信阈值、或达到最大迭代次数。每一步（未决冲突、追问、解决）都被记录，形成完整审计轨迹。

评估在"产品包装合规"任务上：依据涵盖包装形状、结构完整、物理属性等复杂规则判定商品是否合格，数据含文本目录属性与包装图像（两类模态都有真实噪声：文本可能缺失、图像常拍不全所有面且受光照影响）。规则生成模块从合规文档抽取出 38 条结构化规则（分"必须合规"与"建议合规"，违反必须规则即不合格），以 216 条人工验证样本（100 合格 / 116 不合格）为真值。基线含 text-only、image-only、单体 MLLM、以及"多 agent + LLM 融合"（collect-then-reason 朴素聚合，无冲突解决）。

结果揭示的几个现象值得单独点出，它们解释了为何需要这套编排而非单一模型。首先是"注意力稀释"：单体 MLLM 虽同时拥有文本与图像两模态，F1 却在全部方法中最低（0.661），说明单遍融合让模型难以在冲突信号间正确加权、缺乏显式推理结构来识别冲突——这直接挑战"数据越多评估越好"的直觉。其次是"朴素融合抓不到跨模态协同"：多 agent + LLM 融合（F1=0.823）与单个 agent 表现相当而非超越，因为它没有主动收集新证据或做置信度感知的解决，融合 LLM 常退回到更保守的判定；这表明主流多 agent 做法"在现有 agent 输出上推理"并不能在 agent 分歧时利用互补模态信息。第三是"互补模态贡献"：两模态单 agent 的 F1 接近（文本 0.823、图像 0.835），但错误画像不同——文本召回高（0.897）、精度低（0.760），图像相反（召回 0.855、精度 0.816），编排层正是利用这种互补性，在评估每个具体属性时委派最可靠的模态，这正是置信度分诊 exploited 的本质。

论文在讨论部分还把结论推广到更一般的 agentic 评估：其一，冲突模式本身是可信度信号——哪一模态、哪类规则、什么置信度下发生分歧，可在无真值情况下作为分布漂移或能力退化的持续监控信号；其二，主动不确定性降低（生成定向追问）优于被动聚合（投票、融合），提示评估系统应显式设计"知道自己不知道、并行动降低不确定性"的机制，而非用不足证据强行判定；其三，结构化编排让每一决策点（分诊分支、追问、最终 verdict）都可独立核验，这是监管合规应用对可审计性的硬性要求；其四，基于"agent 共识识别简单案例、把人审集中在真正歧义实例"的标注策略，可在不穷尽人工标注的前提下实现大规模真值构建。

## Performance 概括
在 216 条人工验证样本上，框架整体准确率达 89.8%、F1 为 92.5%，相比最强基线（单体 MLLM 77.3% 准确率、83.5% F1）提升约 12.5pp（准确率）与 9.0pp（F1）。跨模态冲突解决机制相对无该机制的朴素融合版本，F1 提升约 13.9%（从 0.823 到 0.925），相对单体 MLLM 提升 26.4%。值得注意的是单体 MLLM 尽管同时拥有两模态却在所有方法中 F1 最低（0.661），说明单遍融合会带来注意力稀释；而框架在召回上提升尤其明显（0.938 vs 融合 0.834），证明追问机制成功解决了初始证据不足以确认合格的那些高风险的例。

## 论文价值与不足
价值在于把"置信度"与"冲突"显式建模进多 agent 编排，并以主动追问（active information gathering）而非朴素集成/开放辩论来解决跨模态冲突，方法轻量、可解释、且产出完整审计轨迹。它是首个在规则评估中用"主动信息收集"解决跨模态 agent 冲突的工作，呼应了多 agent 辩论（MAD）研究中"定向干预优于穷尽辩论"的发现。定性案例中，closure-seal 规则检查里文本 agent 因缺失属性报 UNCERTAIN、图像 agent 报 PASS，编排层生成针对性追问后图像 agent 仍无法确认所有边封口，最终正确给出 UNCERTAIN 而非强行二值判定——这体现了系统"不掩盖不确定性、追问针对分歧点、保留推理轨迹"三项可信度性质。论文还把冲突模式本身视为监控信号：哪两个模态、在哪类规则、以何种置信度分歧，可在无真值情况下检测分布漂移或能力退化。

不足主要在规模、校准与迭代深度。验证仅在 38 条规则与 216 条样本的小规模集合上完成，规则覆盖面与样本规模都有限，泛化能力需在更大规模、更丰富规则集上确认。置信度目前依赖 LLM 自报（self-reported），可能校准不良——论文观察到 agent 在高置信下给出错误判定的情况，会绕过冲突解决机制，作者指出现学的校准层是重要方向。当前实现最多只做一轮追问，虽避免无限计算，但涉及多规则交互的复杂案例可能受益于更多轮次，这是计算成本与评估彻底性之间的权衡。此外约 10% 的规则检查因关键物理属性（重量、材料厚度）在任何模态都不可观测而必然终止于 UNCERTAIN，属于固有数据不足而非方法缺陷。

## 工业界落地可行性评估
较可行，且场景明确：框架面向内容审核、商品/广告合规检查等需要多模态证据融合的场景，可直接用作平台规则合规的自动化初筛与辅助判定环节。其"perception-then-judgment + 置信度分诊 + 主动追问 + 完整审计轨迹"的结构，正好满足监管合规应用对可审计性的硬性要求——每一决策点（分诊分支、追问、最终 verdict）都可独立核验，区别于端到端神经网络推理路径不透明。规则生成改规范不改权重的设计也让标准演进时能快速适配，无需重训模型。它还能用"agent 共识识别简单案例、把人审集中在真正歧义实例"的标注策略，降低大规模真值构建成本。

落地前需补三件事：其一，补充更大规模、更丰富规则集的验证，确认泛化能力；其二，用历史 agent 输出训练学得的校准层以替代自报置信度，否则高置信误判会绕过冲突解决；其三，评估真实生产流量下的时延与成本（每轮追问都增加 LLM 调用与往返延迟）。另外，对"关键属性任何模态都不可观测"的品类，系统会正确返回 UNCERTAIN，需要配套的人审兜底流程而非直接自动化决策。总体看，作为轻量、可解释、可审计的合规评估编排层，它在工业界采用门槛不高、收益清晰。
