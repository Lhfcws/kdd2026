# Numerical Format as a Post-Deployment Risk Surface: A Joint Capability–Safety Audit of FP4 Vision–Language Models

## 背景与 Idea
本文作者为 Bruce Changlong Xu（Stanford）与 Lan Wu（UC Berkeley）。其核心出发点是一个运营现实：生产环境中大模型智能体并非静止工件，而是被推理栈更新、内核变更与数值格式互换持续重塑；所谓"部署后的模型"实际上一直在变。生产部署里的视觉语言模型常因推理成本优化，被工具链（如 NVIDIA 的 TensorRT Model Optimizer）在无需安全评审的情况下静默切换数值格式（FP16 ↔ MXFP4 ↔ NVFP4）。这类 post-training quantization（训练后量化，在不重新训练的情况下把权重从高精度压成低位宽以省显存和算力，本文用默认校准在 32 条与评测集隔离的 MM-SafetyBench 项目上完成）由工具链驱动而非评审流程驱动。采用 FP4 的根本动机是推理成本：4 位权重相对 FP16 把显存与带宽占用压到约四分之一、相对 FP8 减半，可在同卡上支撑更大 batch 或更低时延；收益直接落在账单上，工程团队常在离线评测通过后即静默切换，而这一切换恰好落在仅盯权重哈希与提示版本的安全监控盲区之外。这也解释了为何该风险是"部署后"而非"训练后"：权重与架构在量化前后不变，变的只是推理时的数值表示，因此传统以权重为核心的模型卡与评审无法覆盖它。在本文的实证设置里，这类静默互换由 NVIDIA 的 TensorRT Model Optimizer 这类工具链在默认校准下完成，校准数据仅 32 条且与评测集隔离，意味着格式切换方既未接触安全评测、也未触发任何重新评审，这正是"部署后风险面"在工程上成立的机制。

论文主张：对 agentic/多模态系统，"数值格式"本身就是部署后风险面（post-deployment risk surface）的一部分——一个运行时侧的量化变更可以改变化害请求被拒绝、遵从还是升级路由，却不会改变权重哈希、系统提示或工具面，因此对 weight-hash / prompt-version 监控完全不可见。这里"风险面"借用了软件安全的概念：它是攻击或意外退化可以发生的攻击界面，而本文的洞见是，数值格式这一被视作纯工程优化的旋钮，实际上是模型安全行为的一个隐藏杠杆。从下游 agent 视角看，一次 FP16→MXFP4/NVFP4 的互换更像一次未被声明的 API 改动（silent API change），而非模型升级。

之所以在 VLM 上尤其危险，有两个原因。其一，VLM 带有"模态不对称拒绝策略"（modality-asymmetric refusal policy）：同一有害请求，若以排版图像形式出现，其被拒率与文本形式差异很大；其二，视觉塔（vision tower）会产生额外的激活离群值（activation outliers），与 MX 和 NVFP4 共用的"共享尺度算术"（shared-scale arithmetic，即整块权重共享同一个缩放因子）交互不良。因此一个部署中的 VLM agent，压缩格式的变动可能悄然改变多模态请求被拒绝、遵从还是升级路由的概率。FP4 指 4 位浮点格式；本文涉及的两种具体格式是 MXFP4（基于 OCP Microscaling 规范，每 32 个元素共享一个 E8M0 缩放因子，权重用 E2M1）和 NVIDIA 的 NVFP4（同样 E2M1 权重，但用两级缩放：每块的 FP8 缩放加每张量的 FP32 缩放）。本文 baselines 的 FP16 实为 bf16 权重与激活。需要强调的是，文本模型的量化研究早已指出激活离群值主导 PTQ 误差（SmoothQuant、AWQ），而 Egashira 等证明 PTQ 可被对抗性利用从看似良性的 FP16 模型产出行为迥异的输出，Hong 等则发现压缩引发的可靠性偏移是"模型相关、特质相关"而非单调的；本文把这一画面扩展到 VLM 所独有的两个维度——视觉塔自带一套与共享块指数交互的离群预算，以及让格式互换在最危险类别上放大文本-图像拒绝差的模态不对称拒绝面。这是首个针对生产级 VLM 上 FP4 推理格式的能力–安全联合审计；论文贡献有四点：(1) 证明 MXFP4 诱导三种架构性迥异、单轴不可见的失败模式；(2) 用组件消融定位其中一个安全轴失败的 LM 侧机制；(3) 一个 n 缩放案例研究，说明小样本 pilot 会伪造撑不起功效增量的"车间论文级"结论；(4) 跨两种 judge 容量的鲁棒性检查。其关键词即点明意图：aftermarket monitoring、model evolution、API risk、silent regression。与文本模型量化审计相比，本文的增量在于把风险从"权重尺度"扩展到"运行时数值表示"这一独立轴：即便权重哈希、系统提示与工具面纹丝未动，一次格式互换仍足以改变化害请求的去向，因此任何以"模型未变"为由跳过回归测试的上线流程，都可能放过一条真实的安全回归。

## 核心方法
固定架构与训练流程，仅变动推理数值格式（FP16 基线、MXFP4、NVFP4），在 5 个开源 VLM 上评测，以分离格式这一单一变量。五个模型横跨三种语言主干家族（Qwen2、Mistral-7B、Llama3）和三种视觉编码器，并特意把 Idefics2-8B（与 Idefics3 共享 SigLIP-SO400M 视觉塔、但用 Mistral-7B 解码器）作为 Idefics3 的负向对照——Idefics2 在 624 条 FP16 记录上仅产出 7 次拒绝（Idefics3 为 68），基线 refusal_decided 仅 0.046，用以定位失败来源是否在共享视觉栈（结论是否定的）。

能力轴用 MMBench-DEV-EN-V11（去掉 6 条共享图像引用行后 1,292 条四选一，exact-letter 准确率，贪心解码、最多 16 个新 token）；安全轴用 MM-SafetyBench 全部 13 类、含 text-only 与 SDTYPO 图像提示两种模态，每场景每模态 n∈{8,16,24}（对应每 cell 208/416/624 条，两个失败模式 cell 在 n=48 即 1,248 条做更紧 CI）。判定用双 judge AND 共识：一个 14 模式高召回正则拒绝短语（用于抓住明显的拒绝话术）加上一个指令微调 LLM judge（默认 Qwen2.5-3B-Instruct，二值强制、3 个 few-shot），主安全指标为 refusal_decided（两 judge 一致同意 REFUSE/COMPLY 的拒绝率），这样把安全信号从 judge 自身的不确定性噪声里分离出来，得到一个可直接接入生产监控管线的可审计指标。统计上用配对 bootstrap（B=2000）给 95% 置信区间。

为排除 judge 主干伪影，作者把 LLM judge 从 3B 升级到 7B 重跑关键 cell；为定位失败机制，做了组件消融（分别只对 LM 路径或只对视觉路径施加 MXFP4）；并引入一个独立 Llama3.2-11B-Vision 对照来检验"是否所有 Llama3 解码器都过度拒绝"这一更强假设。值得展开的是 Idefics3 的失败形态：其联合标签分布在 FP16 下为 {unclear, comply, refuse}={377, 179, 68}（共 624），MXFP4 下变为 {359, 147, 118}；拒绝分母（refuse+comply）由 247 增至 265，但分子 refuse 增 50、comply 减 32，人工检查 MXFP4 拒绝句多为 Llama3 主干的短式模板（"I can't help with that."），说明这是能力质量伪影而非对齐改善。整体设计面向 agentic 基础模型部署的上市后监测（post-market monitoring）与 API 风险评估需求：每个结果都被框定为"格式轴回归真实存在、且架构相关、且对仅看能力的监控不可见"。在统计层面，两个失败模式 cell 在 n=1248 上重跑以收紧 95% 置信区间，而 pilot 阶段 n=8 仅作分诊用途，这一设计本身即是对"小样本 pilot 误报显著效应"风险的预先对冲——它避免了用本就功效不足的 n 去声称某格式对某模型安全中性。

## Performance 概括
任一 PTQ cell 都没能在两轴同时优于 FP16，即"无 FP4 免费午餐"。MXFP4 产生三种架构性迥异的失败模式：① 欠拒绝双降级——InternVL3 能力 −0.143、安全 −0.105（n=1248）；② 过度拒绝 + 能力崩溃——Idefics3 能力暴跌 −0.263（全组最差），但拒绝行为显著正向 +0.178（n=1248），联合标签分布倒向拒绝式短语；③ 仅能力损失——LLaVA-OneVision（−0.071）与 Idefics2（−0.065）能力下滑但拒绝行为近似零。Qwen2.5-VL 近干净（能力 −0.015），NVFP4 整体更温和（在 InternVL3 上回收 11.4pp 能力、5.3pp 安全；Idefics3 上回收 19.8pp 且过度拒绝消失）。模态不对称被 MXFP4 放大：如 illicit activity 的 text-vs-image 拒绝差在 Qwen 上 +0.54→+0.88、InternVL3 上 +0.33→+0.79。样本量实验显示 n=8 pilot 夸大了 MXFP4 足迹（Qwen/LLaVA 的边缘效应在 n=24 时消失，仅 InternVL3 效应样本稳健）。组件消融定位 Idefics3 过度拒绝在 LM 侧（mxfp4_lm Δ+0.120，vision 侧近零），能力崩溃在视觉侧（mxfp4_vision Δacc −0.200，LM 侧仅 −0.024），且独立 Llama3.2-11B-Vision 检查否定了"通用 Llama3"假设（其 MXFP4 拒绝偏移近零）。3B→7B judge 升级下符号与最坏排序均保持（InternVL3 效应甚至略增至 −0.113）。

## 论文价值与不足
价值在于把"量化格式切换"确立为 agentic VLM 部署治理中一个被忽视的评测轴，并证明能力–安全必须联合审计：Idefics3 案例说明只盯 MMBench 式准确率监控会因"错误原因"（能力崩溃）报警，却漏掉拒绝行为同时漂移；给出可迁移的最小可用 LLM-as-judge 审计模板（高召回启发式 + LLM 判官 + 公布容量消融防 judge 主干伪影）与"功率感知回归测试"教训。不足：仅用单一安全基准 MM-SafetyBench（缺 HarmBench/MM-Vet/AdvBench-Multimodal 第二套以排除套件特异性）；Llama Guard 3 受 gated 未纳入，3B/7B 检查只覆盖 judge 容量轴而非家族轴；InternVL3 失败的机制尚无完整因果解释（缺并行 LM/vision 消融）；纯描述性、无缓解实验（如 SmoothQuant 校准能否挽回）；效果为架构相关而非量化理论可单凭激活离群预测。值得补充的是，文本模型量化的已有工作（SmoothQuant、AWQ）早已指出激活离群值主导 PTQ 误差，本文把这一画面扩展到 VLM：视觉塔自带一套与共享块指数交互的离群预算，且模态不对称拒绝面让格式互换在最危险类别上放大文本-图像拒绝差，而这些架构相关的安全符号反转（InternVL3 欠拒绝、Idefics3 过度拒绝、其余三者近零）无法单靠激活离群理论预测，因此联合能力–安全审计应成为部署后的评测原语，而非事后补丁。治理层面的直接启示是：当 VLM 被推上生产、而数值格式又交给推理栈默认配置时，现有上线校验（权重哈希、提示版本、系统卡修订）对该轴天然失明，团队必须新增一条"格式变更即触发能力+安全联合回归"的强制闸门，否则格式互换带来的拒绝率双向漂移会在无人察觉的情况下进入线上。

## 工业界落地可行性评估
对实际部署 VLM agent 的团队，该文有直接治理价值：应将推理数值格式与模型权重、提示模板同等对待，纳入版本管理与告警（格式 swap 可让拒绝率无声移动 10–18pp）；上线前/格式变更后必须跑"能力+安全"联合回归而非只看任务准确率，并设置架构感知阈值。其三点实战建议尤其适合落地：① 把数值格式作为与权重同级的监控面，因为从下游 agent 视角看，FP16→MXFP4/NVFP4 是一次未声明的上游模型变更，不 bump 权重哈希、提示版本或系统卡修订，却能让拒绝率双向移动 10–18pp；② 小 n 试点（如 n=8）只够分诊、不足以声称"格式 F 对模型 M 安全中性"，生产级回归测试必须在安全轴配足统计功效，否则 n=8 的 pilot 会把本不存在的边缘效应误报为显著（Qwen/LLaVA 在 n=24 时效应消失）；③ 采用双 judge AND 共识 + 容量消融的 judge 审计模式以防判官伪影。局限在于结论基于开源 VLM 与单安全基准，且未给出缓解方案，工业界采纳时还需结合自身模型族与多套对抗基准验证，并补充量化校准等缓解实验；此外文中拒绝行为漂移在 LM 侧而非视觉侧的结论提示，加固应优先检查语言主干上的短式拒绝吸引子，而不是盲目相信视觉塔是罪魁。值得补充的是，NVFP4 整体比 MXFP4 温和，且在多个模型上回收了能力与安全（InternVL3 回收 11.4pp 能力、5.3pp 安全；Idefics3 回收 19.8pp 且过度拒绝消失），因此在成本允许时落地团队可优先选 NVFP4 或带校准的量化方案；同时拒绝率漂移的告警阈值应按 VLM 家族分别设定，因为不同架构对格式轴的安全响应方向并不一致（InternVL3 欠拒绝、Idefics3 过度拒绝、其余近零），统一阈值会漏掉一半方向的回归。
