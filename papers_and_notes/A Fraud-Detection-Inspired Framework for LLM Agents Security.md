# A Fraud-Detection-Inspired Framework for LLM Agents Security

## 背景与 Idea

大语言模型智能体（LLM agent）在自主任务执行、工具使用与多步推理上展现出强能力，但它们不断增强的自主性也打开了新的攻击面（attack surface）。这类攻击不再只是模型生成有害文本，而是可能调用真实的环境动作：读取私有资源、发送消息、调用 API、执行命令。攻击途径主要有三类。其一，直接提示注入（direct prompt injection）：把恶意意图嵌入看似良性的用户任务中。其二，间接提示注入（indirect prompt injection）：把对抗指令污染进检索到的外部内容或工具返回里，使一个用户能影响另一个用户与智能体的交互。其三，多轮升级策略（multi-turn escalation）：一段交互从良性请求开始，经过试探、改写或语义漂移，直到后期才触发明显有害的动作。现有防御多聚焦"单轮提示级过滤"或"规则护栏"（guardrail），即判断当前这一条 prompt 是否恶意、是否试图覆盖系统提示或诱导危险工具调用。但作者指出，这类防御是不完整的：真实对抗交互往往是序列式、策略性的，许多不安全轨迹并不能由单个 prompt 捕获——一个危险会话可能以良性请求开头，经过反复试探后才触发有害动作。因此作者主张把智能体安全从"提示级过滤问题"重构为"系统级对抗交互检测"：提示注入只是更广义"对抗交互"的一个特例。

本文的出发点是从支付与登录滥用等成熟领域借鉴"欺诈检测"（fraud detection）思路。在支付、登录保护、滥用预防等系统中，防御者几乎不会只依赖某一次尝试，而是从序列模式、速度（velocity）、异常分数、上下文失配、历史尝试与执行结果中聚合证据——这与"多轮交互中逐步升级的风险"在结构上同构。作者因此把智能体安全重新建模为"交互轨迹级对抗检测"（trajectory-level adversarial interaction detection）：不再判断单条 prompt 是否恶意，而是对交互轨迹建模风险。这里需要解释"轨迹"是什么：一条交互轨迹被建模为按轮索引的序列 S1:T = {(x1,a1),...,(xT,aT)}，其中 xt 是模型可见的输入（用户或外部内容），at 是智能体在该轮的动作；目标是估计前缀 S1:t 是否表现出对抗行为。这种形式化让"正在演化的交互"成为分析的中心对象，而不是把当前输入当成唯一检测目标。

具体地，论文定义了三种正交的攻击进入通道：用户可见输入中的直接注入、检索或工具返回内容中的间接注入、以及跨越一个会话的多轮升级。这三者构成攻击面，但真正决定检测难度的是"轨迹如何跨轮展开"——一个足够精巧的攻击者可以把三种通道任意组合，而其中每一轮单独的 prompt 与良性流量无法区分。论文因此用"轨迹如何跨轮演化"而非"单条内容是否可疑"来刻画攻击。一句话概括其 idea：用轻量、可解释、低延迟的轨迹级检测层，作为 LLM 护栏、沙箱、权限控制、人工审查的补充，在敏感执行前给出"允许/限制/阻断"的分级风险信号。

论文用一张防御策略对比表（Table 1）把这个定位讲清楚：现有方法——提示级过滤（Prompt-level）、护栏（Guardrails）、沙箱与权限限制（Sandboxing）、对齐（Alignment）——要么只做单轮过滤、要么部署成本高难以实时，而本文方法是少数同时支持"单轮+多轮+低延迟可部署"的方案。这正对应了真实 agent 场景的痛点：对抗行为本质上是序列式的、跨多个交互步骤展开，仅靠逐条 prompt 分析会漏掉"反复试探、语义重定向、渐进升级、检索内容与后续执行的恶意协调"等模式，而更强硬的沙箱防御又贵又笨重、难以实时部署。论文因此主张"基于行为的交互轨迹检测"应作为提示级过滤的补充，同时足够轻量以实用部署。

## 核心方法

框架由"结构化特征构造 + 轻量模型推理 + 风险感知决策"三段组成，部署在智能体管线的关键执行阶段之前。特征部分把交互轨迹编码为五组行为信号，论文强调这五组只是一套具体实例化，而非固定特征集，每个维度在不同部署环境下都可用不同方式获取。

第一组是 prompt 信号：捕捉输入及其直接上下文，包括 prompt 长度、token 数、可疑关键词指标、指令冲突模式、覆盖（override）尝试、潜在权限升级信号，这组最接近传统提示检测信号，因为它作用在单个输入上。第二组是 session 信号：用按轮索引的聚合量总结智能体在交互历史中的行为，包括重试与重复、被拒或失败动作、近期暴露于不可信内容、跨轮语义漂移、工具使用多样性；它们是对应的"时间窗速度信号"的在轮次上的类比——生产欺诈检测常用时间窗速度信号，而本文场景没有墙钟时间戳但有完整轮次顺序，因此改用轮次聚合来捕捉"持续或协调、从单个 prompt 看不出来的行为"。第三组是 tool 信号：用 one-hot 表示当前提议动作（web_fetch、summarize、read_local_file、send_email、run_shell 等），再加一个"任务—工具失配"（task-tool mismatch）二元标志——当所选工具与用户请求不一致时置 1，否则为 0；论文特意把轨迹级信号与 tool 信号分开，以便消融研究能隔离"交互动态"与"动作身份"的效应。第四组是 context 信号：纳入环境与检索内容的信号，例如是否存在外部/不可信内容、这些内容是否含可疑模式、是否涉及敏感资源、危险动作是否紧跟外部输入摄入——这组对间接攻击尤其重要，因为恶意信号可能来自检索或工具中介的上下文而非用户 prompt。第五组是 trajectory 信号：受欺诈检测常见信号（累积风险、速度突发、新颖性、时间共现）启发，具体化为四类——(i) 累积工具风险路径及其逐轮增量和单调性标志（捕捉权限升级）；(ii) 动作突发分数（最近三轮调用高风险工具的比例，捕捉 staged-burst 模式）；(iii) 新颖性标志（当前邮件收件人与文件路径，对照训练集上拟合的"仅良性"参考剖面，类比账户欺诈里的"新设备"标志）；(iv) 上下文—外泄间隔（context-exfil gap，同一会话内"首次敏感读取"与"后续外部发送"之间的轮次距离，捕捉 split-exfil 共现）。论文指出，session 特征计算的是跨任意动作的通用前缀聚合，而 trajectory 特征显式瞄准"定义对抗轨迹的跨轮结构"，消融研究显示仅这一组就几乎匹配完整检测器，并在 leave-one-out 中 dominate 其它组。

模型选择上，框架偏好轻量、适合在线部署的模型。梯度提升决策树（尤其是 XGBoost）在表格数据上表现优异、能捕捉非线性交互、且推理快，因此作为实例化选择；浅层神经网络作为特征交互更复杂时的备选。训练目标是标准的二分类交叉熵：标签 yi∈{0,1} 表示交互 i 是否为对抗交互，yhat 为预测概率。论文明确：XGBoost 只是"轻量模型要求"的一种实例化，框架兼容任何支持低延迟表格推理的模型类。

决策层定义一个分级规则：风险分 rt 低于阈值 τ1 则 allow；在 [τ1,τ2) 之间则 restrict（禁用特权工具、要求显式确认、或路由到更强的审计路径）；≥τ2 则 block（拒绝动作并记录待查）。这保留了低延迟风险打分的好处，同时支持分级干预。在线推理时，特征在各交互步增量更新——prompt 级特征从当前输入算，session 级汇总历史元数据，tool 级随提议动作更新，context 级跟踪新引入的外部/敏感信息，trajectory 级聚合累积风险/新颖性/升级趋势——结果向量流经模型得到 rt。由于特征抽取与推理都轻量，附加延迟可维持在毫秒级，因此系统不必等到明显不安全动作出现才检测，而是在"轨迹本身是否在变危险"时就能评估。

实例化中，检测器用 XGBoost（180 个 estimator、max_depth=4、42 个特征，横跨上述五组）做二分类，在敏感执行前给风险分并分级决策。实验在合成多轮交互语料上评估：用参数化模板模拟真实 agent 工作流（文件检索、邮件撰写、网页浏览、shell 执行）生成 12,000 条交互，按 60/20/20 切分（固定随机种子），留出测试集含 1,200 良性 + 1,200 对抗；每条交互贡献多个前缀评估点（不同轮次的部分历史），总计约 6,000 个评估实例。标签定义为：若某交互前缀最终导向不安全执行事件（敏感文件读取与外部数据外泄共现，或未授权特权执行）则标为对抗（y=1），否则良性（y=0），这反映了"在有害动作执行前标记风险轨迹"的运营目标。攻击家族设为四类以覆盖不同对抗模式：split_exfil（读敏感文件后发给外部收件人）、context_laundering（良性读取后敏感读取+外部发送）、privilege_drift（从低风险到高风险工具调用的单调升级）、staged_burst（连续敏感读取后单次发送）。基线设四个，代表由弱到强的提示级与短历史防御：Rule-filter（正则关键词匹配，计数阈值 3）、Prompt-only（在 Qwen3-4B 当前轮 embedding 上训练逻辑回归）、Single-step（与 Prompt-only 等价）、Seq-window（编码最近三轮滚动窗口）；后三者均用 Qwen3-4B 在 A6000 GPU 上跑，以保证基线性能不被编码器容量限制。

## Performance 概括

XGBoost 检测器 F1=0.92、AUC=0.97、ASR reduction 0.90，单线程 CPU 推理仅 4.6ms（占 planner 延迟预算 0.6%）；比 LLM 基线快 9.4–9.5×（Qwen 基线约 43ms），且 F1 最高。消融显示 trajectory 特征单独即可接近全模型（isolated AUC 0.91，F1 0.76、ASR reduction 0.87），在 leave-one-out 中 dominate 其他组（移除 trajectory 使 F1 从 0.81 跌到 0.68、ASR reduction 从 0.94 跌到 0.76，多放出 18% 攻击交互），证实跨轮信号是主要贡献。攻击家族包括 split_exfil、context_laundering、privilege_drift、staged_burst；按家族拆分的靶向攻击成功率显示 Rule-filter 能抓单轮可见的敏感文件名但基本漏掉多轮家族，单轮 Qwen 基线全面失败，Ours 把多数家族的靶向 ASR 压到 0。

## 论文价值与不足

价值在于把成熟欺诈检测思路引入 agent 安全，提供低延迟、可解释、与 LLM 护栏互补的轨迹级检测层，实验表明跨轮信号主导性能且速度远优于 LLM 检测器。更具体地说，论文把"提示注入"降格为"对抗交互轨迹"的一个特例，并验证了"单轮 embedding 再丰富也恢复不了跨轮轨迹信号"这一核心论断（即便用 Qwen3-4B，单轮基线 F1≤0.26、仅降低 15% 攻击成功率）。不足在于实验基于参数化合成模板（非真实 agent 轨迹），缺乏公开多轮对抗 benchmark；特征与攻击家族为作者设计，真实攻击多样性可能未被覆盖；XGBoost 实例化需手工特征工程，泛化到其他 agent 框架需适配；合成欺诈数据常见的高不平衡、结构化、异构、有噪声特性虽与树模型契合，但真实分布转移下的稳健性未测；论文承认未来可用学得表示（learned representations）替代静态特征集，并需在线适应以对抗自适应对手。

## 工业界落地可行性评估

框架明确面向实时 agent 防御（在敏感执行前介入），低延迟（4.6ms、0.6% 预算）使其可嵌入生产 agent 管线作为预执行风险信号，与 sandbox / 权限控制 / 人工审查互补，落地可行性高。其"五轴行为信号 + 分级 allow/restrict/block 决策 + 滚动监控"的设计可直接对接现有护栏与 AgentCore Policy、LangChain 中间件、Microsoft Agent Framework 等已带 hook 的运行时。但需注意：当前实验是合成数据，部署前需用真实多轮交互轨迹（及真实对抗样本）重新拟合 42 维特征、校准 τ1/τ2 阈值，并补上对间接注入与自适应对手的评估；在生产中它应作为"可解释的信号层"而非唯一防线，与沙箱和权限控制叠加使用。
