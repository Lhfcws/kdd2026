# MADS-CPS: A Machine-Checkable Run-Level Evaluation Contract for Trustworthy Agentic Cyber-Physical Workflows

## 背景与 Idea
Agentic 网络物理系统（cyber-physical systems, CPS）把规划、工具调用、感知、协调与执行耦合在一起，单个组件故障会跨软件状态、物理状态和下游授权传播。相关工作把相关能力分散在能力评测（AgentBench、WebArena、τ-bench）、运行时遥测（OpenTelemetry、AgentTrace）、动作中介（AgentTrust 返回 allow/warn/block/review）与生命周期风险管控（NIST AI RMF、UL 4600、SACM 安全论证、SLSA/in-toto 来源）中。论文指出，这类部署还有一个任务成功率无法回答的“准入（admission）”问题：一次运行即使完成了任务，也可能缺少用于不可逆或权威状态切换所需的证据。准入判定依赖证据完整性、独立的报告重算、披露敏感谓词可用性，以及在发布边界的正确拒绝。原始 trace 只支持诊断，治理框架只组织生命周期控制，但缺少一个能把“一条记录下来的运行”与其“发布条件”连接起来的关系对象。

因此作者提出 MADS-CPS，一个机器可校验的“运行级（run-level）”评估契约。所谓 run-level（运行级）是指：把“一条记录下来的运行是否可被用于审计、控制面回放和发布”这一最小证据对象显式地定义出来，而不是评估整个智能体系统的宏观能力。其核心 idea 是把声明式保障包络（declared assurance envelope）与四类必需产物、独立重算谓词、单调一致层级、显式披露状态和 fail-closed 的 PONR（point-of-no-return，不可回退点）发布门禁绑定在一起。PONR 是不可回退点：指一次不可逆或权威性的状态切换（如提交处置、释放设备），在它之前必须有前置门禁、之后必须有唯一终态结果。论文强调“结构准入（structural admissibility）”与“物理真值（physical ground truth）”是两个分离的声明：被攻陷的采集路径可以伪造出内部自洽的 trace、report、bundle 与 manifest，从而暴露出“证据到世界”的脱节必须由部署配置（设备签名、安全时间、远程证明）来锚定。论文明确四项贡献：(1) 一个运行级证据契约，标准化产物、验证模式、回放等价策略、单调一致性层级与 fail-closed 发布语义；(2) 在证据边界定义的控制器无关一致性，除非改变了被声明谓词，否则排除控制器身份与隐藏优化状态；(3) 显式的信任与脱敏边界，在受限披露下保留可校验结构完整性、把物理真值绑定交给部署剖面；(4) 一个覆盖对抗一致性、披露敏感可审计性、独立重算、控制器压力与合成版本漂移的可执行评估。与相邻技术层相比，交互式 agent 基准、可观测性系统、运行时中介与风险/保障框架分别在能力测量、日志、动作级拦截、生命周期治理上侧重不同，而 MADS-CPS 补上的是“在声明式契约下一条记录运行的准入（run admissibility）”这一最小关系对象——它不替代这些层，而是作为它们可引用的运行级证据。

## 核心方法
每一条运行都输出四类标准化产物：结构化 trace（trace.json）、评估报告（eval_report.json）、证据包（evidence_bundle.json）和发布清单（release_manifest.json）。声明式包络 E=(s, v, P, ρ, τ) 固定了场景/剖面 s、验证模式 v、PONR 义务集 P、回放等价策略 ρ 与证据信任边界 τ。验证模式分 public / evaluator / regulator 三档：public 允许结构保持型脱敏（redaction），即保留事件序、类型、时间戳、承诺与完整性元数据，但撤下报告重算、控制面回放、PONR 语义所需载荷，此时这些谓词被标记为“不可用（unavailable）”而非成功或失败；evaluator/regulator 可要求可回放载荷与更强信任锚。回放等价 ρ 定义 L0（仅由记录状态转移重算决策与强制结果）与 L1（还消费记录观测）两级；连续信号允许声明规范化规则、数值容差与时间窗，避免良性浮点/时序变化造成误失败，又不默默接受未声明漂移。

一致性检查器从产物与包络的关系中计算分层裁决：Tier1 检查产物存在性/模式/跨产物链接（structOK，要求四个产物齐全、模式合法、run/scenario/模式版本/产物引用一致）；Tier2 进一步要求提交完整性（重算每个声明摘要、拒绝重复或含遍历路径、验证终态承诺）、报告重算等价（独立重算的 report 与原始 report 在 ρ 下等价 stateOK）与控制面终态重建；Tier3 则额外要求对所有 PONR 义务满足“恰好一个前置门禁、一个终态结果、二者一致、拒绝后无完成”的关系（ponrOK）。层级单调：Tier3 ⇒ Tier2 ⇒ Tier1。最后的 fail-closed 发布门禁只在所需层级成立时才授权状态切换（如空 PONR 义务的可声明 Tier2 为发布要求，未知场景直接判包络解析失败而非继承空义务集）；证据缺失或矛盾则直接拒绝，紧急覆盖是独立授权路径、绝不把失败判定改成通过。信任策略 τ 把“证据是否真实反映物理世界”交给部署配置（设备绑定签名、安全时间戳、远程证明、只追加存储、跨传感器校验或独立观测），从而在产物内部自洽时仍能识别“证据到世界”的脱节。契约的逐层判定由 structOK（产物齐全且模式合法、run/scenario/模式版本/产物引用一致）、commitOK（重算每个声明摘要、拒绝重复或含遍历路径、验证终态承诺）、reportOK（独立重算 report 与原 report 在 ρ 下等价）、stateOK（控制面终态重建）组合，再叠加每个 PONR 义务的 ponrOK（恰好一个前置门禁、一个终态结果、二者一致、拒绝后无完成）。验证按固定顺序推进：E1 先用 24 个预声明案例检验契约自身能否对注入的结构/语义/回放/报告/PONR 故障指派正确层级；E2 在不变更底层运行前提下改变披露模式，看哪些谓词仍可计算；E3 用独立进程验证器（不导入生产者度量实现、源码摘要固定）检验报告能否被独立重算，并以 110 个回放突变做定位压力测试；E4 在 480 次运行上检验协调冲击下证据可采性是否与生产力分离；E5 在 720 次运行上检验固定契约能否暴露合成版本回归。论文还强调 controller-agnostic conformance：固定 E 后，不同控制器只要在每个被读取谓词上一致就得到相同裁决，把评估与具体控制器能力解耦。

## Performance 概括
论文在机器人中心自主实验室（robot-centric autonomous-laboratory）的纯软件 thin slice 中通过 5 项研究和回放突变压力测试评估契约。E1 的 24 例对抗一致性语料（覆盖 9 个故障族：存在/模式、完整性、跨产物链接、包络解析、trace 语义、回放、报告重算、PONR 关系、阳性对照）与预声明结果达成 1.00 完全一致；E2 验证结构化脱敏在保留模式/链接/完整性的同时把报告重算等谓词标记为“不可用”而非成功或失败；E3 的独立进程验证器（不导入生产者度量实现、源码摘要固定）在两个场景各 20 个种子上核心报告重算一致率达到 1.00，110 个回放突变全部被精确定位；E4 在 480 次控制器-场景-机制运行上 conformance 与强回放均为 1.00，而协调冲击下 centralized 与 representative-CPS 适配器产品成功率分别为 0.55 和 0.00，说明证据可采性与生产力可分离；E5 的 720 次合成版本漂移研究中 conformance/回放保持 1.00，但回归条件下产品成功率从 0.7208 降至 0.6375。可复现性方面，硬化实现定钉于 commit 1e84f8e…，结果定钉于 ab4ad06…，81 个聚焦 P0/P3 测试零失败。

## 论文价值与不足
价值在于首次把“单条运行的结构性准入”做成机器可判定、外部可检视的最小证据对象，并以单调层级、控制器无关一致性和显式信任/脱敏边界把评估与具体控制器能力解耦，方法论上紧扣证据有效性与可复现性。其“结构准入 ≠ 物理真值”的区分尤其关键，避免了“内部自洽即安全”的过度声明。不足主要有：全部评估在纯软件合成工作流中进行，未含真实传感器噪声、丢包、时延与连续物理信号（ρ 的容差策略需领域标定）；24 例和 110 突变属于设计性测试，分布不同于真实攻击分布，且完全被攻陷、掌握可信签名的证据生产者不在威胁模型内；PONR 门禁只覆盖前置/发布边界，持续稳定控制与物理急停仍由运行时安全控制器负责；E4 两适配器共享同一模拟器且仅在有限接口变体上。讨论部分强调，稳定的契约裁决表示接口级有效性，并不暗示稳定的能力或安全的物理行为——E4 中两个适配器都发出内部可准入证据，但 centralized 完成 55% 种子、representative-CPS 在每个种子上都于调度门禁拒绝（安全不生产），说明证据层不变性对受测接口变体成立、而控制器能力在裁决之外。组合上，OpenTelemetry 兼容 span 可填充规范化 trace 事件，经签名的运行时裁决提供动作级证据，provenance 证明把包绑定到执行环境，SACM 或行业安全案例可引用运行裁决；信任边界决定最强可辩护主张：哈希与回放保护捕获后的一致性，而传感器真值取决于 τ 中声明的“证据到世界”绑定，缺失信任锚会产生“物理真值绑定失败”即使包内部有效。作者还列出具体局限：评估用纯软件合成工作流，真实传感器会引入噪声、标定误差、丢包、时延与环境非确定性；PONR 门禁仅在前置/发布边界运作，持续工厂稳定、轨迹中断与紧急停车仍由运行时安全控制器与物理联锁负责；24 案例与 110 突变是设计性测试、分布不同于运行攻击分布；完全掌控可信签名材料的被攻陷证据生产者不在已演示威胁模型内。

## 工业界落地可行性评估
该契约面向高风险网络物理部署（自主实验室、机器人、工业控制）具有明确的落地价值：其 fail-closed 发布门禁、独立重算和声明式信任锚（设备签名、安全时间、远程证明、独立观测）可直接嵌入现有 OpenTelemetry 遥测、SLSA/in-toto 来源与 SACM/UL 4600 安全论证流程，作为合规与安全论证可引用的运行级证据。组合方式上，OpenTelemetry 兼容 span 可填充规范化 trace 事件，经签名的运行时裁决提供动作级证据，provenance 证明把包绑定到执行环境，SACM 或行业安全案例可引用运行裁决。但落地仍需补足真实硬件在环、独立实现的生产者、被攻陷采集路径与传感器欺骗等验证，并将连续物理信号的回放容差留给领域专家标定；本质上它是一个“证据基座”，物理真值、持续运行时安全与认证仍需周边保障系统承担，因此适合作为现有治理栈的接口层而非独立解决方案。可复现性被显式绑定：硬化实现定钉于 commit 1e84f8e…、生成结果定钉于 ab4ad06…，81 个聚焦 P0/P3 测试零失败，发布清单记录确切实验命令、独立验证器摘要、GitHub Actions 运行与每个表生成产物的 SHA-256 摘要，所有 camera-ready 数值都从这些可执行产物生成并绑定到清单。对高风险部署，部署剖面应要求相关设备身份、经认证的测量、安全时间、经证明的执行、只追加存储或独立观测作为信任锚；缺失信任锚会产生物理真值绑定失败（即使包内部有效）——这意味着该契约必须嵌入既有的 OpenTelemetry 遥测、SLSA/in-toto 来源与 SACM/UL 4600 安全论证流程才能发挥价值，而非作为独立解决方案。
