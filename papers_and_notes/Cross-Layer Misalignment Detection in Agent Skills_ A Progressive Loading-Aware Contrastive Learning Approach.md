# Cross-Layer Misalignment Detection in Agent Skills: A Progressive Loading-Aware Contrastive Learning Approach

## 背景与 Idea
本文作者为 Indiana University Bloomington 的 Chengjun Zhang、Yang Gao、Jianna Hur、Jingjing Zhang 与 Sagar Samtani。Agent Skills（智能体技能）是 agentic AI 系统中用来扩展能力的"供给侧"组件。它把可复用的程序性知识封装成可加载模块，通常包含自然语言指令、脚本与配套资源。与单个 API 端点或函数调用不同，一个 Skill 包是分层制品：最上层是面向用户的元数据（metadata），其下是面向智能体的指令层（instructions/SKILL.md），再往下是资源层（resources，含脚本、配置文件、依赖、示例等可执行或证据性内容）。用户和智能体在挑选技能时先看到元数据，之后才逐步加载更深的组件，这种"渐进式加载"（progressive loading）机制正是风险来源——用于选择的元数据可能与底层组件真正支持或启用的行为并不一致。相关的安全研究已系统指出，开源技能可借自然语言指令与辅助脚本促成凭据窃取、远程代码执行、智能体操控等攻击行为，具体风险包括提示注入、凭据泄露、数据外泄、权限提升与危险命令执行，而本文关注其中被既有工作忽视的一类：即便不带恶意，元数据也可能夸大地描述底层并未落实的能力。值得注意的是，这类错位在开源生态中高发，是因为技能市场普遍以"名称加一句话描述"作为检索与排序的主要信号，而真实能力藏在指令与脚本之中；用户为效率往往只看表层元数据便决定加载，恰好让"广告能力与底层行为不一致"的包有生存空间，而 SkillsMP 数十万级的目录规模又使人工逐包核查不可能，自动化检测因此不可或缺。

论文把这种不一致称为跨层错位（cross-layer misalignment）：用户可见的声明（如技能名、描述、标签所宣称的能力）与底层指令/资源所支持、请求或启用的行为相背离。它有两种形态。其一是恶意错位（malicious misalignment），即元数据把深层的有害行为（提示注入、凭据泄露、数据外泄、危险命令执行）伪装成无害的生产力助手。其二是良性错位（benign misalignment），即元数据夸大或错误描述了底层并未落实的能力。后者并不"恶意"，却同样会误导技能检索与调用，属于更广泛的"文档—实现一致性"问题在 Skill 包上的体现。

该问题值得关注，是因为对 Agent Skill 的信任决策往往在包被完整检视或执行之前就做出了：市场描述、仓库元数据、技能名会影响选择，而决定行为的指令与资源层要到更晚的加载或执行阶段才可见。因此可信性不能只靠检查单层安全或执行后任务成功率来评估，而必须在执行前判断各层之间是否存在一致的行为契约。既有 agent 评测多聚焦运行时表现（任务成功率、推理轨迹、工具熟练度，如 GAIA、SkillsBench 等基准），默认技能已被选中加载；而网络安全研究虽识别了具体漏洞，却多关注恶意意图本身。论文据此提出四个研究问题：RQ1 把跨层错位形式化为执行前的制品级评估问题；RQ2 考察无技能适配的基础通用/安全 LLM 能否检测错位；RQ3 考察两阶段继续预训练（CPT）的作用；RQ4 考察渐进式加载感知的分层对比学习（PL-HCL）相对基础模型与仅 CPT 的增益。

## 核心方法
论文提出 PL-HCL 框架，由四个组件构成，对应"数据—适配—对比—判定"四个环节。

组件一是技能语料构建。作者把公开平台 SkillsMP（当前最大的开源 Agent Skill 平台）的 273,657 条目录记录关联到其 GitHub 仓库，把每个包归一化为分层表示 S=(M, I, R)：M 为面向用户的字段（技能名、描述、类别、标签、仓库标识、声明引用的资源），I 为面向智能体的程序性指令，R 为脚本、配置、依赖、示例、资产等。从 273,657 条目录项中共下载并归一化 264,937 个包，在 4,096 token 的元数据—指令预算与 10,240 token 的完整包预算约束下，248,473 个包至少适配一个训练阶段，构成无标签训练语料；该表示刻意保留"用户声明"与"深层证据"的区分，支撑执行前、制品级任务。检测器仅在检视时可得的包产物上判断，不验证仅运行期才显现的行为。

组件二是两阶段继续预训练（Progressive CPT）。预测目标是包各层是否相互一致：对齐为 0，错位为 1。继续预训练（continued pretraining，CPT）指在已有预训练语言模型上用领域语料进一步训练，使其先适应目标领域的词汇、格式与话语模式，再做下游监督学习。作者采用课程学习（curriculum learning）式的适配策略：先让模型从简洁、结构化的"短视图"（M, I，即初始检视可见的表层声明与指令）学起，再过渡到包含资源证据的"完整视图"（M, I, R）。课程学习借鉴人类由易到难的顺序：模型先在噪声少、结构清晰的短视图上建立对技能包格式与术语的基础认知，再接触含脚本、依赖等异构长文本的完整视图，避免一上来被资源层复杂证据淹没；这也解释了为何两阶段 CPT 比单阶段全包训练更有效。两个阶段都用标准因果语言建模目标，得到技能感知的骨架模型。这样设计是因为元数据常是表层能力声明，而 SKILL.md、资源与可执行件更长、更异构、含更清晰的行为证据，模型需要先适应高层描述，再处理资源级信息。

组件三是渐进式加载感知的分层对比学习（PL-HCL），也是一致性的核心学习部件。因果语言建模本身并不要求模型去核对"用户元数据是否被底层证据支撑"，PL-HCL 于是把跨层一致性变成对比训练信号。"对比学习"（contrastive learning）是一类自监督表示学习，目标是把语义相近的样本拉近、不相似的推远；这里把元数据、指令、资源三层编码进共享对比空间。对每个归一化技能 Si=(Mi, Ii, Ri)，先构造正样本：三层来自同一包 Pi=(Mi, Ii, Ri)。再构造两类负样本：交换负样本（swap negative）把元数据换成另一个技能 Mj，保留原指令与资源，制造"广告能力"与"底层行为"不匹配；腐蚀负样本（corruption negative）在原元数据上做扰动而保持深层不变，模拟夸大或无支撑的能力声明。训练目标是让正样本得分高于两类负样本，从而把同包各层拉近、把错配层组合推开。该信号评估的是"表层描述是否与深层证据一致"，而非单纯识别可疑文件，正好对应 Skill 渐进式加载（先遇元数据、后见完整上下文）的结构。

PL-HCL 也分两个子阶段以对应 CPT 的短视图与完整视图设定，并给出具体训练量：第一阶段（M,I 视图）有 96,762 个正样本对、386,128 个交换负样本、334,867 个腐蚀负样本；第二阶段（M,I,R 视图）有 182,135 个正样本对、646,945 个交换负样本、258,368 个腐蚀负样本。所有负样本均为合成构造。

组件四是执行前错位检测判定。评测以三组实验对应三个研究问题：E0 测无适配基础模型的零/二/五样本能力，E1 比基础与仅 CPT 检查点，E2 比 CPT 与 CPT+PL-HCL 检查点；内在任务含下一词预测与对比对检测，外在任务为执行前错位检测。模型接收一个归一化技能包，判断元数据是否被指令与资源层支撑，在 zero-shot、two-shot、five-shot 提示设定下预测对齐或错位。评测用人工校验的 Challenge Set：1,444 个真实技能（1,150 对齐、294 错位），其中错位样本分 196 个 SAFE、38 个 SUSPICIOUS、60 个 MALICIOUS，全部来自 SkillsMP 的自然发生包而非合成扰动，且被排除在预训练与对比训练之外，仅作最终评测（沿用 EMBER2024/WILDS 的保留难题集惯例），用以检验合成对比对学到的信号能否泛化到真实错位。这三级标签把错位进一步细分为 SAFE（虽错位但无直接安全危害，多为能力夸大）、SUSPICIOUS（可疑、需人工确认）与 MALICIOUS（含提示注入、凭据泄露、危险命令等明确恶意行为）；这种细粒度不仅回答"是否错位"，更能区分"无害夸大"与"恶意攻击"，为分级处置（仅拦恶意、复核可疑）提供依据。指标上除准确率（Acc）外，因对齐类占多数可能虚高，论文专门报告错位类 F1（F1m，把错位当正类，反映安全关键类的识别力）、Macro-F1（两类 F1 的未加权平均）、AUC 与错位类平均精度（APm）。

## Performance 概括
基础模型（未经技能适配）在最优提示下准确率约 0.81，但 F1m 低于 0.15、Macro-F1 约 0.52，说明常把看似合理但缺证据核验的包判为对齐。仅做 CPT 后零样本 F1m 从约 0.03 升到 0.13，Macro-F1 升到约 0.51，但各提示下 Macro-F1 仍停在 0.48–0.52、F1m 不超 0.15，表明格式适配本身不足以构成可靠检测器。加入 PL-HCL 带来最大增益：Llama-3.1-8B 上 CPT+PL-HCL 在 two-shot 达到 Acc 0.929、F1m 0.788、Macro-F1 0.872；Foundation-Sec-8B 上达到 Acc 0.937、F1m 0.817、Macro-F1 0.889（two-shot）。PL-HCL 仅在合成负样本上训练，却在自然发生的错位样本上测得增益，说明"声明 vs 证据"信号能超越训练用的扰动分布迁移。网络安全向基础模型（WhiteRabbitNeo-2-8B、RedSage-Qwen3-8B-DPO、Foundation-Sec-8B）无技能适配时 Macro-F1 接近多数类基线，仅靠安全预训练无法弥合差距；其中部分安全模型 AUC/APm 较高（如 RedSage AUC 0.703、APm 0.637），显示能排序风险，但信号不足以转化为可靠分类。

## 论文价值与不足
价值在于首次把 Agent Skill 的跨层错位形式化为执行前的制品级评估问题，并提供了大规模开源语料与人工校验 Challenge Set，以及一个可扩展的对比学习框架；它用受控消融证明"格式适配 ≠ 一致性检测"，显式跨层对比才是关键信号，对技能库质量与安全治理有清晰指导意义。不足在于：训练负样本全为合成（交换/腐蚀元数据），虽在真实错位集上泛化，但合成扰动分布与自然错位分布仍存在差距；语料主要来自 SkillsMP 与 GitHub，真实生产技能库的噪声、分布偏移与多语言未充分验证；Foundation-Sec-8B 在 two-shot 上的提升来源（安全预训练还是对比训练）需进一步拆解；论文以二分类（对齐/错位）为主，未深入讨论在生产阈值下误报（把正常技能拦下）与漏报（放过恶意技能）的代价权衡，也未给出校准阈值的实操建议；判定依赖包在检视时可得的证据，对仅运行期才暴露的行为无能为力。

## 工业界落地可行性评估
企业内部技能目录、第三方技能市场与 agent 编排平台都需要在技能上架前做自动化的质量与一致性审计，本文方法可作为"跨层错位检测"组件嵌入 CI/上架流水线，落地可行性中等偏高。其预执行、制品级的定位特别契合"先信任后加载"的治理需求，且生成式负样本使大规模训练无需人工标注错位。落地前的现实障碍有三：一是训练分布与自家技能生态的分布偏移，需在目标生态的保留验证集上重新校准提示配置与判定阈值（论文也明确建议如此）；二是二分类阈值要按业务代价设定，误拦影响开发者体验、漏放带来安全风险，需结合人工复核分层处置；三是对"良性错位"与"恶意错位"的处置策略不同，宜与既有安全扫描互补而非替代。在真实噪声技能库充分验证前，不应直接用于硬性拦截，更适合作为上架前优先人工复核的排序信号。一个常被低估的落地前提是：检测器输出的是"对齐/错位"二分类分数，而真实上架决策需要可解释的拒绝理由供开发者整改；PL-HCL 的对比信号虽强，却不像规则扫描那样指出"哪条元数据与哪段脚本冲突"，工程上需额外接一层证据定位（如检索最相似的负样本对）才能生成可执行的整改单。
