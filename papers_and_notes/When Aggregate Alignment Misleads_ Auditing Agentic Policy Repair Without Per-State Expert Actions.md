# When Aggregate Alignment Misleads: Auditing Agentic Policy Repair Without Per-State Expert Actions

## 背景与 Idea

代理式人工智能系统越来越多地被用来修改、精修和修复决策策略，而不只是回答问题或产出文本。这类系统的输出不再是单一标签或预测，而是对一个决策策略本身的"干预"——它写代码、调整运营规则、更新工作流、提出策略补丁。这就带来一个新的评估难题：智能体的产出是一个对象（策略），评估者必须判断这次"策略修复"（policy repair）是否可信，而此时智能体手里并没有逐状态的专家动作标签（per-state expert action labels）。要理解这个术语为何关键，需要先区分三类训练设定。其一是标准模仿学习（imitation learning）：学习器可以观察专家在每个状态下给出的具体动作（state-action pair），从而直接复制行为。其二是奖励优化（reward optimization）：学习器收到一个标量目标，朝着最大化该目标去调整策略。其三正是本文的"诊断反馈修复"（diagnostic-feedback repair）：智能体既看不到基准在每个状态下的动作，也拿不到基准源码、奖励数值或留出结果，它只收到一份"聚合行为摘要"——这份摘要会说某个状态空间区域过量或不足地使用了某些动作，但不会告诉你在某个具体状态下该采取什么动作。换句话说，信号从"逐状态的正确答案"降级成了"区域级的分布差异"。

作者以酒店动态定价作为受控测试床来研究这个问题。被编辑的策略是一张按"时间×库存×市场"三维索引的目标动作表（target-action table），每个表项对应一个价格动作；基准策略是一个固定的、基于规则的收益管理（revenue management，简称 RM）参考策略。这里要解释 RM 是什么：它是一套在酒店/航空/零售行业长期使用的定价纪律，目标是根据需求与剩余库存动态调整价格以最大化收益。本文的基准规则结合了"针对参考对手价格的短视期望收益价格"（myopic expected-revenue price）和"库存节奏下限"（inventory-pace floor）——当已售库存跑在目标曲线前面时，抬高最低可接受价格，防止过早低价抛售。需要强调的是，这个基准只是"行为参考"而非"全局最优证书"：作者刻意选择去审计一个非最优基准，因为真实运营中，运营者关心的往往不只是收入最大化，还包括策略是否保持可预测、可解释、以及符合一条已审批规则的定性行为。一个只看收入的审计可能接受一个行为纪律已经漂移的策略，而本文要评估的是"修复是否保留了有益的行为结构、同时维持或改善结果"。

本文要回答的核心问题是：在缺失逐状态专家动作、奖励数值、留出结果的前提下，仅靠区域级诊断反馈，一个编辑器能否产出既在闭环收入上接近基准、又在行为上保持基准结构的修复？关键风险叫做"聚合对齐误导"（aggregate alignment misleads）。它的含义是：一个策略编辑器可以让整体动作分布看起来与基准相似，却在轨迹级（trajectory-level）的价格构成上失败。在定价场景里，这意味着它用了正确的全局价格组合，却把这些价格错误地放在了不同的预订情节（booking episodes）中。更一般地，修复后的策略可能匹配了"边际动作分布"（marginal action distribution），却仍然通不过以轨迹为单位的更细粒度行为审计。作者因此主张，这类的审计不能依赖单一聚合指标，因为同一策略可能在一个审计口径下很强，却在收入或另一个行为口径下失败。

## 核心方法

实验运行在一个酒店定价模拟器上。被编辑的策略是一张目标动作表，形状为 30（时间）× 30（库存）× 10（市场），起始为一张常数表；基准策略只在诊断比较和留出审计时可用，编辑器在训练过程中看不到它。每个修复迭代中，当前策略在训练情节上 rollout，其动作分布与基准策略在每个诊断区域内比较，生成一份"诊断报告"，说明当前策略在哪些区域过量或不足地使用了某些动作区间。编辑器据此提出一个补丁；合法补丁只能对目标动作表项做"矩形整数位移"（rectangular integer-shift）编辑，最多 16 次更新，允许的操作是 shift_region 与 set_region，作用于半开矩形区间。模拟器参数、市场边界、分箱边界、温度参数、指标与策略类别都不可变，无效编辑被拒绝。编辑器不能修改基准策略、奖励函数、指标定义或评估器，这把任务锁成了一个"诊断反馈评估设定"。

诊断被设计为 12 个区域，由时间、库存、市场的 2×2×3 划分构成，每个区域报告该策略相对于基准的动作分布失配。论文刻意设置了一组信息约束：不给编辑者逐状态基准动作、不给基准源码、不给奖励/RevPAR/入住率/ADR/留出结果、不给环境参数，最终指标只在留出生产情节上计算一次。这些约束对应一个明确的"威胁模型"（threat model）：逐状态动作标签泄漏会让任务退化成模仿而非诊断修复；奖励数值泄漏会让编辑器直接优化结果而非使用诊断；允许改指标/模拟器/策略类会让"改善"未必来自修复；选择器与最终审计用同一批情节会产生选择噪声；任何看似合理的诊断提示都能用则意味着诊断信号没在做语义工作——后两点分别由"选择器仅用训练诊断、最终数字仅用留出情节一次"和"打乱诊断安慰剂"来封堵。

论文对比了三类编辑器。第一是诊断投影（diagnostic projection）：把诊断动作分布直接机械地映射进目标动作表，是一个"强而便宜"的基线，用于衡量不靠语言模型生成、仅机械转换诊断摘要能恢复多少；它不是形式化神谕，因为它不会在可行表空间上搜索。第二是树搜索编辑器（tree-search editor）：用相同补丁语法和诊断结构做非语义搜索（500 次候选评估、束宽 5、分支因子 10、最终前 5 重评估），用来检验"仅靠诊断表示和编辑语法、不需要语言模型提议结构"是否足够；它主要作为非语义诊断消费者和指标压力测试，而非用来证明某种提议架构优于另一种。第三是多重启 LLM 编辑器（multi-restart LLM editor）：主干用 DeepSeek-V4-Flash、temperature 0、JSON 响应模式、思考关闭、最大 2048 输出 token；共 125 次重启 × 20 次迭代 × 每轮 1 个候选，得到 2500 个候选；每个重启从同一常数策略出发、使用互不相交的 100 种子训练划分，重启最优候选在 500 种子选择器池上用"聚合 D1 + Jensen-Shannon 散度"重新打分；最终指标只在 5000 条留出生产情节上报告一次。提示被结构化为四个块：指令块（允许的 JSON 键与补丁操作）、策略摘要块（策略类、表形状、动作直方图、区域块众数）、重启块（仅重启标识）、诊断块（12 区域 schema、聚合 D1 与 JS 值、含支持计数/当前与参考动作直方图/平均动作差距/推荐位移方向的前排区域记录）；提示中不含奖励、RevPAR、入住率、ADR、留出结果、基准源码或逐状态基准动作。

评估同时使用运营指标与行为指标两类。RevPAR（每可售房收入，等于总收益除以总可售房数）、入住率（已售房除以可售房）、ADR（已售房平均房价，等于 RevPAR 除以入住率）衡量运营表现。行为方面使用三种 D1 距离：两个离散动作直方图的 L1 距离，值域为 [0,2]，0 表示动作分布完全相同。池化 D1（pooled D1）在把每个策略自身 rollout 的所有留出情节聚合后，衡量全局动作组合是否与基准一致。情节 D1（episode D1）在每个留出情节的轨迹内计算动作分布距离并取平均，虽然是边际直方图指标，但单位更细，能捕捉"全局组合对、单个情节构成不同"。参考状态 D1（reference-state D1）是一个反事实压力测试：在留出种子上重放基准策略，把基准访问到的状态归入相同的 12 个诊断区域，再评估被编辑策略在"基准访问到的状态"上的动作分布；它回答的是"被编辑策略在基准状态分布下会如何行动"，与池化/情节 D1 条件化的单位、乃至状态分布都不同，因此论文把它当作压力测试而非主要成功指标。这三者刻意互补：论文指出一个策略可以在其中某一项对齐却在另一项失败。

为了排除替代解释，论文设了两类对照。其一是打乱诊断安慰剂（shuffled-diagnostic placebo）：保留提示格式、补丁语法和选择机制，但把诊断内容在不同区域坐标间打乱，使一个区域的失配摘要可能出现在另一个区域之下，区域—错误对应关系被破坏；评分与选择仍用真实诊断，因此这是一个"机制安慰剂"而非算力匹配的排行榜跑分。其二是算力匹配的非语义提议器（compute-matched nonsemantic proposers）：随机区域提议器与诊断引导区域提议器，使用相同诊断结构、补丁语法、选择器目标、以及最高 2500 次候选评估预算，用来检验"结果是否仅仅来自重启搜索而非语言模型的提议结构"。所有被报告策略都在同一 5000 条留出生产情节上审计，候选生成与选择使用非生产诊断，生产留出结果只在选择后使用一次——这把"策略修复"与"奖励泄漏/标签泄漏/评估器操纵"隔离开来。

论文还做了一组稳健性与审计检查来加固结论。重启预算检查显示，LLM 编辑器的表现随重启次数增加而变好，最优策略只在对足够多独立重启后才出现，这支持"多重启编辑器"而非"单一修复轨迹"的设计。选择器敏感性检查显示，主行为选择器（聚合 D1 + JS 散度）与"仅 D1""仅 JS 散度"选出的候选一致，论文承认这形成了一个张力——选择器本身仍是边际行为目标，而论文主张边际目标不完整，因此把选择仅作为协议的一个阶段，并要求最终留出审计同时包含 outcome、pooled、episode 组成与 reference-state D1。为排除"结果只是重启搜索"，论文跑了最高 2500 次评估的非语义提议器（随机区域提议器 RevPAR 93.90、诊断引导区域提议器 RevPAR 99.70），二者 pooled/reference-state D1 可能低于 LLM 编辑器，反而强化了"行为距离好看、闭环收入与轨迹构成却失败"的核心论点。候选多样性方面，2500 个候选中产生 480 个唯一策略、125 个重启最优策略中有 69 个唯一，说明编辑器并非在所有重启中重复同一补丁。决策空间锁定（提示排除标签/源码/奖励/留出/环境参数，补丁只改目标动作表）与上述检查共同支持"诊断反馈解释"而非"奖励泄漏/标签泄漏/评估器操纵"。作为稳健性的补充，论文还用 Wasserstein-1 距离（推土机距离，以美元计）重算分布比较，定性结论不变：池化 W1 仍把树搜索排在 LLM 之前（3.66 对 6.05），情节 W1 仍把 LLM 排在非基准策略之首（10.37 对投影 11.23、树搜索 15.18），参考状态 W1 仍把树搜索排在 LLM 之前（6.04 对 16.69），说明"指标相互不服"不是分类 L1 距离的假象。

## Performance 概括

LLM 编辑器将 RevPAR 从 102.75 提至 108.47（基准 108.75），paired gap -0.276（95% CI 跨零 [-0.692,0.146]）；episode-composition distance 从 1.153 降至 0.609（最强非基准结果），但 reference-state D1 1.197 差于基线 1.153。tree-search 达到最强 pooled D1 0.214、ref-state D1 0.328，却 RevPAR 跌至 98.91。diagnostic projection 达 RevPAR 107.90。非语义 proposer（≤2,500 评估）落后 8.77–14.57 RevPAR；shuffled diagnostic 崩溃至 RevPAR 94.30（破坏区域—错误对应后 pooled 对齐仍看似良好）。

## 论文价值与不足

价值在于揭示"聚合对齐误导"——policy 在边际动作分布上像基准，却在轨迹级组成与收入上失败；提出多粒度行为审计 + 诊断 placebo 对照协议，证明 LLM 编辑能用区域诊断产生近基准闭环收入（非仅靠重启搜索或提示格式）。更具体地，论文给出了一条"证据链"：主留出审计说明 LLM 编辑达到接近基准的 paired RevPAR gap（置信区间跨零）且拿到非基准编辑器中最强的 episode 组成距离；非语义提议器与打乱诊断两个对照分别排除了"重启搜索"与"提示格式合理"两种替代解释；树搜索则演示了"仅优化行为距离也会在收入上翻车"的失败模式。不足在于：仅单一模拟器与单一基准策略；主 LLM 结果仅一次生产运行（DeepSeek 无 seed，运行级方差未测）；LLM 在 reference-state 上仍有显著残差距离，而 episode D1 虽比 pooled D1 更严，但仍只是轨迹级边际指标而非逐状态模仿；target-action 表仅为一种策略表示，其它策略类可能需要不同的补丁语法与审计指标；打乱诊断对照规模小于主 LLM 跑分；非语义提议器虽降低"重启搜索本身解释 LLM 结果"的担忧，但未穷尽所有手工启发式。

## 工业界落地可行性评估

论文将协议定位为"离线 policy-repair 助手"而非自主部署决策者：LLM 提补丁，外部校验/评分/选择/审计，需留出审计后才影子/金丝雀部署。工程落地路径清晰——一个工程化 dashboard 应同时报 outcome 与多层行为距离（pooled D1、episode 组成距离、reference-state D1、诊断安慰剂表现、补丁合法性、训练—留出差距），否则只看奖励会漏掉行为漂移，只看池化动作距离会漏掉轨迹级失败。落地可行性中等偏高；主要障碍是需要在具体业务域里定义"基准行为纪律"与诊断区域 schema，并构建受约束的补丁语法与留出审计管线，这比单纯跑一个排行榜昂贵但可控。
