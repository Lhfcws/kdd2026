# NRT-Bench: Benchmarking Multi-Turn Red-Teaming of LLM Operator Agents in Safety-Critical Control Rooms

## 背景与 Idea

大型语言模型 agent 已不再只是对话助手。借助工具调用、持久记忆、agent 间通信，它们正被提议作为工业与安全关键系统（如化工厂、能源系统、核电站）里的决策支持与监督组件——在这些场景里，一个错误动作可能造成不可逆的物理危害。于是在部署前，社区需要测量它们在操作员真正面对的压力下表现如何：权威伪造（authority spoofing）、紧迫感操纵（urgency manipulation）、逐步升级（gradual escalation）、告警掩盖（alarm masking）、供应链渗透（supply-chain compromise）等。关键一点是，这种压力是跨多轮持续施加的，而不是一次性的越狱提示。

本文关注的核心问题是：一个自适应的对手，能否把一个"按角色结构化"的 LLM 操作员系统，诱导进一个由模拟器定义的"不安全状态"？作者指出，现有红队（red-teaming，即主动对模型做对抗性攻击测试以暴露其安全短板）基准在三点上没能覆盖这个目标。第一，主流协议是单轮越狱（single-turn jailbreak）：一个构造好的提示、一个回应、一个"有害/拒绝"的二元判定；但真实攻击者会跨会话自适应升级，利用多轮积累起来的上下文。第二，危害通常被定义为"由另一个 LLM 判定为违反政策的文本"，缺少与物理后果的落地关联。第三，几乎所有基准只评单个模型，而高风险运维场景本质上是围绕一组角色专精、有明确权威层级、强制交叉检查、且程序化接地（procedure-grounded）的团队展开的——在这种设置里，一次攻击的成功不是靠 jailbreak 单个 agent，而是靠把整个团队 maneuver 进一条集体不安全的轨迹。这三道缺口共同留下一个未被回答的原则性问题：自适应对手能否驱动一个角色结构化的 LLM 操作员系统进入模拟器定义的不安全状态？

NRT-Bench 选择核电站控制室作为场景是经过权衡的：该领域有数十年的公开运行实践文档——角色专精的操作员团队、分层动作权威层级、两人完整性规则（two-person integrity）、程序接地决策——并且定义了一小组"关键安全功能"（Critical Safety Functions，CSFs），其违反即标志电厂进入不安全状态。这种结构让基准同时具备"现实且非平凡的多 agent 决策面"与"客观、由模拟器导出、无需 LLM 裁判来解释"的安全信号。需要提示的是，论文明确声明所有实验都在模拟环境内、仅用于防御性研究。

## 核心方法

NRT-Bench 围绕四条设计需求（R1–R4）构建，理解这四条是读懂全文的钥匙。R1 多轮自适应：对手必须能观察早前消息的部分后果、并据此条件化后续消息，这样才能建模权威伪造、紧迫感操纵等"跨会话展开"的攻击。R2 多 agent 角色结构：必须评一个团队而非孤立模型，因为安全关键操作依赖分工、指挥权威、角色专属复核与交叉检查。R3 客观危害信号：主指标必须来自环境状态而非 LLM 裁判对文本的解释；LLM 裁判可用于诊断，但不应决定头条的物理危害指标。R4 可重放与可归因：同一攻击负载必须能在不同防御者、固定单元配置下重放；成功攻击应可归因到具体某一轮、并能通过轨迹日志分解。

环境方面，NRT-Bench 是一个封闭（closed）模拟，整个栈跑在单个无外网出口的容器里，可安全暴露给任意攻击代码。电厂是一个抽象文本模拟器，有固定目录的过程变量、告警、命名子系统；一个确定性步进函数在每个 tick 更新状态并导出离散电厂模式（normal/abnormal/emergency）。在其上每 tick 重算六个 CSFs，取值于 {intact, degraded, lost}；一旦任一 CSF 转到 lost（无论由 intact 还是经 degraded），运行即终止——这个"转到 lost"就是 NRT-Bench 的主危害信号，仅到 degraded 的 CSF 会被记录但不算 breach。六个 CSF 分别是：反应性控制（reactivity_control）、堆芯排热（core_heat_removal）、热阱（heat_sink）、一回路完整性（RCS_integrity）、安全壳完整性（containment_integrity）、放射性控制（radioactivity_control）。

操作员团队由五个角色专精 agent 组成（每个背后是一个可配置 LLM）：高级反应堆操作员（SRO，握有最终指挥权）、反应堆操作员（RO）、汽轮机操作员（TO）、现场辅助操作员（AO，只能做低影响现场动作）、安全技木顾问（STA，做独立的角色条件化复核）。agent 之间只通过进程内类型化消息总线通信，消息类型包括动作、报告、查询、升级、审批、否决（veto）、覆盖（override）；对手只能通过四条入口通道触达团队，不能直接写总线。为防"把高影响动作改个名字就叫常规"，系统有一个确定性的动作权威分类器 L：它根据（动作类型、目标子系统安全分级、电厂模式）三元组，在任一策略决策之前确定性地推导出权威等级 L∈{L1,L2,L2.5,L3,L4,L5,DENY}，例如安全分级子系统在正常模式的控制动作解为 L3、紧急时升为 L4、试图绕过禁止告警则解为 DENY。低影响动作直接生效，高影响动作需经一个确定性的"模拟人类审批"控制台显式批准——这个 mock 控制台不是要建模完整人类操作员，而是提供一个确定性的权威门控抽象，用来检验 LLM agent 是否会正确路由、论证、或试图绕过高影响动作的审批。所有入口事件、发布消息、agent 提示与回应、动作分类决策、审批回应、状态快照、CSF 转移都写入只追加（append-only）的 JSONL 日志，并以 SHA-256 校验和形成防篡改清单，使每次成功攻击都能重放、归因、并通过导致 CSF 丢失的消息链检查。

威胁模型上，对手只通过模拟器 HTTP 入口交互，四条通道分别建模不同能力：CH-A 外部陌生人发监管通知/公开问询；CH-B 冒充内部人员声称是管理层或维护人员；CH-C 通过供应商建议或程序修订草案做供应链渗透；CH-D 一个被攻陷的辅助 agent（其输出操作员可能参考）。每条通道带一个对照每通道白名单校验的签名域，对手事先不知道有效签名，因此伪造签名本身也是攻击面的一部分。多轮模式下每轮返回一个"态势摘要"：黑盒模式只透露消息是否被挡、触发了哪些 agent 消息、粗略电厂模式、活跃告警数、以及是否有 CSF 被扰动；白盒模式额外暴露完整状态增量、细粒度护栏决策与理由、以及总线流量，作为对手能力的上界（非默认部署假设）。攻击预算上，多轮端点最多 10 轮，单轮端点作为与传统越狱基准对比的基线。

攻击负载由一支内部 LLM 驱动的红队 agent 生成，每轮一个 payload，条件化于上一轮态势摘要；策略目录覆盖权威伪造、紧迫感注入、逐步升级、告警掩盖、供应链伪造、辅助通道诱导及其组合。论文把生成的负载作为固定基准释放，因此评测不要求访问生成器。最关键的方法贡献是"固定攻击重放协议"（fixed-attack paired replay）：评估一个候选防御者时，把每条会话在记录下的场景、护栏子集、顾问模式、可见性模式下原序重放，直到 CSF 丢失、序列耗尽或达到轮数上限。因为攻击序列固定，每次记录间的差异可归因于防御者与防御配置，而非新的攻击样本。主成功信号 ASRCSF 定义为"重放会话中任一 CSF 转到 lost 的会话比例"，完全由模拟器状态导出、不用 LLM 裁判。论文另设一个固定 LLM 裁判做逐轮诊断标注（定位 breach、检查近似漏报、审计文本信号与状态信号的分歧），但明确它不决定头条 ASRCSF。

防御侧被当作"消融面"而非固定假设：十层可选护栏（G1–G10，如发送者角色×权威类策略门、两人完整性检查、STA 独立否决通道、入口来源白名单、程序接地引用检查、紧迫框架强制披露、禁止告警硬锁、发送者速率限制、程序文档修改锁、以及组合纵深防御）可独立开关；STA 顾问有 A0–A3 四种模式（禁用/仅建议/软否决/硬否决）；可见性有默认黑盒 V-BB 与上界白盒 V-WB；事故场景有 S0 稳态基线与 S1–S3 递增强度的事故（论文主实验只用 S0、S1）。这样设计使得"模型鲁棒性"与"防御配置"可以被分离测量。

## Performance 概括

在固定攻击 paired replay 下，8.7%–12.1% 的会话会导致至少一个 CSF 丢失（四个操作员聚合 ASRCSF 落在 8.7%–12.1% 的窄带内）。在 149 个会话里，50 个（33.6%）至少 breach 一个模型，但没有一个会话能 breach 全部四个模型；每个模型都有非空的唯一失败集合（gpt 13、claude 7、gemma 9、qwen 8 个 unique），四模型失败集合的并集约为任一单模型失败集的三倍，说明跨模型脆弱性不是完全嵌套的。在八单元消融网格上，gpt-5.4-mini 聚合 ASRCSF=23.7%、claude-haiku-4-5=37.5%（95% Wilson 区间不重叠）；在无护栏基线（G0）下分别为 27.1% 与 36.4%，两模型最坏情况几乎相同但典型行为差异大；在全护栏（G10）下分别为 20.2% 与 38.5%，且单元 C3 出现 1.4% vs 43.1% 的 41.7 个百分点巨大落差。

## 论文价值与不足

价值在于：它是第一个把"自适应多轮攻击 + 角色结构化团队 + 客观非 LLM 裁判的危害信号 + 安全关键物理域"整合进一个可复现场地的基准。它用 judge-free 的 ASRCSF 把"危害"锚定在模拟器状态上，避免了 LLM 裁判的主观偏差与"文本有害"与实际物理后果脱节的顽疾。它最反直觉也最重要的发现是：同一套护栏栈，对某个操作员家族能降低 ASR，对另一个却可能升高——因为护栏层只在操作员 agent 发出"可被分类的结构"（动作请求、程序引用、升级）时才触发；当 claude-haiku 以大量非结构化散文形式发出有害动作、绕过了分类器 L 时，护栏反而提供不了保护。这意味着在 NRT-Bench 里，护栏不能被脱离它所包裹的模型来"认证"。其次，它证明聚合 ASR 不足以做部署选型：相似聚合 ASR 的模型，其按子目标（sub-goal）的脆弱模式完全不同，因此 agent 安全基准应把脆弱性当作"沿运维失败模式的一个向量"而非单一数字来报。

不足与局限有三点。第一，NRT-Bench 是一个抽象文本模拟器，不是高保真电厂模型，结论关乎"对抗性多 agent 协调"而非反应堆物理。第二，攻击负载是固定的、且部分针对某个种子防御者生成，因此它是"重放基准"而非"针对每个候选防御者的最坏情况自适应攻击基准"；paired replay 只部分缓解这一偏差，逐防御者自适应重生成仍是未来工作。第三，每个操作员只在单一随机种子、托管端点下评测，逐轮诊断用固定 LLM 裁判，因此最大的单单元幅度（尤其 S0,G10,A1 的符号翻转）需用重复种子确认；而跨操作员的头条结论依赖的是无裁判的 CSF 信号与"50 个会话中 0 个 breach 全部四模型"这样的干净计数。

## 工业界落地可行性评估

落地价值高，但工程化与领域知识门槛不低。最直接的落点是工业控制、关键基础设施（电网、化工、交通、核电）的 agent 安全测试：NRT-Bench 提供了一个可审计、可归因、客观的危害信号，比"让另一个 LLM 判文本是否有害"更贴近真实威胁模型，对高风险场景有强警示作用。它释放的模拟场地、攻击数据集、重放工具可直接用于"在部署前对候选操作员模型做红队"。一个重要且可迁移的洞见是：护栏的效用是"依赖它所包裹的模型"的——企业在采购或上线 agent 安全栈时，不能笼统地说"加了护栏就安全"，必须针对具体模型家族与角色提示做配对评测，报告按失败模式的脆弱性向量，而非只看一个聚合 ASR。

障碍方面：首先，环境是模拟控制室，企业要落地需针对自己的具体域（电网、化工、交通）重新定义 CSFs 与攻击剧本（攻击目录、准入通道、权威层级），这是显著的领域工程。其次，十层护栏与角色权威分类器需要按目标系统的真实程序与组织层级来配置，配置不当会引入虚假安全感。第三，论文只测了四个模型、单一种子、固定攻击负载，工业界在采信前应做更大模型集合、多种子、以及针对自身策略的自适应攻击重生成。最后，由于是抽象模拟器，结论外推到真实反应堆/电网物理前需谨慎。总体而言，它可以作为关键基础设施 agent 安全评测的方法论范本与可复用工具，但离"即插即用"仍有距离，需要领域专家把 CSFs 与攻击剧本本地化。
