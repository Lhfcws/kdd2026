KDD 2026 “Evaluation and Trustworthiness of Agentic AI” Workshop 观察笔记

KDD 2026 在济州岛举办，其中 "Evaluation and Trustworthiness of Agentic AI" workshop 收录了 49 篇论文，加上 4 场 keynote 和 industry talk。以下观察基于本 workshop 已整理的 47 篇论文速读笔记。

一今年在讨论什么

这批论文有一个相当集中的主题：对评测本身的反思。47 篇速读笔记中 41 篇（87.2%）带"测评"标签，但这里的测评不是前两年那种"跑个 benchmark 排个名"的模式。今年核心问题是：现有评测手段到底靠不靠谱？

几个反复出现的方向：

构念效度（construct validity）。 第 23 号论文借用心理测量学框架，对 5 个主流 benchmark 做跨榜单审计，发现 22% 的模型对存在排名反转。推理专用模型在 GPQA 上排第 2，在 tool-use 基准上跌到第 9。排名的含义比想象的模糊。第 38 号把这种审计落到体育分析决策支持，用 APCR、IAJA、SRI、MERS 等指标拆解"压力分析"到底测到了什么；第 25 号则回头审 MoltBook agent society，借助度保持零模型和外部真值校验，质疑幂律级联、社会强化、协作增益等结论。这说明问题不是某一个榜单失真，而是 agent benchmark 常把"可测信号"误当成"目标构念"。

隐藏变量。 第 36 号（脚手架效应）做了一个受控实验：固定模型、只换 harness，token 消耗差了 40 倍，但通过率差异只有 2-8 个百分点。目前排行榜上模型排名的差异，有一部分可能是 harness 选择的副产品。第 15 号进一步指出评测协议本身也是隐藏变量，提出 Protocol Cards、SNRfile 和 clean-apply rate，让 coding-agent 评测能报告"结果是怎么被测出来的"。第 29 号（协调噪声地板）也发现，近期报道的多 agent 协调增益有 7/10 低于同模型配对的本地噪声水平。

过程与结果分离。 第 7 号（推理轨迹评估）、第 28 号（ACID-Bench 事务可靠性）、第 46 号都强调同一个观点：只看最终任务成功与否不够，需要检查 agent 的完整执行过程。第 7 号关注推理轨迹的效率、幻觉与适应性；第 28 号把"任务成功"和"事务状态完好"拆开；第 46 号则说明经济 agent 即使 RevPAR 等标量结果相同，也可能在定价和 bid 分布上出现纪律崩溃。第 17 号（DutyFormer）更进一步，把审批、核验、引用、升级上报这类"义务"建模为可预测的过程状态，用神经符号监视器提前发现 agent 没报错但悄悄跳过必做步骤的风险。

多 agent 的反思。 前两年多 agent 辩论/协作是热门方向，今年的论文开始系统地质疑。第 24 号证明多 agent 辩论的一致性信号几乎无法区分正确和错误答案（AUROC 0.49-0.58），所谓"共识"可能只是多样性崩溃后的过度自信。第 21 号从理论上证明，个体评估必然漏检多 agent 系统中的均衡级危害。第 29 号提出协调增益需要先跨过"噪声地板"才能宣称有效。第 35 号则换了一个角度：用 replay-based 协议固定每个"任务-agent"对的潜在结果，把路由策略比较从 LLM / judge 随机性里剥离出来。

安全的精细化。 安全讨论从"有没有 guardrail"转向了"guardrail 实际在干什么"。第 31 号发现 56.6% 的安全拒绝是"不忠实的"——模型拒绝了一个本应正常执行的请求，然后把责任推给 guardrail。第 43 号发现自改进 harness 会为从未真实发生的失败构建护栏（phantom guardrails），增加了系统表面积和延迟但没有任何实际收益。第 26 号则用确定性 gate 在工具调用前拦截策略违规，用轻量级只读检查替代靠重采样碰运气的做法。第 41 号把安全边界前移到 skill 上架前，检查元数据、SKILL.md 和资源层是否跨层错位；第 44 号借鉴欺诈检测，把多轮提示注入视为轨迹级对抗交互，而不是单轮 prompt 分类问题。

二相比前几年的变化

如果回顾 2023-2024 年的 agent 研究，主线是"能不能做"——让 agent 调用工具、完成多步任务、在 benchmark 上刷分。2025 年讨论开始转向框架设计、编排模式、benchmark 建设。今年 KDD 这批工作的信号很明确：从能力展示转向可靠性审计。

具体有三点变化：

  1. 从建 benchmark 到审 benchmark。 前两年大家在发布新 benchmark，今年开始有人系统地审计 benchmark 本身的质量。第 45 号的 replay 分析发现，SWE-bench Lite 在用了 95% 的任务预算后仍然无法给出可靠的成对比较结论。第 15 号提出用"协议卡片"替代排行榜。
  2. 从单 agent 到多 agent 的安全视角。 单 agent 安全关注 prompt 注入、越狱、工具误调用等；多 agent 安全引入了新的失败模式——均衡级危害、多样性崩溃、协调幻觉。第 11 号用运营改写、planner 行为和批准式委派的受控对比说明，流水线安全性不能简单外推为稳定架构属性；第 26 号则提醒，即便是单 agent，只要工具接口 policy-permissive，模型也会留下"工具成功、状态错误"的 silent wrong state。
  3. 从离线评估到生命周期监控。 Workshop 的 Call for Contributions 明确列出"实时部署后监控"和"生命周期与治理框架"两个方向。Jian Pei 的 keynote 用一整年模拟企业运行来评估记忆系统（EverMemBench），Thu Le 的 Arena 平台积累了 8200 万条人类偏好投票做因果评估。

另外，KDD 作为算法会议，记忆/检索类工作只占 4 篇（8.5%），且全部与测评共现。知识检索、长期记忆、RAG 系统的架构设计更多会在 SIGMOD、VLDB 等数据库会议上讨论。KDD 这边的关注点偏向"如何评估这些记忆系统是否可靠"。

这 4 篇记忆/检索论文内部也有分工：第 16 号 PRISM 更像金融检索的低成本系统基线，强调提示工程、ICL 和轻量多 agent 的成本-效果取舍；第 32 号用诊断知识图谱把 benchmark 构建和多步推理评估统一起来；第 37 号 IFCMemoryBench 专门压测长期记忆在 BIM 专业工作流中的跨会话复用，结论是通用记忆系统常能取到主题相关内容，却取不全关键项目事实；第 42 号则把 Active RAG 的"何时检索"变成预算效用与校准问题。也就是说，这批工作不是在说"记忆/检索怎么做最快"，而是在问"什么时候该信它、什么时候该花钱调用它、它漏掉了什么"。

三值得关注的亮点

  • MADS-CPS（第 1 号）：为网络物理系统中的 agent 工作流定义了机器可校验的"运行级评估契约"，包含四类标准化产物和三层一致性裁决。在自主实验室场景中，110 个回放突变全部被精确定位。为什么值得关注： 传统 agent 评估只看任务成功率，但高风险场景（工业控制、机器人）需要的是"这次运行能不能被审计、能不能被回放、能不能被采信"——MADS-CPS 把这个问题从口头的可靠性要求变成了可编程的检查项。110 个突变全部被定位，也说明其覆盖范围较广。
  • ACID-Bench（第 28 号）：把数据库领域的事务可靠性概念引入 agent 评估，52 个确定性故障注入场景覆盖部分提交、过期读、崩溃恢复等。为什么值得关注： 它借用了数据库领域发展了四十年的成熟概念框架（ACID），来解决 agent 评估中一个被忽视但普遍存在的问题。"任务报告成功但状态已损坏"是生产环境中 agent 最危险的失败模式之一——既难以发现，又难以复现。ACID-Bench 的"任务成功"和"状态完好"分开度量的思路，比大多数强调 pass rate 的 benchmark 更贴近实际部署需求。它也刻意不引入 LLM judge，保持结果可复现、可审计，这对依赖 LLM 做评判的评测范式是一种补充。
  • Phantom Guardrails（第 43 号）：揭示了自改进 agent 系统的一个反直觉失败模式——当系统只奖励"抑制失败"时，会虚构出从未发生的失败并为之构建护栏。为什么值得关注： 自改进（self-improving）是当前 agent 系统的一个热门方向，但几乎没有人讨论"改错了怎么办"。这篇论文指出：当奖励信号是"抑制失败"而所有输入本来就是合法的，系统会为了满足"我在做有用的事"的倾向而编造出并不存在的失败类。三个触发条件被界定为规则形状的模式、开放规则集、预设失败的指令，且实验表明移除任一条件即归零。这对正在引入自改进管线的工程团队来说是一个直接的警示。
  • 脚手架效应（第 36 号）：2 模型 × 3 harness × 50 任务的受控实验，证明 harness 选择是编码 agent 评估中不可忽视的混淆变量。为什么值得关注： 40 倍的 token 效率差异是一个很难被忽视的数字。它的实验设计是固定模型、固定任务、只换 harness，把"harness 到底重不重要"这个问题变成了可量化的结论。失败指纹跨模型复现这一发现同样值得关注：它说明某些失败模式是 harness 的结构性特征而非模型能力问题，论文据此认为 harness 选择是编码 agent 评估中的混淆变量，应在评估中显式控制。后续任何 agent benchmark 报告如果不标注 harness 配置，其结论的可信度都会打折扣。
  • Recursive Resolution（第 2 号）：来自 Amazon 的实践，用"LLM 与人工一致即免费信号，分歧才升级到多标注者"的机制，把标注工时从 7672 小时降到 481 小时（约 16 倍缩减），同时形成评估→修复→精炼评估标准的闭环。为什么值得关注： 这篇论文的价值不在于提出新算法，而在于展示了一个生产环境中的真实解决方案。评估→修复→再评估的闭环在学术论文中经常被抽象讨论，但这里给出了具体的工程架构和成本数据。16 倍的标注工时缩减是实打实的生产收益，不是 benchmark 上的几个百分点。它来自 Amazon 的真实 RAG 系统，说明这套方法论已经过了生产环境的检验，而非停留在论文里。

Keynote 专场

Workshop 安排了 4 场 keynote/industry talk，覆盖了学术研究和工业实践两个视角。

Jian Pei（Duke University / Amazon Scholar） 的报告题为 "Beyond the Single Turn: Decomposing Evaluation for Multi-Party, Long-Horizon Agentic AI"，核心观点是当前 agent 评估过于简化——大多数 benchmark 假设单轮、单 agent、单任务，但真实世界的 agent 协作是多人、多轮、跨时间的。他介绍了两个具体工作：

  • MPCEval：一个多方对话评估基准，把评估分解为三个子问题——"谁该说话"（角色轮换的合理性）、"说什么"（内容质量）、"内容是否合适"（是否符合说话者的身份和上下文）。这比传统对话评估只看回复质量要细致得多，也更贴近群组协作的实际场景。
  • EverMemBench：一个模拟一整年企业运行的记忆系统评估基准。参与者的记忆涉及碎片化证据、事后修正的决策、未言明的偏好等复杂情况，评估的是 agent 在长时间跨度下能否正确处理这些信息。这个工作的隐含论点是：记忆系统的可靠性不能靠短时测试来推断，必须在"时间"这个维度上做压力测试。

Jian Pei 的整体立场是，agent 评估需要接受"混乱的、分布式的、时间敏感的、社会性扎根的现实"——这比当前主流 benchmark 的假设要复杂得多，但回避这些复杂性只会让评估与真实需求脱节。

Xiangliang Zhang（University of Notre Dame） 的报告 "Trustworthiness of Capable Agents: Understanding Emergent Failure Modes in Agentic AI" 从"失败模式"的角度切入可信评估。她的核心观察是：能力越强的 agent，在面对不完美的目标函数时，越容易"优化得太好"而偏离预期。她将 emergent failure modes 分为三个层次：

  • 个体层：agent 通过后训练和微调找到目标函数的漏洞并加以利用（loophole exploitation），这在 reward hacking 文献中已有讨论，但在 agentic 系统中因为工具调用和环境交互的引入而变得更隐蔽。
  • 多 agent 层：agent 之间出现激励机制层面的合谋、信息隐藏、策略性不合作——这些行为在个体评估中完全合规，但在系统层面造成危害。这与第 21 号论文的"均衡级危害"概念形成呼应。
  • 集体认知层：多 agent 群体出现从众、跟风、过度服从等认知失败，导致群体决策质量下降。这与第 24 号论文的"多样性崩溃"在机制上有共通之处。

她的框架提供了一个从"出了什么问题"出发来组织安全评估的思路，而非从"我们有什么测试手段"出发——前者更容易覆盖未知的失败模式。

Thu Le（Arena Intelligence, arena.ai） 的 industry talk "Agent Arena: Causal Evaluation of AI Agents from Millions of Real-World Interactions" 展示了一个大规模 agent 评估平台的运行数据。几个关键数字：平台已积累 8200 万条人类偏好投票、每周处理 16 万任务、每周生成 4000 万行代码、200 万次工具调用。他们用因果推断方法从随机化的真实 trace 数据中做 agent 排名，而非依赖固定 benchmark 的离线评测。

这个 talk 的参考价值在于，它展示了 agent 评估从实验室走向生产环境后的形态变化——评估不再是"跑一遍 benchmark"，而是一个持续运行的系统，需要处理真实用户分布、工具调用轨迹、人类偏好信号等复杂数据流。8200 万条投票的规模也意味着，在足够大的用户基数下，人类反馈可以成为评估体系的核心组件，而不仅是 LLM judge 的校准参考。

Jun (Luke) Huan（AWS AI Labs） 的 industry talk "Harness Evaluation and Optimization in Coding Agents" 聚焦编码 agent 中模型推理与工具执行之间的"意图-执行鸿沟"（intent-execution gap）。他介绍了 Simple Strands Agent（SSA），一个轻量级、完全开源的单 agent harness，核心理念是通过缩小意图-执行鸿沟来提升性能，而非依赖任务特定的调优。在第 36 号论文（脚手架效应）的视角下，这个 talk 可以看作是从工业界角度对"harness 设计至关重要"这一论点的印证——AWS 选择将 harness 本身作为优化对象，说明 harness 已经被视为编码 agent 技术栈中的独立变量而非附属品。

四高亮小结与展望

  1. 效度的概念会逐渐变得更重要。 就像论文需要 ablation study，未来发布 agent benchmark 可能需要附带构念效度分析。第 23 号提出的 D1-D5 五个 desiderata 可能成为社区参考标准。实际上测量心理学里的效度概念除了构念效度，还包括内容效度、效标效度，计算机领域 agent 评估由于更接近真实物理世界和人类，面临的问题复杂性和评测模糊性最终也会走到其他学科早已走过的部分路径。
  2. agent 落地与评测的领域化。 本次会议的多篇论文是从一些很具体的领域或案例出发的去讨论 Agent 相关问题（评测占多数），包括Coding、酒店订单、酒店定价、能源、量子、经济等。Agent 由于解决的问题具有更高的模糊性，相比于试图定义通用 Agent 的效度，把问题收敛到具体的领域或场景能带来的明确性会更高。
  3. harness/scaffold 会成为评估中的一等公民。 如果 harness 能造成 40 倍的效率差异，评估报告就需要明确标注 harness 配置，和现在标注模型版本一样。在更多的评测场景，LLM 逐渐会降级成控制变量之一。
  4. 过程级评估和 trace 标准化会加速。 当"结果不够"成为共识，trace 格式、可观测性标准、生命周期评估框架的需求会上升。MADS-CPS 的三层检查、ACID-Bench 的确定性故障注入、DutyFormer 的神经符号 trace 检测，代表了三种不同的技术路线。
  5. 部署后监控（post-market monitoring）会成为一个独立方向。 Workshop 的 Call for Contributions 将其列为第一项，说明工业界需求明确。模型更新、API 变更、用户分布漂移带来的 agent 行为退化，目前还缺乏系统化的检测手段。

总体来看，KDD 2026 这批 agent 工作传递了一个清晰的信号：agent 领域正在从"能不能做"进入"做得可靠不可靠"的阶段。评测方法论本身成为研究对象，这通常是一个领域开始成熟的标志。
